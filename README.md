# 人物冷存档（DSH Tavern 插件）

把游玩中出现、**具有后续价值的非龙套人物**，在离开现场后收进「人物册」；之后按关键词按需召回；人物回场则冻结，再次离场时恢复同一本人物书并刷新。

- 以**人物为中心**保存内容，不按剧情保存，不做剧情流水账
- 人物书属于**当前这一局**，随剧情版本回退、分叉，由酒馆自动处理
- 只维护**离场人物**；在场人物交给酒馆前台与人物卡原有机制

## 这是什么形态的插件

DSH Tavern 的插件**就是一个文件夹**：放进酒馆数据目录的 `plugins/` 下即可加载，不需要编译、不需要安装脚本、不改酒馆源码。

| 文件 | 跑在哪 | 作用 |
|---|---|---|
| `plugin/index.mjs` | 宿主（Node） | 监听轮次、读写存档、调模型 |
| `plugin/client.js` | 浏览器 | 侧栏面板、状态页分节、正文渲染 |
| `plugin/package.json` | — | 声明入口 |

## 怎么装（本地调试）

```bash
npm run install:dev
```

它把 `plugin/` 整个复制到：

```
~/.dsh/profile-data/tavern/data/plugins/dsh-tavern-npc-archives
```

（Windows 即 `C:\Users\<你>\.dsh\profile-data\tavern\data\plugins\…`；可用环境变量 `TAVERN_PLUGINS_DIR` 改目标。）

生效规则：

| 改了哪个文件 | 怎么生效 |
|---|---|
| `plugin/client.js` | 几秒内自动换，不用刷新 |
| `plugin/index.mjs` | **要重启 DSH** |
| 新放进 `plugins/` 的插件 | 宿主侧几秒内加载，浏览器侧刷新一次页面 |

## 怎么用

本局打开后：

- 侧栏「＋」→ 插件 → **人物档案馆**：人物册面板
- 「酒馆状态」页 → **人物册** 一节：容量与动作记录（设计稿 §3.5）

## 怎么测

```bash
npm test          # node --test tests/，只跑纯逻辑单元测试
```

纯逻辑（快照编解码、字典、信度排序、召回打分、容量水位）都有单元测试，**不需要开酒馆**；涉及插件接口的部分只能装进酒馆手测。

## 结构

```
.
├─ plugin/                 ← 复制进 plugins/ 的那一份（可运行）
│  ├─ package.json
│  ├─ index.mjs            宿主侧入口：apply(ctx)
│  ├─ client.js            浏览器侧：__ModuleLoader__.load
│  └─ lib/                 纯逻辑模块（不 import 酒馆接口，可单测）
│     └─ settings.js       设置项默认值（唯一事实来源）
├─ tests/                  单元测试
├─ scripts/
│  └─ install-dev.mjs      复制到酒馆 plugins/
└─ docs/                   设计稿与交接说明
```

`lib/` 的设计原则：**纯函数、零依赖、不碰 `ctx`**。这样规则（信度、排序、容量、打分）能本地跑测试，也便于以后换宿主。

## 路线（四段，每段都能看到东西）

| 段 | 交付 | 验收 |
|---|---|---|
| **M1 骨架** | 插件能加载；侧栏有「人物档案馆」；状态页有「人物册」一节；整局数据能存能读 | 装进酒馆一眼可见 |
| **M2 能存** | 快照结构（`v`/`t`/`p`）+ 字典（`d`/`t`）+ 信度位 + 容量水位 | `npm test` 全绿 |
| **M3 能召回** | 关键词匹配 + 打分 + 字数预算 + 冷却，正文前注入 | 造几轮看注入结果 |
| **M4 能改** | 结算后派活给常驻成员 → 校验 → 落盘；侧栏编辑 + 对话式修改 | 玩几轮看人物册 |

M2 起 `plugin/lib/` 会按需增加：`snapshot.js`、`dictionary.js`、`confidence.js`、`recall.js`、`capacity.js`、`prompts.js`。**不提前建空文件。**

## 已知限制

- 开场白不触发 `onTurnSettled`
- 玩家把关掉的酒馆后台结算全关时，`onTurnSettled` 不触发（设计稿 §10.1，刻意与官方对齐）
- 插件回调默认 30 秒超时：长任务必须走后台任务，不能在回调里同步等模型（设计稿 §10.3）
