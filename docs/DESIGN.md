## 一、定位与边界

把游玩中出现、具有后续价值的非龙套人物收进人物册（**第一次被判定为非龙套就建档**，不管当时在不在场）；只有**离场**人物会被召回注入正文；人物回场照常维护，离场只是状态变化。

- 以**人物为中心**保存内容，不按剧情保存，不做剧情流水账；
- 人物书属于**当前这一局**，随剧情版本回退、分叉：回退靠「按轮指针」自然剪掉未来；**分叉要靠搬**——分叉是新 `gameId`，而插件自己的文件按 `gameId` 存（官方文档：自己写的文件不随分叉带走），所以订阅 `onTimelineChanged` 的 `fork`，把父局**分叉点之前**的整局数据（`flags` 剪掉未来记录）、快照、已删名单搬给新局，子局已有数据则不覆盖（[ADR 0110](adr/0110-分叉继承档案.md)）；
- 一个人物始终只有一本人物书，不重复建档；
- **非龙套就建档（在场也建）**；在场人物**不召回**（[ADR 0024](adr/0024-建档提前.md)），离场只是状态变化；
- 完整剧情由其他系统负责，本插件不重复记录。

## 二、人物状态

**状态字段只有一个数字（0／1）：**

| 值 | 含义 | 界面分组 |
|---|---|---|
| `0` | 离场 | 离场组 |
| `1` | 在场 | 在场组 |

- **手动锁定（🔒）与可见性（👁）不是状态**，它们是人物上的附加标记，存整局数据、不写快照。

补充规则：

- 离场判断以**正文语义**为主，MVU／现场名单变化只作为提醒，不单独判定；
- **MVU 只作数据源、不作状态源**：程序每轮按映射表把 MVU 值抄进档案（信度位 `"9"`），抄完就存下了；MVU 那边后来消失、被清空、换卡，都动不了档案（[ADR 0045](adr/0045-砍掉MVU容灾.md)）；
- 空壳人物：手填他述来源时若该名字不在档案中，可创建一个只有名字、其余全空的人物；后续正文里真有人离场时对应上。

**建档时机与离场判定**（[ADR 0024](adr/0024-建档提前.md)）

- **建档**：非龙套人物**第一次被判定为非龙套就建档**（不论当场在不在场）；**NPC 不许与主角同名**（主角本人常驻一档 `p0`，由程序维护，见 [ADR 0085](adr/0085-主角入档与召回规则.md)）；
- **维护**：只在**本轮被提到**时更新；MVU 值由程序按映射表直接抄入（信度位 `"9"`），不经过模型；
- **离场判定分工**：**离场**（正文写了告别／离开／死亡）由模型读**本轮正文**抓；**模糊离场**（连续 N 轮没出现）由**程序数轮次直接判**，不问模型（[ADR 0030](adr/0030-术语统一与模糊离场归程序.md)）；
- **人物级动作**：`{动作:"建档", 称呼, 姓名?, 状态}`、`{动作:"改状态", 人物, 状态}`；编号 `p7` 由程序发，不交给模型。

> **为什么没有「资料容灾」**：容灾原本是"趁 MVU 里的人物还在，抢先把资料存下来，等以后回读历史正文补内容"。但建档已经提前到第一次出现（ADR 0024），不需要回读；MVU 值又每轮都抄。所以整套（状态 `2`／`3`、容灾组、`pending` 暂存、容灾开关）都已删除。只在 MVU 里、正文从没出现过的人本来就不该建档——那正是"没戏的背景板"。

### 非龙套判定

**不要求有名字，但要求有一个能把他一个人叫出来的标识**——这道关叫「**回头测试**」：

> 站在街上喊这个称呼，会**只有他一个人回头**吗？

| | 例 | 判断 |
|---|---|---|
| ✅ 专名 | 老陈、独眼陈、刀疤刘 | 只有一个回头 |
| ✅ 反常 | 瞎眼的鱼贩、独臂铁匠、养只会说话的鸟的老太 | 反常＝同行标配之外的特征 |
| ✗ 通用称谓 | 小贩、路人、侍卫、伙计、黑衣人 | 喊一声一堆人回头 |
| ✗ 同行标配 | 骑电瓶车的外卖小哥、戴头盔的外卖小哥、系围裙的鱼贩 | 电瓶车／头盔／围裙是这行的标配，十个回头 |

- 原则：**同行的标配不算标识，反常才算**；
- 称呼**必须来自正文里怎么叫他**，不许模型自己起名；
- **过不了回头测试 → 不建档**。这不是判"他重要不重要"，只是判"他有没有一个能找回来的名字"——**召不回来的档案是死档**（[ADR 0031](adr/0031-回头测试与沉降.md)）。

**过了回头测试，再满足任一条即视为非龙套**：

| 条件 | 含义 |
|---|---|
| 与主角有实质互动 | 有对话且涉及信息、交易、冲突、承诺等 |
| 持有重要物品或**线索** | 对后续有牵连 |
| 被其他人物提起 | 提的是**他的具体事**；只出现一个名字不算 |

**「出现 ≥2 轮」本身不算够格**（[ADR 0078](adr/0078-判据降级.md)）：反复露脸只说明"值得留意"，反复露脸但一直没有上面任一条的，继续留在模糊建档表里等（表本身有 3 轮过期清理，ADR 0075）。

只出现一轮、无互动、也无人提及的，不收录。

- **姓名位必须非空**——但**可以是称呼**，不要求是真名（「瞎眼的鱼贩」直接当姓名用）；
- 内部编号（如 `p7`）始终唯一，不依赖姓名；
- 临时称呼（如「无名船工・第12轮」）只剩**玩家手动创建的空壳人物**在用，可随时改。

**姓名是召回的硬前提**（[ADR 0044](adr/0044-姓名升到人物级别.md)）：没名字就匹配不上、抬头也写不出来，所以**不参与召回**——但**照常参与写入**（写入靠人物码 `p7`）。面板上这类人显示为 `p7（未命名）` 并带提示标记，点进去能补。

**无名字但有独特标识的人**：把那个标识填进姓名位，召回靠它，不靠"真名"。

**兜底**：玩家可手动转正或降级，程序判错不会卡住。

### 模糊建档表

还没够格建档、但已经露过脸的人，先记在一张轻名单上——**这是档案的缓冲区，不是档案**（[ADR 0035](adr/0035-候选改名模糊建档.md)、[ADR 0036](adr/0036-模糊建档表的存储与扫描.md)）。

**存储格式**：整局数据（`saveGameData`），**每人一个整数**

```js
draft: { "卖炭翁": 30, "沈九": 33 }   // 姓名 → 最后一次露面的轮次
```

- **只存「最后一次露面的轮次」**：入表时＝当前轮，之后每轮正文命中就刷成当前轮；
- 判据③「出现 ≥ 2 轮」的算法是：**表里有他（＝以前露过脸）＋ 本轮又出现 ＝ 2 轮**——两个事实都是现成的，用不到计数；
- 一个整数管两件事：面板显示的「已几轮没露面」＝ `now − 值`，**过期清理**＝ `now − 值 ≥ 上限`；
- 一个人平均十几个字节，几百人也就几 KB，整局数据 256 KB 里可忽略。

**谁扫**：**程序**，用 `match.js`（姓名／别名／单字），与「扫已建档人物」**同一次扫描**跑完，都在 `onTurnSettled` 里。实现见 `lib/draft.js` 的 `scanDraft`。

| 扫描对象 | 扫出来干什么 |
|---|---|
| 已建档人物 | 得出【本轮提到的人】＋状态，供模型判离场／回场 |
| **模糊建档人物** | 得出**本轮出现的**模糊建档名单，供模型按建档判据判够不够格 |

> ⚠️ 单字名的命中落在 `singleName` 里、`name` 恒为 false（ADR 0010），`scanDraft` 两个都看。

两条路进表：

1. **程序扫到**本轮出现的模糊建档人物 → 列进判定素材，模型判够不够格；
2. **模型自己发现**正文里的新面孔（程序没扫到的）→ 报 `{"动作":"模糊建档","姓名":"…"}` → 程序加进表。

**出口只有三个**（[ADR 0075](adr/0075-模糊建档候选过期清理.md)）：

| 出口 | 谁触发 |
|---|---|
| **转正建档** | 模型报「建档」并过全部门槛 → `pruneDraft` 把人摘掉（姓名或别名撞上都算） |
| **太久没露面** | 连续 `draft.maxIdleTurns` 轮（默认 3，范围 1～10）正文里都没提到 → `expireDraft` 清掉 |
| **玩家手动移出** | 面板「移出」按钮（`draft-remove`） |

清理时机：**判定之后、写入之前**，紧跟 `pruneDraft`——先摘掉刚转正的人，再判过期。判定阶段整个失败也照样清理：露没露面是程序算的，与模型无关。

**素材里只给名字**

```text
【模糊建档】卖炭翁、沈九
```

不给轮次、不给次数——轮次是引擎概念，**绝不发给模型**（[ADR 0025](adr/0025-离场记录取代在场名单.md)）。

**已知边界：同一轮既报「建档」又报「模糊建档」是安全的**

撞名检查用的是动作应用**之前**的人物表，所以同一个人两条动作都会过校验。没有实际危害——`pruneDraft` 只在本轮有新建档时跑，而它恰好会把这个人从表里摘掉。**这不是 bug，别去"修"它**：真去加互斥，反而要额外处理两条动作的先后依赖。

### 离场判定

两种离场，两套判据，谁判分得很清。

**离场（明确，正文写了就立即判）**

- 告别、离开、分头行动；
- 玩家离开了他所在的场景；
- 明确写他去了别处、退场或死亡。

判者＝**模型**：它读得懂本轮正文的语义，程序读不懂。

**模糊离场（连续 N 轮没出现，程序自己数）**

1. 现场名单里没有他（卡有 MVU 或现场状态时可用）；
2. 连续 **N 轮**未再出现，也没有「他还在」的迹象。

判者＝**程序**：数够就判，**不问模型**。本轮正文里根本没有他，问了也是空手。

**程序靠什么数：`flags.seen`（整局数据）**

```js
flags.seen = { p7: 20, p12: 35 }   // 人物编号 → 最后一次被提到的轮次
```

- **每人一个整数**，约 8 字节，200 人约 2 KB，整局数据 256 KB 里可忽略；
- **谁写**：程序在 `onTurnSettled` 的**同一次正文扫描**里，命中谁就把他的 `seen` 刷成当前轮——和「【本轮提到的人】」「模糊建档扫描」共用这一次扫描；
- 另外三处也算「确认」，同样刷新：**写入新值**、**玩家手动编辑**、**点★**；
- **判法**：`gap = 当前轮 − flags.seen[编号]`；`gap ≥ N` 且现场名单里没他 → 判模糊离场；
- **没有记录怎么办**：刚建档、还没被扫到过的人没有这条记录，视为 `gap = 0`（不判），下一轮扫描就会补上。

N 即设置项「**模糊离场判定轮数**」，默认 **3 轮**，范围 **1～5 轮**。

> **为什么不能用离场记录代替**：`flags.left` 只在「在场→离场」那一刻写一条，**判离场之前它根本还不存在**——拿它数 gap 等于先有鸡才有蛋（[ADR 0039](adr/0039-最后确认轮次seen.md)）。

**回场**

已离场的人本轮明确在场 → 改回「在场」，清掉他的离场记录。判者＝模型。

**不需要回看历史**：建档提前、档案一直在攒，离场只改状态（[ADR 0024](adr/0024-建档提前.md)）。

### 同名、改名与合并

**一个人多个称呼**（老陈／陈师傅／陈老板）

不需合并：姓名栏放最常用的，其余进「别名」，召回时全部参与匹配。

**人物改名**

旧名自动进别名，新名成为主姓名；人物编号不变，档案里记「第 N 轮起改称 X」。

**同名不同人 —— 这一版不支持**（[ADR 0049](adr/0049-砍掉同名.md)）

**撞名一律拒绝建档**，并在面板提示「局里已经有「X」了」。

原因是同名会牵动五处、每处都难：匹配层分不清正文里的「老陈」指谁、召回时两个都命中、写入时模型只能猜、素材得靠 `(p7)` 区分、面板上玩家也分不清。**收益低、代价高**，整套延后到 [ROADMAP](ROADMAP.md) **P9**（优先级最低）。

**能绕开同名的办法**：给其中一个起个**专属别名**（「账房陈」「义庄陈」）。别名本来就全部参与匹配（见上），正文只要用得上那个称呼就能精确命中。这是当前唯一可行的做法。

**手动合并入口**（保留）

玩家在界面中选中两个人 → 合并，并选择保留哪一本为主。合并用于「本来就是同一个人、被当成两个人建了档」的清理，与同名无关。

合并规则：

| 项目 | 做法 |
|---|---|
| 条目 | 按栏目合并；同栏目多值**保留双方**（信度不同，本就应并存） |
| 别名、召回词 | 取并集 |
| 编号 | 保留主编号，副编号记为「已并入 X」，后续引用自动重定向 |
| 关键度 | 取主人物值，之后按第六节的追赶规则平滑追上 |
| 锁定、可见性 | 以主为准 |

保留合并记录（谁并到谁、何时）。

**副合并项不删除，原地变灰**：

- 副项留在原分组，样式变灰、不可编辑；
- 显示一行「已合并至 X」，点击跳转到主项；
- 直到**下一次合并发生时**才删除旧的副项，由新的副项接替变灰位置。

## 三、存储方案

### 3.1 基本方式

- 使用酒馆的按轮数据：`saveTurnData` / `readTurnData`；
- 每次人物册变化，保存一份**完整人物册快照**；
- 读取当前剧情线上该轮及之前最近的一份；
- 回退、重新生成、分叉、导出导入由酒馆自动处理。

### 3.2 容量（已核实源码）

| 项目 | 上限 |
|---|---|
| 单条快照 | 64 KB（按 UTF-8 **字节**计，`Buffer.byteLength`） |
| 条数上限 | 每插件每局 2000 条 |
| 每局总量 | 每插件 8 MB |

估算：

| 人物类型 | 单人大约 | 64 KB 可装 |
|---|---:|---:|
| 精简（6 条 × 15 字） | 0.45 KB | 约 140 人 |
| 常规（8 条 × 20 字 + MVU） | 0.85 KB | 约 75 人 |
| 详细（10 条 × 35 字 + MVU） | 1.2 KB | 约 55 人 |

折算成内容量，单份快照约能放 **1.5～1.8 万汉字**。

### 3.3 写入策略

- **有变化才写**，无变化不写；
- **设置项切换一律从下一轮开始生效**；设置变更本身不触发快照写入——若生效后产生了新的数据变化，下一轮写入一份；没有变化就等下次正常写入；
- 回退到没有快照的轮次 → 借用**该轮之前最近的一份**；
- 借用之后的**下一轮强制写一份**，重新锚定；
- 每局总量（8 MB）达到 **95%** → 提示用户可用「压缩人物册历史」；达到 **98%** → 自动**删掉最早的 10 份快照**；
- 删除早期快照的代价：回退到极早期时读不到人物册，等于「那时还没有人物册」。

### 3.4 每局总量（8 MB）的删除规则

> **当前状态：决定不做**（2026-11-06 定，取代 2026-11-05 的"未实现"）。`lib/capacity.js` **不存在**，也没有代码在算水位、提示或删快照。数据现在走自持文件（[ADR 0057](adr/0057-自持文件存储.md) / [ADR 0058](adr/0058-数据放插件数据区.md)），酒馆里只剩几十字节的指针，64 KB／8 MB 那套硬上限基本碰不到——这也是容量组设置项被删掉的原因（[ADR 0079](adr/0079-删掉容量设置组.md)）。下面 3.4～3.7 保留为**原设计存档**：不做实现，真撞上上限再谈（[ROADMAP](ROADMAP.md) M4-8 已标 ❌ 不做）。

**不再按「变化率」判断，一律按最早轮次删。**

| 水位 | 动作 |
|---|---|
| **95%** | 提示用户「可以压缩人物册历史」，附按钮；说明「删完旧快照后回退会看不到人物册」 |
| **98%** | 自动**删掉最早的 10 份快照**，并在提示板记录：删了哪些轮次、删后总量 |

- **起点不特殊对待**：与其它快照一样按轮次最早优先删除；
- 删除只影响「回退到更早轮次时读不到人物册」，不影响当前人物册内容；
- 索引：插件整局数据里维护一份轻量快照索引（轮次、字节数），写快照时追加，供删除时挑选。

### 3.5 容量兜底（64 KB 侧）

**不再有 80% 自动清理。** 只保留三道闸：

| 水位 | 动作 |
|---|---|
| **95%** | 提示板记录「人物册即将溢出」 |
| **97%** | **着重提示**，要求玩家手动清理或使用自动清理，并给「一键自动清理」按钮；自动清理＝按「最久未更新」排序、同分取关键度最低的，**清空该人物全部条目**（人物保留），一次清一个，**清到 90% 以下** |
| **99%** | **拒绝写入**（任何新增都拒） |

**写入超限的处理（不做实时预判）**

99% 已拒绝写入；若仍因边界情况写超：

1. 酒馆在挂快照时拒绝；
2. 插件**放弃本次写入并回退**，不做部分写入；
3. 提示板记录「本次写入失败：人物册容量超载」。

**整局数据（256 KB）的兜底**

| 水位 | 动作 |
|---|---|
| **> 90%** | 触发一次**全量扫描**，回收无引用的字典下标 |
| 扫描后回收不到东西 | **下一轮再提示一次，之后不再扫描** |
| **95%** | **着重提示当前情况**：整局数据已接近上限，等待后续版本提供冷存储 |
| 是否停止收录 | **不停止**。若因此加快撞到 64 KB，交给 64 KB 那边的 97% 提示与手动压缩处理 |

**快照条数（2000 条）的兜底**

| 水位 | 动作 |
|---|---|
| **1900 条** | 提示板记录「快照数量接近上限」 |
| **1999 条** | 按最早轮次**删掉 100 份快照**，然后告知用户 |

**提示的呈现方式（统一）**

所有容量相关提示**一律不弹窗、不抢前台**，只通过：

- **侧栏角标**：人物档案馆入口显示一个小红点／数字；
- **「酒馆状态」页的一节**：按时间倒序列出全部记录，可翻阅历史。

**每一项都要写明“做了什么”**，不能只写“容量紧张”。必记事件：

| 事件 | 记录内容 |
|---|---|
| 95% 即将溢出 | 当前水位 |
| 97% 自动清理 | 清空了谁、清掉几条条目、清理前后水位 |
| 99% 拒绝写入 | 被拒绝的是什么（人物／条目／值／模型写回／自动建档）、当前水位 |
| 删除旧快照 | 删了哪几轮、删除后总量 |
| 整局数据 >90% 扫描 | 回收了几个下标 |
| 整局数据 95% | 当前占比、已提示等待冷存储 |
| 条数 1900 / 1999 | 当前条数；1999 时记录删了哪 100 份 |
| 压缩人物册历史 | 保留了几轮、删掉多少份、释放了多少空间 |
| 写入失败回退 | 失败原因（容量超载等） |

**每轮动作日志**

除容量事件外，**插件每轮做了什么也要记**，例如：

- 本轮召回了谁（完整／详细／简单／提示／连带）、注入了哪些条目；
- 模型写回的动作（新增谁的第几条、覆盖、删除、无变化）；
- 建档了谁、谁离场、谁回场；
- 跳过原因（冷却中、预算不足、95% 拒绝、人物不可见等）。

**详细程度**（2026-11-05：原设计由设置项控制，该设置项**已删**，因为整套「提示记录」`lib/notice.js` 根本没接线；要接线时固定按下面最细的「详细」档来）：

| 档位 | 记录范围 |
|---|---|
| **简洁** | 只记异常与容量事件 |
| **标准（默认）** | 简洁 + 归档、离场、回场等关键动作 |
| **详细** | 标准 + 每轮的召回、写入、跳过与无变化 |

**冷分片**：暂不做。

### 3.6 回退时各状态的归属

人物册随剧情回退：快照按轮存，读回退后的轮次就是那一轮的人物册。下列状态不在快照里，按**当前轮次**校正：

| 状态 | 存放 | 回退后行为 |
|---|---|---|
| **定位轮次** `meta.updatedTurn` | 整局数据 | 读数据时用酒馆当前状态（`getTurnState().turn`）校正——回退只动酒馆正文与按轮快照，不动插件自己写的数据；拿不到才回落旧值（`lib/snapshot.js` 的 `resolveTurn`） |
| **最后确认轮次** `flags.seen`／离场记录 `flags.left`／候选表 `flags.draft`／模糊离场 `flags.fuzzyLeft`／主角回场 `flags.playerBack` | 整局数据 | **清掉轮次大于当前轮的记录**（`lib/rollback.js` 的 `pruneFutureFlags`）——它们记的是回退后才发生的事 |
| 召回冷却 | 整局数据 | **不清**：`until` 本来就是未来值，且只对「存在的指针」生效；指向已不存在命题的脏键无害 |
| 旧轮次的快照 | `snapshots/<局>/` | **回退后开始下一轮时**，把「未来轮次」的快照挪进 `trash/`（`store.pruneAfter`，幂等）；命题与指针就在快照里，旧快照删掉它们自然没了 |
| 锁、眼睛、★ | 整局数据 | **保留**，不随回退变化 |

### 3.7 压缩人物册历史

> **当前状态：未实现**（2026-11-05 核）。面板上没有「压缩人物册历史」按钮，也没有按 90% 触发的提示。`store.js` 只有它自己那套**自动按轮次窗口剪枝**（保留最近若干轮、剪掉的挪 `trash/`），不是这一节说的手动压缩。

**触发**：整局数据已用达到 **90%** 时，在提示板（侧栏角标 + 酒馆状态页那节）记录一条，并在该节提供「压缩人物册历史」按钮；不弹窗。

**行为**：

1. 保留**最近 N 轮**内的快照（N 默认 **10**，可设 0～50）；
2. 删除更早的所有快照（对每轮调用 `saveTurnData` 传 `null` 清除）；
3. 顺带做一次字典回收，释放无引用下标。

**二次确认文案**：

> 压缩后，回退到较早轮次将看不到人物册。  
> 建议在分叉或新开对话前执行。  
> 确定压缩吗？

**默认保留 10 轮的理由**：与酒馆上下文压缩的 `RETAINED_STORY_ROUNDS = 10` 对齐，让「近期剧情」与「近期人物册」时间范围一致。

**技术依据（已核对源码）**：`saveTurnData` 对历史轮次同样可用，`currentKey` 会返回该轮当前版本的 key，传 `data: null` 即清除该轮记录；只对当前剧情线上仍存在的轮次有效。

### 3.8 不采用的方案

- **自有普通文件作主存**：不随回退、分叉、导出走，需要重做一整套版本管理（回退靠「按轮指针」挡住；**分叉已由 [ADR 0110](adr/0110-分叉继承档案.md) 用 `onTimelineChanged` 的 `fork` 主动搬补上**；导出／导入见 ADR 0050）；
- **整局数据（256 KB）作主存**：回退时人物册不跟着变，会穿帮。

自有存储只用于：插件设置、卡级映射、字典、可重建缓存。

## 四、快照结构

### 4.1 总体

```json
{ "v": 1, "t": 40, "p": [ ...人物... ], "gt": "永安三年·冬", "loc": "临安·旧港·码头",
  "c": [ ...命题... ], "pt": [ ...指针... ] }
```

- `v`：结构版本号，插件自己定，改结构不兼容时加一；
- `t`：快照对应轮次；
- `p`：人物数组；`gt`：本轮游戏内时间原文；**`loc`：剧情发生地点原文**（[ADR 0053](adr/0053-快照地点与MVU勾选.md)）。时间与地点都**只记录不解析**，拿不到就是空串；
- **`c`：命题表**（[ADR 0081](adr/0081-信度改成事实加指针-提案.md)）——全局扁平一份，一条＝一句"有人提过／有人信过"的话；
- **`pt`：指针表**（[ADR 0081](adr/0081-信度改成事实加指针-提案.md) / [ADR 0083](adr/0083-写入流程-命题与指针.md)）——一条＝「某个人对某条命题的态度」。

> 旧快照没有 `c` / `pt` 时补空数组即可，**不升版本号**：新字段加在末尾是向后兼容的（§4.8）。

**人物** `[编号, 状态, 姓名, 别名串]`

```json
["p7", 1, "老陈", "陈先生,老陈头"]
```

| # | 字段 | 说明 |
|---|---|---|
| 0 | 编号 | `p0` 是主角（程序维护，[ADR 0085](adr/0085-主角入档与召回规则.md)）；其余 `p7` 这类自增，**永不复用** |
| 1 | 状态 | `0` 离场 / `1` 在场（见第二节） |
| 2 | 姓名 | **原文存放、不进字典**；必须非空（可用称呼顶替）。见 [ADR 0044](adr/0044-姓名升到人物级别.md) |
| 3 | 别名串 | 半角逗号分隔。姓名＋别名一起参与匹配，切分口径唯一一份在 `lib/names.js`（[ADR 0084](adr/0084-姓名与别名的唯一性与导入体检.md)） |

**命题** `[id, 所属人物, 栏目码, 内容, 起始轮, 索引词]`

- `id`：自增正整数，给指针指路；
- **所属人物**：这条命题说的是谁——一条命题只属于一个人；
- **内容**：字符串＝原文、数字＝字典下标（同 §4.3）；
- **索引词**：`[{ 词, 类 }]`，0～3 个，必须是内容的原文片段（[ADR 0021](adr/0021-关联词的抽取规则.md) / [ADR 0076](adr/0076-索引词跟着值走.md)；上限由 [ADR 0107](adr/0107-通用词自动抽与查档限次.md) 从 0～2 放到 0～3）。

> **为什么扁平而不嵌在人物里**：一条命题可能被很多人知道（多个人各有指针指向它）。嵌进人物档案就得复制 N 份、索引词也抽 N 次（[ADR 0081](adr/0081-信度改成事实加指针-提案.md)）。

**指针** `[人物编号, 命题id, [来源组…], 最后变动轮]`

**来源组** `[态度, 来源, 游戏时间?, 约定状态?]`

| 位置 | 含义 |
|---|---|
| 0 态度 | `0` 真 / `1` 假 / `2` 未定 |
| 1 来源 | `''` 他自己 / `p7` 某人 / `'?'` 未知来源 |
| 2 游戏时间 | 他听到/确认这条时的 `gt`（可省；省略时连第 4 格一起省） |
| 3 约定状态 | `0` 没完成 / `1` 完成了 / `2` 过期了 / `3` 失败了（只有约定类栏目才有，[ADR 0087](adr/0087-约定类命题程序只存不判断.md)） |

- **一人一命题只有一条指针**（[ADR 0083](adr/0083-写入流程-命题与指针.md)）；
- 「自己」那组永远排第 0 位，**只有本人能改**；别人的来源组最多 **3** 组（设置页 `cognition.maxOtherSources` 可调 1～8，默认 3），超了丢最早加入的那组（[ADR 0098](adr/0098-认知模型四个旋钮.md)）；
- 第 4 格是**最后变动轮**：建立时＝起始轮，之后每次改动刷新。冷却拿它算「多少轮没动过」（[ADR 0086](adr/0086-召回冷却按指针记.md)）。

**锁定与可见性不写入快照**，存插件整局数据；回退时保持原样。

**`p[3]` 的现状（2026-11-05 更新）**

MVU 抄入**已迁完**：走 `mergeMvuIntoClaims`，直接写命题＋指针（态度真、来源他自己），所以 MVU 值现在**会被召回、面板也看得到**。

还留着 `p[3]` 的只剩三处：删除人物时的存档、恢复人物、面板旧的「改值」路径。它们读写的都是**迁移前存下的老条目**，不影响召回（召回只读 `c` / `pt`）。等这三处一并迁走，`p[3]` 就可以真的退休成恒空数组。

### 4.2 条目码分配

**条目码分三段，互不干扰：**

| 码段 | 数量 | 用途 | 能否被映射表替换 |
|---|---|---|---|
| 单字母 `a`～`z`、`A`～`Z` | 52 | **映射槽位**：内置栏目 + 由 MVU 映射自动建立的栏目 | ✅ 换表时改名、复用同一槽 |
| 双字母 `aa`～`ZZ` | 2704 | **玩家手动新增的栏目** | ❌ 永不触碰 |
| 三字母 | 备用 | 真不够时再扩 | — |

- **映射槽位与内置栏目合计上限 52 条**（当前内置 8 条，余下 44 个槽供映射自动建立）。

~~**信度位另有一套单字符码**（`0`～`9`、`X`、来源下标）~~ —— **已退役**（2026-11-04）：信度不再是"每个值一个码"，改由**指针的来源组**表达（§4.1）。栏目码与它本来就不在同一位置，互不影响这条依旧成立。

**换映射表时的行为**：

- 只改**单字母槽位**的名字与对应 MVU 字段；
- 双字母条目一个都不动；
- 历史快照跟着**当前槽名**显示（值不变、标签变）。

### 4.3 字典（原「号码簿」）

**用整数下标代替两位码**：字典就是一个数组，下标即号码。

**靠 JSON 类型区分「引用」与「原文」**

| 写法 | 含义 |
|---|---|
| `"A3"`（字符串） | 原文就是 A3 |
| `42`（数字） | 字典第 42 号 |

- 字符串永远是原文，数字永远是引用，**不需要前缀、不需要转义**；
- 规约：原文一律存字符串（纯数字也存 `"27"`），引用一律存数字；程序保证，玩家与模型接触不到。

**存什么**：**只收长句与重复短语**。

- **不收人名、地名**——实测占比极小（一人只出现一次，约省 6 字节/人，占单份快照不到 1%），却要额外承担同名、字面像码等麻烦；
- 同类也不收：短词、纯数字、英文单词、MVU 值、条目名。
- 条目名不进字典：单字母槽位固定，个人条目名存在「条目定义」里。

**收录规则**

| 长度／类型 | 收录时机 |
|---|---|
| **超过 8 个汉字** | **第一次出现就收录** |
| **4～8 个汉字** | **第二次出现**才收录 |
| **少于 4 个汉字** | 不收录 |
| 英文单词 | 不收录 |
| 纯数字 | 不收录 |
| 含数字的混合串（“三天后”“27岁”） | 不收录 |
| MVU 值 | 不收录 |
| 常见虚词短句（“什么”“可以”“不是”） | 不收录 |
| 纯标点或空白 | 不收录 |

**规则**：

- 每个条目带**类型标记**（人名／地名／MVU值／常用词），与字典并行存放，不占快照；
- **只增不删**，但允许在满足条件时**原地替换**（见 4.6 滚动回收）。

### 4.4 编码后缀（**已退役**）

原来的 `+`／`-` 后缀只服务于信度位的来源引用（`"r42+"`／`"r42-"`）。信度位随 [ADR 0081](adr/0081-信度改成事实加指针-提案.md) 退役后，**这个后缀不再有任何地方使用**；态度（真／假／未定）写在指针的来源组第 0 位。保留这一节只为说明"别再照着写"。

### 4.5 字典的存储与索引

- **归属**：跟局走，每局一份；卡级复用暂不考虑；
- **位置**：整局数据（`saveGameData`），不占 64 KB 快照额度；
- **结构**：两个并行数组，下标即号码

```json
{ "v": 1, "d": ["老陈", "相濡以沫", "旧港"], "t": [1, 3, 2] }
```

| 字段 | 含义 |
|---|---|
| `v` | 结构版本 |
| `d` | 词条原文数组，下标 = 号码 |
| `t` | 类型数组，与 `d` 同下标（1 人名／2 地名／3 MVU值／4 常用词） |

- **反向索引**（文字 → 号码）**不落盘**，加载时临时构造成 `Map`，查找 O(1)；
- 新增即 `push`，号码自然递增，无需维护「下一个可用序号」；
- 粗算 400 个词条约 6～8 KB，整局数据上限 256 KB（**独享，不与其他插件共享**）。

### 4.6 字典滚动回收

**触发条件**：整局数据体积达到其上限的 **90%**。

**做法（全量扫描，纯程序，不调模型）**：

1. 读取这一局**所有现存快照**；
2. 统计每个字典下标被引用的次数；
3. 挑出同时满足两个条件的下标：
   - 引用次数为 **0**（任何现存快照都没用到它）；
   - **最早收录**的优先；
4. 把这些下标**原地替换**为新收录的词条（下标不变，因此不会影响任何快照）。

**目的说明**：原地替换**不会让整局数据变小**，它的作用是**复用槽位、阻止继续增长**。若需要真正释放空间，用 3.7「压缩人物册历史」。

**执行方式**：放后台异步执行，不阻塞当前这一轮；扫完再默默替换。

**耗时参考**：接近上限（约 130 份、8 MB）时约 0.8～1.5 秒，常规局 0.3～0.6 秒，触发频率很低。

**为什么必须全量扫描**：若按「本轮快照是否引用」判断就替换，被替换的下标仍可能被**历史快照**引用，回退后会把旧档案解码成完全无关的内容。

### 4.7 派生值不写入快照

- 关键度（插件自己维护，**当前未实现**）；
- 分组归属（由状态推）；
- 空栏目（UI 按定义补出折叠按钮）；
- 字典本体；
- MVU 映射表；
- **冷却表**、**锁／眼睛**、**`flags.seen`／`flags.left`／`flags.draft`**：都在整局数据里，不进快照。

### 4.8 版本与迁移策略

**总原则：只加不改。**

1. 新字段一律加在末尾，旧数据缺这个字段时按默认值处理；
2. **字段的顺序与结构永不改变**；
3. 因此绝大多数功能扩展**不需要升版本号**。

**关于条目码**：单字母码是**位置**（槽位），其**含义（槽名）允许随映射表更换**——这是设计上的例外。换表后，历史快照的值不变、标签跟着当前槽名走，属于**已知且接受的行为**，不需要升版本号。

**什么时候才升 `v`**：只有改了已有字段的顺序或类型、无法向后兼容时才升。

**读旧数据**

- `v` 低于当前：按迁移链逐级转换（v1→v2→v3），**读时在内存转换**，不批量改存档；
- 下次该轮因正常写入需要保存时，按当前版本重新写出；
- 旧版本快照本身保持不动，回退到旧轮次仍能按旧规则读出。

**读新数据**

- `v` 高于当前：**拒绝参与召回与写入**，只在界面只读展示，并提示「请升级插件」；
- 不会清空、不会覆盖，避免降级安装时丢数据。

**字典**独立带 `v`，规则相同。

## 五、态度与来源

（原「信度体系」；信度位那套编码已在 2026-11-04 退役，见 §5.4）

**一条认知拆成两半**（[ADR 0081](adr/0081-信度改成事实加指针-提案.md)）：

| 一半 | 存在哪 | 说明 |
|---|---|---|
| **命题**：一句"发生过什么" | `snapshot.c`，全局扁平一份 | 不属于任何人的判断 |
| **指针**：某人对它的态度 | `snapshot.pt` | 每个人各有一条 |

所以「老陈以为李四在码头、李四说自己不在」这种矛盾**根本不用打架**：一条命题，两条指针，各记各的态度。旧的「信度位」硬把它压成一个码，压不下——这就是 [ADR 0081](adr/0081-信度改成事实加指针-提案.md) 换掉它的原因。

**默认态度＝未定**；只有正文明确写了、模型才敢标真或假，拿不准一律未定（[ADR 0020](adr/0020-写入判断带上视角说明.md)）。

**两类命题的态度不一样**（[ADR 0104](adr/0104-两类命题的态度.md)）：**能直接观察的事实**（在哪、做了什么、说了什么、身上有什么伤）亲见或正文写明时可以给「真」；**推断出来的东西**（性格、动机、想法、关系性质、评价）**不能给真**，只能给「未定」，除非正文里有人明确这么说、且这个人明确信了——「真」的语义是"他信"，不是"客观为真"，所以这一条必须显式写死。

**「假」不会被删掉**：他说过假话这件事本身就是重要记忆——命题留着，态度记假。

### 5.1 三个维度

一条指针的每个**来源组**记四样东西（结构见 §4.1）：

| 维度 | 取值 | 谁定 |
|---|---|---|
| **态度** | 真 / 假 / 未定 | 模型判；玩家可在面板改 |
| **来源** | 他自己 / 某人 / 未知来源 | 模型判 |
| **游戏时间** | 他听到／确认这条时的 `gt` | 程序抄，没有就省 |
| **约定状态** | 没完成 / 完成了 / 过期了 / 失败了 | 模型报，程序**只存不判**（[ADR 0087](adr/0087-约定类命题程序只存不判断.md)） |

**他述来源必须是已建档人物**，否则记「未知来源」——不凭空造人，也不记二阶认知（"他以为你以为"）。

### 5.2 谁能改哪一组

- **「自己」那组**（来源 `''`）：**只有本人能改**。别人不能替他改口；
- **「某人」那组**：记的是"他听这个人说的"，同一来源只留一组；
- **每人最多挂 3 个别人**（默认值；设置页「认知 · 一条命题最多几个『听说』来源」可调 1～8，[ADR 0098](adr/0098-认知模型四个旋钮.md)），超了丢最早加入的那组——一条指针挂十个来源没有额外价值，只会让快照膨胀（[ADR 0083](adr/0083-写入流程-命题与指针.md)）。

### 5.3 面板上怎么改

详情页「他的认知」块：点命题改内容、下拉选态度、填来源。改完把**最后变动轮**推到当前轮，于是这条按冷却规则不会下一轮立刻又被召回（接口 `/update-pointer`、`/update-claim`）。

## 六、关键度

**当前状态：未实现**（2026-11-05 记为待办）。代码里**没有任何地方读写人物的关键度**，也没有"总分 = Σ栏目贡献"这套计算；设置项 `salience.lock` / `salience.proportional` 同样**只存不用**。下面是原始设计，将来实现时照它来，别重新发明。

> 但下面这批用途已经作废，不要再实现：「连带召回优先级」（召回已重做，§七）。

- 计算的是**人物级别的总分**：把该人物每个条目的贡献加起来；
- 每个条目有自己的**计数方式**：
  - **条目式**：该条目只要有值就贡献 **1**，没有值贡献 **0**；
  - **值数式**：该条目有几条值就贡献 **几**；
- **别名特例**：不论有几个值，最多贡献 **1**；没有值则为 **0**；
- 数值越大越关键；
- **不写入人物快照**，插件自己维护，回退或值变化时重算；
- 用途：组内排序、连带召回优先级、关闭信度时的取舍、容量清理时的挑选。

**新建条目默认值**：计数方式＝值数式（内置条目中特别标注为「条目式」的除外，见 8.8）。

**合并后的追赶过渡**

- 合并时关键度取**主人物**的值；
- 之后每当该人物被**写入一次**（有更新才加，不按轮次加），关键度 +1；
- 追赶目标＝该人物**按上述算法算出的当前关键度**，目标会随值增减动态变化；
- 追到目标值后，恢复正常计算。

用户手改：

- 提供五个档位：最高／较高／中／较低／低，也可填非负整数；
- 最高 = **999999**，最低 = 0；
- 改完按新位置插入排序；
- 人物行右侧提供「恢复关键度」按钮，恢复为自动计算。

设置项：

| 设置 | 行为 |
|---|---|
| 关键度锁定 + 不按比例 | 数值固定死，不再随值数变化 |
| 关键度锁定 + 按比例 | 按排名分位（向上取整）记录，人物增删后重算 |
| 关闭锁定 | 只覆盖一次，下次重算即被覆盖 |

### 7.0 现行召回模型（2026-11-05 定稿）

**单位＝一条指针**（某人 × 某条命题 × 某个来源组）。不是"一个人一段"，也不是"一个条目一段"。

#### ① 五道闸（候选要先过五关）

| 闸 | 条件 |
|---|---|
| 主体活着 | 人在人物表里，且不在已删除名单 |
| 眼睛没闭 | 没被玩家标成「不可见」（👁） |
| 栏目勾选 | 这条命题所属栏目在设置里勾上了 |
| 指针不在冷却 | 按 `pt:人物id:命题id` 记的冷却没到期（§7.5） |
| 主体在场 | **只召回在场的人**——离场的人不给 |

> **锁**（🔒）不影响召回：锁的意思是"模型不许写他"，不是"不记得他"。

#### ② 打分（固定常量，不学习、不加权）

| 命中 | 分 |
|---|---|
| 关于**本轮在场的其他人** | +3 |
| 关于**当前地点** | +2 |
| **索引词**（模型抽的）**或程序自动词**在本轮正文里出现 | +2 |
| 其他 | 0 |

同分依次比：**最后变动轮**（新→旧）→ **命题起始轮**（新→旧）。

**「命中」认两份词**（[ADR 0107](adr/0107-通用词自动抽与查档限次.md)）：模型抽的**索引词**只管专名（人／地／组织／物件），通用词（收银员、超市、早饭）由程序用分词器从命题值里切出来当**自动词**；任一份在本轮正文里出现就 +2。代码里写的是 `索引词命中 || 自动词命中`，**短路求值**，两边都命中也不会翻倍；`autoWordsOf` 还会把该条已有的索引词排除掉（`exclude`），作用是让面板不重复显示同一个词、并防止以后改成累加时踩坑（`lib/indexWords.js`、`lib/recallEngine.js`）。**自动词不落盘**：面板上的自动词是每次现算的。

#### ③ 预算怎么分

| 项 | 值 |
|---|---|
| 每轮上限 | `recall.budgetChars`，默认 **3000** 字（可调 1000～6000） |
| 主角回场 | 先划 **1000** 字给他做全量注入（[ADR 0085](adr/0085-主角入档与召回规则.md)） |
| ★ 重要人物 | 拿剩余预算的 **60%**，在 ★ 之间平分 |
| 普通角色 | 拿剩下的，在普通角色之间平分 |

每人内部：**必带栏目先给**（`mustRecall`，不参与打分与预算竞争），其余按分装——装得下用**详细**、装不下退成**简单**、再装不下就丢。

#### ④ 两档（不是四档）

| 档 | 内容 |
|---|---|
| **详细** | `· 命题内容：真／假／未定（他自己确认过／听某人说的，游戏时间，约定状态）` |
| **简单** | `· 命题内容` |

旧的「提示档」与「完整档」都已取消。

**一条命题有几种说法、注入时显示几组**：由设置页「认知 · 一件事有几种说法时显示几种」决定（`cognition.conflictDisplay`：都显示／只显示他本人那组／只显示最新；`self` 档在他本人没那组时退回全部）。实现在 `lib/pointers.js` 的 `visibleGroups`，**召回注入、查认知、手动召回三处共用**（`recallEngine.js` 与 `recallQuery.js` 各调一次）；**只影响注入文本，不动快照、不动持久化**，改设置不回改历史（[ADR 0098](adr/0098-认知模型四个旋钮.md)）。

#### ⑤ 抬头与模板

默认抬头是「【人物档案参考】＋ 写作人称 ＋ 当前时间地点 ＋ 一句'这是各人自己记得的事，不要在正文里复述'」。整段骨架可以在设置页改（`assets/recall-prompt.txt`，占位符 `{{VIEWPOINT}} {{GT}} {{LOC}} {{STAMP}} {{BLOCKS}}`）。

#### ⑥ 冷却：三处盖章，粒度是**指针**

键是 `pt:人物id:命题id`，记 `{lastTurn, until}`（[ADR 0086](adr/0086-召回冷却按指针记.md)）。

| 什么时候盖 | 说明 |
|---|---|
| **建立** | 新建指针时，指针第 4 格＝建立轮 |
| **修改** | 改态度／来源／内容时，刷新第 4 格 |
| **召回** | **真注入给模型**才盖（2026-11-05 补齐——之前只有前两处，等于"刚念叨过的人下一轮还能念叨"） |

判法两道合起来：`当前轮 − 第4格 < N` **或** 冷却表里 `until > 当前轮` → 冷却中。默认 N＝**10**（0～20，0＝关）。

#### ⑦ 主角的特殊待遇

- 编号固定 `p0`，名字跟玩家称呼同步；称呼空着时叫「主角」；
- **入档排在写入之前**：`ensurePlayer` 在**建判人／写入素材之前**执行（读完身份、算好视角之后就调，那一轮 `snapshot.p` 当场就有 `p0`），**轮末再同步一次**——模型可能本轮给主角改名，三人称下他的离场／回场也要跟着变（`playerWasOffline` 采样点仍在写入前）（[ADR 0101](adr/0101-主角必须在写入之前入档.md)）；
- **永远在场**（一／二人称下 `/status` 拒绝把他切离场）；
- 主角 `离场 → 在场` 时记 `flags.playerBack`，下一轮**全量注入一次**并给这批指针盖章；
- 主角不能删。

#### ⑧ 三条入口，三种语义

| 入口 | 谁触发 | 看不看冷却 | 盖不盖章 | 进不进提示词 |
|---|---|---|---|---|
| 每轮自动召回 | 程序 | ✅ 看 | ✅ 真注入了才盖 | ✅ |
| 面板「召回」 | 玩家点名 | ✅ 看（按设置档位） | ✅ 真注入了才盖 | ✅ 下一轮 |
| 面板「查认知」 | 玩家查阅 | ❌ 不看（恒全量） | ❌ 不盖 | ❌ 只显示 |
| 正文模型 `archive_query` | 模型自己问 | ✅ 看 | ✅ 查完就盖 | — |

面板「查人物」只是搜索定位（展开分组＋滚动＋高亮），不读档案、不盖章、不进提示词。

**正文模型自己查有次数上限**：`archive_query` 每轮最多 **2 次**（`lib/queryBudget.js` 的 `createQueryCounter`，账按「局＋轮」记、换轮清零），超限回一句人话让模型先用已有信息写，**不静默失败**；工具描述里也写清了「什么时候用／什么时候不用查」（[ADR 0107](adr/0107-通用词自动抽与查档限次.md)）。

#### ⑨ 什么时候不召回

- 这个人的**姓名是空**——匹配不上、抬头也写不出来（§二）；
- 人在**已删除名单**里；
- 这一轮**判定阶段整个失败**——不影响召回，召回只看已存下的指针。

### 7.1 双层机制

> ⚠️ **本节描述的召回实现已标记退役。** 信度改成「命题 + 指针」（[ADR 0081](adr/0081-信度改成事实加指针-提案.md)）后，「只召回离场人物」这条前提失效——新召回给的是「他知道什么」，而正文写不出这个。重构方案见 [ADR 0082](adr/0082-召回改成在场人物认知指针-提案.md)。本节内容在新结构落地前仍是**当前实现**。

1. **程序自动召回**（主路径）：姓名、别名、有效索引词命中；
2. **模型主动查询**（补漏）：前台工具，模型觉得资料不足时自行调用。

> **一个命中都没有 → 不召回。** 这条是硬闸：分数再高也不给（只有一个人时先验分会给满分，不设闸就会"档案很全"就塞进正文）。命中＝姓名／别名／单字／索引词任一，含本轮实时与上一轮缓存两路。

**扫什么文本**（[ADR 0042](adr/0042-一致性四档与召回命中缓存.md)）

召回跑在 `turnSection`，平台只给 `{gameId, turn, input}`——**只有玩家本轮输入，拿不到历史正文**。所以两路输入：

| 来源 | 怎么拿 | 说明 |
|---|---|---|
| **本轮玩家输入** | 现成的 `input` | 最强信号（"我去找老陈"） |
| **上一轮正文的命中结果** | 读 `flags.lastHits` | 上一轮结算时扫好存下的小缓存，**只存一轮** |

- **只回看上一轮**，不回看更多轮：召回信号是**一次性消费**的——第 30 轮命中，第 31 轮就用掉，之后由冷却接管；再往前留只会让同一批人反复参与计算；
- 两路命中的索引词**合并去重**（子串、大小写都算同一条），否则一致性会被虚增。

`flags.lastHits`（整局数据，每轮**整体覆盖**）：

```js
flags.lastHits = {
  p7:  { hit: "alias", words: ["旧港码头", "林澈"] },  // 上一轮点名了（别名）＋ 对上这两条索引词
  p12: { hit: null,    words: ["一张欠条"] }           // 没点名，只沾边
}
```

- `hit`：`"name"`／`"alias"`／`"single"`／`null`，供匹配分；
- `words`：命中的索引词**原文**，供一致性分数条数与**挑条目**用；
- 它只管已建档人物；模糊建档的人用 `flags.draft`（§2）。

### 7.2 重复注入规避

**做不到**按「模型上下文里实际还剩什么」判断——酒馆不向插件开放上下文占用与历史压缩状态（见 7.5）。

替代做法：

- 冷却模式下，由冷却轮数控制重复注入；
- 冷却关闭时，不做额外判断，允许随时召回；
- 召回内容中已注入过的条目，由冷却粒度（人物级／条目级）避免重复。

### 7.3 预算与分级

- 每轮召回总量按**字数预算**控制，**默认 3000 字符，可调 500～6000**。预算天花板不是"每轮固定注入"——一个都没命中就一个字都不注入；
- 不按人数设限；
- 分级选项：**混合（默认）／全部简单／全部详细**（"全部完整"随完整召回一起延后）；
- 四档内容（细则见 §7.10.2）：**提示** = 更短的一行「身份＋离场时间」；**简单** = 一行名片；**详细** = 挑过的记忆（每条目最多 2 条值）；**完整** = 整个档案（**第一版延后**，见 [ROADMAP](ROADMAP.md) §6.1）；
- 装配是**三步**（[ADR 0018](adr/0018-装配三步与完整召回延后.md)）：① 非提示档的人先各放一行**简单**（装不下就丢）→ ② 够详细分的按分数升成**详细** → ③ 还有预算才把**提示档**的人塞进去。完整召回第一版不做。

> 术语说明：「最后去向」是条目；「离开时间」「最后地点」都是**派生展示字段**，不是条目——前者取**离场记录**的 `gt`，后者取「最后去向」条目，不进快照结构。

### 7.4 连带召回

主人物档案中提到其他人物时：

- 匹配在**解码后的文本**上做，单字名也参与；
- 带出的内容 = **简单一行 + 该人物档案中提及主人物的条目**；
- 排序按关键度从高到低，同档再比被提及次数与更新轮次；
- 只用剩余预算，不挤占主人物；
- 预算不足先砍关联条目，保住简单一行；
- 写满预算即停；
- **只顺一层**，不再从被带出者继续展开。

### 7.5 召回冷却

**冷却开关（默认开，默认 10 轮，范围 0～20）**

| 开关 | 行为 |
|---|---|
| **开** | 按轮数冷却：冷却未结束 → 不允许召回；冷却结束 → **允许**召回 |
| **关** | 不设冷却，随时允许召回 |

三个层次必须分清：

1. **是否允许召回** —— 由冷却决定，是闸门；
2. **是否真的召回** —— 由姓名／别名／索引词命中决定；
3. **召回什么** —— 完整／详细／简单／提示（见 §7.10.2）。

冷却粒度：**完整召回冷却整个人物**；详细／简单／提示／连带只冷却**给过的具体条目**。0 轮＝无冷却。

**两个例外**（[ADR 0043](adr/0043-身份层豁免冷却与空值兜底.md)）：

- **身份层的唯一值条目永不冷却**——它本来就规定「必带」，被冷却掉会跟"必带"自相矛盾；而且少这一行，模型对"这是谁"就更没把握了；
- **冷却只剔内容、不剔人物**：一个被冷却到空的人如果分数够，仍然占名额但什么都不给（这个浪费是已知的，第一版不处理）。

**为什么不做「按上下文占用」的冷却**：酒馆没有向插件开放「模型当前上下文用了多少」「某段历史是否已被压缩」这类信息。插件只能读到存档里的正文与本轮请求材料，无法判断窗口真实余量，因此「掉出窗口才召回」无法准确实现，第一版不做。

**说明**：「注意力涣散」指长上下文中部信息利用率下降（Lost in the Middle），不是按轮数线性衰减，与上下文总长度、模型都有关。轮数只是粗略参考，玩家可自行调短。

**常驻摘要开关**（默认关闭）：

- 打开后，每轮给**关键度前 5 名、且处于离场状态**的人物各一行极简摘要；
- 每条限 20 字以内，只写姓名、关系、状态；
- 必须附一句「仅供一致性参考，不要主动安排他们回场」；
- 估算约占召回预算 6%～8%。

### 7.6 写回流程（正文之后）

1. 正文写完、MVU 结算完成后触发；
2. 程序筛出本轮涉及的人物（姓名／别名／索引词命中）；
3. 组装提示词：**当前游戏内时间（本轮 `gt`）** ＋ **可写栏目清单** ＋ **每个栏目现有的值（带序号）**；当前时间让模型知道故事里现在是哪一刻，避免写出与时间线矛盾的叙述；
> ⚠️ **下面 4、5 两步与「程序校验项」是旧「值动作＋信度码」模型的描述，已废**。现行是「一条命题 ＋ 若干指针」（[ADR 0083](adr/0083-写入流程-命题与指针.md)），模型交的是 `命题[]`＋`认知[]`＋可选 `撤回[]`（[ADR 0102](adr/0102-撤回指针.md)／[ADR 0106](adr/0106-撤回只写谁与约定回到固定提示词.md)），信度码已退役（[ADR 0108](adr/0108-信度码退役.md)）。**以 §四／§五 与 §7.6.1／§7.6.2 为准**，下面几段只当历史备查。

4. ~~后台模型**一次调用**返回动作~~（旧：新增／覆盖第 N 条／删除第 N 条／判定真假／无变化）；
5. ~~程序校验后写入快照~~。

**程序校验项**（旧模型，已废）：

- 栏目必须存在，且属于该人物；
- 「第 N 条」必须真实存在，越界即拒绝；
- 一次返回里不能对同一条既删除又覆盖；
- **唯一值条目**不允许「新增」第二条：已有值时必须改为「覆盖第 1 条」；
- ~~值长度、信度码合法~~（信度码已退役，见 ADR 0108）；
- 校验不通过 → 整条动作丢弃并记日志，不部分写入。

单轮判定即可，不做「先写再复核」的两轮调用。

**值的书写规范**（[ADR 0022](adr/0022-条目值的书写规范.md)）：

> **一条值 = 一个事实**，自然短句，尽量带专名（地名／机构／人名／独特物件）。

| 规则 | 例 |
|---|---|
| 一条只讲一件事 | ✅`左手两根手指没了`／`怕水`　❌`手指没了，所以怕水` |
| 4～15 字最舒服，**30 字硬上限** | ✅`旧港码头的账房` |
| 尽量带专名 | ✅`欠林澈一条命`　❌`欠一个人一条命` |
| 不用代词／泛指 | ✅`旧港码头`　❌`那个地方` |
| 不确定写进信度，不写进值 | ✅`欠林澈一条命`＋未定　❌`据说可能欠…` |
| 时间不写进值（有 `gt`） | ✅`受伤`＋gt　❌`三天前受伤` |
| 数字用阿拉伯数字 | ✅`欠300两`　❌`欠三百两` |
| 不加句末标点 | ✅`欠林澈一条命` |

程序能查的：长度、句末标点、数字形态、代词黑名单；"一条一个事实"只能靠提示词。

**索引词怎么抽**（[ADR 0021](adr/0021-关联词的抽取规则.md)）

- **时机**：写入同一次调用顺带输出，每条值 **0～3 个**，不额外调用（上限由 [ADR 0107](adr/0107-通用词自动抽与查档限次.md) 从 0～2 放开）；
- **只抽四类专名**：人名／地名·场所／组织·势力／独特物件·宠物；
- **不抽**：代词、泛指、**通用状态**（受伤）、通用职业（账房）、通用物件（刀剑）、评价情绪；
- **形态**：2～10 字，**必须是值的原文片段**（程序做子串校验，防幻觉）；每个词带**类别** `{词, 类}`，类 ∈ 人／地／组织／物件（[ADR 0077](adr/0077-全局专名词库.md)）；
- **条目分工**：可检索型（姓名／别名／最后去向／未了事项／关系）提供线索；纯描述型（性格／外貌／能力／后续计划／纯状态处境）只负责注入，靠"值里带专名"才获得检索力；
- **存哪**：直接存在**值条目自己的第 6 位**——`[码, 值, 信度, 轮次, 游戏内时间, 索引词]`（[ADR 0076](adr/0076-索引词跟着值走.md)）。**值回退，词一起回退**；不再有插件数据里的跨局缓存（老方案会漏回退、跨局污染、还占掉 256 KB 里最大一块）；
- **未命中就是没有索引词**，不漏不错——召回退回只认姓名/别名。不过**通用词不用模型抽**：程序会从值里自动切出通用词参与打分（§7.0②），所以模型一条索引词都不给，召回靠自动词也还能命中（[ADR 0107](adr/0107-通用词自动抽与查档限次.md)）。

### 7.6.1 系统提示词（建子代理时挂一次，之后固定）

**正文是 [plugin/assets/system-prompt.txt](../plugin/assets/system-prompt.txt)**——改完跑 `scripts/sync-prompt.mjs` 同步兜底副本 `plugin/prompt.js`（守卫测试会查两份是否一致）。本节只说约束，不复制全文。面板「提示词」标签页也能直接改（[ADR 0063](adr/0063-三段提示词可编辑.md)）。

- **运行期的真实来源是面板存档**：`readPrompts` → `resolveTemplates` 优先读 `plugin-data` 里的 `prompts.system`，空串才回落到 `assets/system-prompt.txt`；面板保存时还会把存档同步写进安装目录的 txt。所以改提示词要把**仓库 txt／`prompt.js` 兜底／安装目录 txt／面板存档**四处统一，否则「测试全绿但跑的是旧版」（[ADR 0105](adr/0105-系统提示词体检.md)）。
- **三段模板的「默认」也是三处一份**：每段都有 `plugin/assets/*.txt`（运行期真读的那份）、`plugin/prompt.js` 的兜底常量（`PROMPT_TEMPLATE`／`WRITE_TEMPLATE`／`RECALL_TEMPLATE`）、`lib/promptTemplates.js` 的 `DEFAULT_TEMPLATES` 三份。玩家点「恢复默认」（存空串）时，`savePrompts` 会把 `assets/*.txt` **重写成** `PROMPT_TEMPLATE` + `DEFAULT_TEMPLATES.write/recall`——任何一处没跟上，一按恢复默认就把旧内容写回文件。改三段的默认值＝改这三份＋跑 `scripts/sync-prompt.mjs`，守卫测试会逐字比对。当前召回段的默认是 194 字那版：抬头＋「不是剧情本身／不是客观真相」＋写作人称＋当前时间地点＋`{{BLOCKS}}`。
- 一局一个子代理，提示词**只在建的时候挂一次**（`systemPrompt.section`）；此后每轮只发素材（§7.6.2），**不重发提示词**；
- 一次发【判定】+【写入】两段合并素材，公共规则全在系统提示词里；
- 【本局视角】那一行由插件按本局设置拼进模板，不是写死的；
- **模糊离场不进提示词**：连续 N 轮没出现由程序自己数，模型只判「明确离场」和「回场」（[ADR 0030](adr/0030-术语统一与模糊离场归程序.md)）。

### 7.6.2 每轮发什么（判人与写入合并成一次）

**模板的实际来源是 `plugin/lib/followup.js` 的 `buildCombinedPrompt`**（内部复用 `buildJudgePrompt` / `buildWritePrompt`；写入段的骨架玩家可在面板「提示词」页改，程序负责把素材填进去）。本节只说约束与要点，不复制模板。

公共规则（人物级动作、命题与指针、值的写法、索引词、输出格式）在 [plugin/assets/system-prompt.txt](../plugin/assets/system-prompt.txt) 里；followup **只发素材、不发规则**。

**动态上下文**（本局视角、玩家称呼、代词规则、栏目定义、**认知口径**）由 `lib/followup.js` 的 `buildContextText` 拼在**工单开头**；系统提示词只留固定规则（[ADR 0095](adr/0095-系统提示词拆固定与动态.md)）。**【约定规则】**已于 2026-11-06 **移回系统提示词**「四、态度与来源」（[ADR 0106](adr/0106-撤回只写谁与约定回到固定提示词.md) 推翻 0105 的「按需发」：约定规则不随局变，属固定内容，固定处才能被模型缓存）；`buildContextText` 的 `definitions` 参数保留但不再使用。**【认知口径】**＝设置页「认知」组的落地处：拿不准给什么态度、亲见算不算真（默认关：按正文里他自己的表现判断，看不出才用默认态度；打开才写「主角亲见的、其他角色自己确认过的」那两条），以及「一条命题最多挂几个『听说』来源」的告知（[ADR 0098](adr/0098-认知模型四个旋钮.md)、[ADR 0103](adr/0103-亲见不自动算真.md)）。**【约定规则】**已回到系统提示词的「四、态度与来源」段（`约定状态只有四个`＋沿用条件＋示例），写明「只有【栏目定义】表里标了【约定】的栏目才用；本局没有约定栏目就别带这个字段」——约定规则不随局变，属固定内容，固定处才能被缓存（[ADR 0106](adr/0106-撤回只写谁与约定回到固定提示词.md) 推翻 0105 的「按需发」）。`buildContextText` 的 `definitions` 参数保留但不再使用。

面板「提示词」页这一份就是**模型的真实来源**：子代理每轮随工单发；「跟随后台」档把它注册成成员前缀，面板保存即重挂（[ADR 0096](adr/0096-面板提示词即成员前缀.md)）——前缀是**每次组装现取**的，所以**下一轮结算就生效**（既有会话也算），代价只是提示词缓存失效一次；页面顶部常显这条边界。系统提示词上限 20000 字（宿主成员前缀上限）。

- **一次发出去**：前半【判定】＝当前 gt ＋ **【本轮提到的人】＋ 状态** ＋ 【模糊建档】＋ 正文全文；后半【写入】＝本轮在场人物（**判人前**的状态）的栏目清单（含空栏目）；**锁住的人不列**——列了他也不能改，纯烧 token（[ADR 0038](adr/0038-锁的写入边界.md)）；
- **一次交回一个对象**：判人五块 + `命题` 数组（[ADR 0092](adr/0092-判人与写入合并成一次调用.md)）；程序先应用判人，再用判人后的档案校验命题，刚建档的人可以直接挂命题；
- **可选 `撤回` 块**：`撤回:[{谁,序号}]` 表示「**谁**不再这么认为了」——`谁`＝持指针的人（与 `认知[].谁` 同义），**命题说的是谁由程序按序号查、不要模型报**（[ADR 0106](adr/0106-撤回只写谁与约定回到固定提示词.md)，旧字段 `关于` 已废）；只摘**他一个人**的指针，撤到零指针就把那条命题清掉；只认在场人物、只认本轮素材里发过号的命题（[ADR 0102](adr/0102-撤回指针.md)）；调试日志按「谁 → 关于谁 · 命题内容」显示；
- 【模糊建档】**只给名字**（本轮出现的那些），不给轮次也不给次数（[ADR 0036](adr/0036-模糊建档表的存储与扫描.md)）；
- **没有模糊离场名单**——模糊离场是程序自己数的事（[ADR 0030](adr/0030-术语统一与模糊离场归程序.md)）；
- **没有已建档全名单**——去重是程序比对名字的事，发给模型只会让它"看谁都像"、瞎认人（[ADR 0033](adr/0033-判定素材删除已建档名单.md)）。

判断一段素材该不该发，只用一把尺子：**模型自己算不出来的才给**。正文、跨轮状态、某个模糊建档人物本轮露没露脸它都算不出来；已建档名单程序自己就有。

**【本轮提到的人】为什么必须带状态**：模型要判「回场」，得先知道**谁是离场的**；只给名字，这条指令就是空的（[ADR 0032](adr/0032-判定素材带状态.md)）。这一段的名单由**程序扫本轮正文**（`match.js`）命中已建档人物得出，不是模型自己找。

> ⚠️ **「提到」不等于「在场」**：正文里出现名字可能只是回忆、传闻、假设。只有正文写他实际在这个场景里、能对话能动手，才算在场。素材段标题因此叫「本轮提到的人」，不叫「本轮在场的人」；判法写进系统提示词的「改状态」段——**素材给事实，规则给判法**。

### 7.7 旧值怎么给模型

> ⚠️ **整节已废**（旧「值动作」模型）。现行写入素材是「按人组织、每人列出他知道的命题（带**局部序号**）」——序号跨人物共用以支持 `序号` 复用，格式见 `lib/followup.js` 的 `buildWritePrompt` 与 §7.6.2。本节保留只当历史备查（[ADR 0083](adr/0083-写入流程-命题与指针.md)）。

**所有条目都带现有值，并带序号。**

原因：动作集里有「覆盖第 N 条」「删除第 N 条」，模型必须看到值列表和序号才指得准。

**成本说明**：写回用的是后台模型，**不占用前台正文的上下文**，也不占召回的 3000 字预算，只增加后台输入。

**输入格式示例**：

> 【老陈·外貌】
> 1. 戴帽子
> 2. 左手两指旧伤
> 3. 右眼蒙布

> **草案（2026-11-01 记，未定稿）**：要让模型能判断"这条是谁说的、对玩家而言真假如何"，输入就得把**信度与时间跟着每条值一起给**：
>
> > 【老陈·外貌】
> > 1. 戴帽子（自述·真·永安元年·春）
> > 2. 左手两指旧伤（用户·真·永安二年·冬）
> > 3. 右眼蒙布（传闻·未定·永安三年）
>
> 状态见 [ADR 索引](adr/README.md) 的 **Q9**。

**变化信号加强**：若本轮正文出现「变成、不再是、成了、毁容、晋升、失去」等词，在该栏目后加一句提示：

> 本轮该栏目可能有变化，请逐条核对是否需要覆盖或删除。

**数值裁剪**：某人物条目过多时，按「与本轮线索的重合度」「最近更新时间」排序后截取；**包含计划的条目永远保留**。

**开关「未映射的内置条目是否由正文自动维护」（默认开）**

- 开：未被 MVU 映射的内置条目照常加入可写清单，由模型按正文补充；
- 关：可写清单里只保留**被 MVU 映射的条目**，其余内置条目只能手填，模型不再更新。

**开关「MVU 条目是否接受模型整理的值」（默认关）**

- 关：MVU 条目不进入模型的可写清单，只接受 `"9"`（MVU 抄入）的值；
- 开：模型也可以往 MVU 条目写值（普通信度码），与 MVU 值并存；关闭信度时仍按 5.5 的「MVU 优先」处理。

**条目过多时**按打分裁剪，打分维度为「与本轮线索的重合度」「最近更新时间」；**包含计划的条目永远保留**，不参与裁剪。

### 7.8 去重与改写判定

**第一层：程序精确去重**

归一化（去空格、统一全半角、去句末标点）后与该栏目已有值完全相等 → 视为「无变化」，不新增。数字按数值比较。

**第二层：近似改写交给模型判断**

模型在同一次调用里看到现有值列表与序号，自行决定「新增／覆盖第 N 条／删除第 N 条／无变化」，而不是悄悄并存两条。

**行业参考**：Mem0 原版在写入时用 ADD/UPDATE/DELETE/NOOP 四选一消解冲突；新版改变为只 ADD、新旧并存，靠读取时排序解决，代价是无处记录「哪条赢了」。本插件保留多值＋信度，并采用单轮判定，兼顾成本与可追溯性。

### 7.9 条目有效期

**本插件不做「到期／兑现」判断。**

- `gt` 只表示**这条值被收进来的时间**，不表示"事情什么时候发生"；
- 不打「待确认／已兑现」标记、不做定期复查、召回里也不提示"可能已过期"；
- 理由：模型没有"轮次"概念，没有 gt 的游戏更无从判断，硬做等于让它瞎猜；
- **这套更适合单独做一个插件**（方案存在 [ROADMAP](ROADMAP.md) §6.3）。

**不做**「按轮数折算游戏时间」，节奏差异过大，误差不可控。

### 7.10 召回加权算法

设置项：**召回加权算法** —— 等权归一化（默认）／ RRF 名次融合。

**模式一：等权归一化（默认）**

> 分 = (匹配 + 一致性 + 先验 + 时效) ÷ 4

四个信号一律用**固定刻度**归一化，**不按本轮候选做 min-max**（候选只有一两个时 min-max 会把最高分永远抬成 1.0，导致“只要命中就满分”）：

| 信号 | 固定刻度 |
|---|---|
| 匹配 | **只看「点名」**：姓名 1.0；别名 0.9；**单字一律 0.6**（细则见 [ADR 0010](adr/0010-单字命中细则.md) 与 §7.10.1）。**不含索引词**——索引词归「一致性」 |
| 一致性 | **只看「沾边」**：这一轮文本对上了他档案里几条索引词 → 1 条 = 0.4；2 条 = 0.6；3 条 = 0.8；**4 条及以上 = 1.0**；0 条 = 0 |
| 先验 | 关键度在全册中的分位，0～1 |
| 时效 | **分角色**（[ADR 0017](adr/0017-四档召回与完整召回三重门.md)）：★重要人物 `0.6 + 0.4 × exp(−0.01 × 离场轮数)`（上限 1.0，**地板 0.6**）；普通角色 `0.9 × (下限 + (1 − 下限) × exp(−0.01 × 离场轮数))`（上限 0.9），下限由剧情节奏档位给（慢 0.7／中 0.5／快 0.2） |

> **匹配看「点名」，一致性看「沾边」**（[ADR 0041](adr/0041-匹配与一致性拆开.md)）
>
> | | 回答的问题 | 怎么算 |
> |---|---|---|
> | **匹配** | 这句话**有没有提到他**？ | 姓名 1.0／别名 0.9／单字 0.6 |
> | **一致性** | 这段话讲的**事跟他有没有关系**？ | 对上 1 条索引词 0.4／2 条 0.6／3 条 0.8／4 条以上 1.0 |
>
> 举例：正文写「A 地遭袭，白鸦带着旧港的人赶来」，老陈档案里登记着「A 地」「旧港」「一张欠条」——**没人点老陈的名**，但对上了 2 条 → 一致性 0.7。「没点名但明显相关」就是靠这一项抓的。
>
> **两项不共用同一批数据。** 改前是同一条索引词在两项里各算一次（匹配 0.5 ＋ 一致性按条数），等于给「沾边」发了两票，会算出"只沾边的人分数比本人出场还高"。

- 权重全为 1.0，依据是 Generative Agents 的做法（多信号归一化后等权相加）；
- 固定刻度让分数**绝对可比**，阈值才有意义。

分档阈值（[ADR 0017](adr/0017-四档召回与完整召回三重门.md)、[ADR 0018](adr/0018-装配三步与完整召回延后.md)）：

| 分数 | 处理 |
|---|---|
| ≥ 0.90 ＋ **玩家允许** | ~~完整召回~~ **第一版砍掉**（方案存 [ROADMAP](ROADMAP.md) §6.1）；现在一律按详细给 |
| 0.60～0.90 | **详细召回**：挑过的记忆（每条目最多 2 条值） |
| 0.40～0.60 | **简单召回**：名片 |
| 0.20～0.40 | **提示召回**：印象（人物识别 + 唯一值 + MVU + 离场时间） |
| < 0.20 | 不召回 |

> 完整召回的三重门（全局开关 + ★标记 + 分数 ≥0.90）**设计已定但第一版不做**，连"每轮最多 2 个"的名额规则一起存在 ROADMAP §6.1。代码里 `TIER.full` 与 `tierOf({ fullAllowed })` 还在，默认 `false`＝永不触发；装配层不实现。

同名候选分差 **< 0.10** 视为分不清。

**普通角色总分封顶 0.79**（[ADR 0011](adr/0011-时效分档与普通角色封顶.md)）：分数上就够不着 0.90，再叠上"完整召回只给★"这道门，两道保险。

### 7.10.1 单字命中细则

单字（姓名或别名长度为 1）**一律只给 0.6**，永不置 `name`／`alias`，因此最多到「提示召回」档。哪些算命中：

| 场合 | 算 | 不算 |
|---|---|---|
| **最近几轮正文** | **称谓形态**：老X／小X／阿X／X老板／X姑娘／X先生／X总／X哥／X姐／X叔 | 裸单字（周末、周天子、周朝、大小周） |
| **玩家输入** | 称谓形态；外加**独立成词**（「周，」「问问周」「周不是」「你叫周什么」「我们的周呢」） | 夹在词里的（周末、大小周、这周、周国强） |
| **两边都算** | 被引号/括号包住（「生」「死」）——**待拍板 Q1** | — |

**闭集边界规则**（玩家输入里的裸单字）：

- 前界＝句首／标点／介词·连词·助词·量词＋少量高频动词；
- 后界＝句尾／标点／**语气词＋否定词＋疑问词**；
- **内容词一律不进表**——「会／朝／都／要／的」这类会把「周会」「周朝」判成在叫周，这是被对抗测例撞穿过的地方；
- **指示代词「这／那」与序数「上／下／每／一／两」不进前界**——它们和「周」组成时间词。

**线索词**：单字线索词（酒／刀／雨）直接丢弃；同一词去重；子串合并（「旧港」与「旧港码头」算同一条）；大小写合并。

### 7.10.2 四档内容：提示 / 简单 / 详细（完整延后）

提示与简单共用同一个**身份层**，且**只在勾选了的条目里取**：

| 层 | 取什么 | 规则 |
|---|---|---|
| ① 人物识别（姓名位） | 人物记录里的姓名／称呼 | **有值就必带、且永不冷却**（**必须非空**，见下）；它不在条目里，所以不吃条目冷却 |
| ② 唯一值条目 | 玩家自己点开的那些（**默认预设里一个都不开**） | 有值就必带、**永不冷却**；没值就整行省略 |
| ③ MVU 值 | 信度位是 `"9"` 的值 | 单独 **50 字符窗口**，按值**从短到长**填，装不下就截断 |

**召回的两个前提**（[ADR 0044](adr/0044-姓名升到人物级别.md)）：

1. **姓名位非空**——没名字匹配不上，抬头也写不出来，召回来模型也不知道是谁；
2. **至少有一个条目有值**——档案全空的人召回来只是一行名字，纯占预算。

任一条不满足 → **不参与召回**，但**照常参与写入**（写入靠人物码 `p7`，跟有没有名字无关）。

> 唯一值条目没值怎么办：整行省略，**不占位、不替补**（[ADR 0043](adr/0043-身份层豁免冷却与空值兜底.md)）。

**提示**（0.20～0.40 档，也是单字命中的出口）＝ 身份层 ＋ **离场时间**：

- 离场时间取**离场记录**里的 `gt`（他真正离场那一刻的游戏内时间）；**没有 `gt` 就整段省略**——轮次只供插件内部用，**不给模型看**；
- **不发任何剧情条目**——只告诉正文模型"有这么个人、什么时候走的"，要不要理会由它判断。

**简单**（0.40～0.60 档）＝ 身份层 ＋ ③ ＋ ④ ＋ 行尾最后确认时间：

| 段 | 取什么 | 规则 |
|---|---|---|
| ③ 最重要的一条 | 来源必须落在**上一轮在场人员**里 | 取其中排序最高的；两个条件必须同时满足，没有就不带 |
| ④ 再一条 | 来源同样要在场 | 但不能与 ③ 同一个来源；在符合条件的里**随机**取 |
| 行尾 | 最后确认时间 | 取**离场记录**的 `gt`；没有就**省略这一段**（轮次不给模型看） |

**详细**（0.60～0.90 档）＝ **所有勾选条目**，但每个条目**最多 2 条值**（最可信的一条 ＋ 最新的一条；同一条就只给一条）。条目按「本轮相关 → 预设顺序 → 信度」排；含「计划」的条目**永不裁**。每人约 400 字符。

> ⚠️ **「详细档具体召回什么」还没定稿。** 上面这套（所有勾选条目 ＋ 每条目最多 2 条值 ＋ 那个排序）是**临时口径**，不是定论。至少还有这些没想清楚：要不要按分数只挑前 N 条？「最可信＋最新」会不会漏掉关键旧事？「计划类永不裁」该不该有上限？每人 400 字够不够？——统一记在 [ADR 索引](adr/README.md) **Q11**。

> **「本轮相关」怎么判**：拿 §7.1 合并去重后的命中词，去查每条值的索引词（[ADR 0021](adr/0021-关联词的抽取规则.md) 的按值缓存），**有交集的值优先**。所以 `flags.lastHits` 必须存命中的**词**而不只是条数——只给条数，程序挑不出「该给他哪一条」（[ADR 0042](adr/0042-一致性四档与召回命中缓存.md)）。

**完整**（≥0.90 且玩家允许）＝ 整个档案——**第一版不做**，方案见 [ROADMAP](ROADMAP.md) §6.1。

**容量估算**（默认预算 3000、上限 6000 字符）：一人简单约 **200 字符**、详细约 **400 字符**；一轮 10 人先拿简单 ≈ 2000 字符，余下的用于升级详细。因为"人人先拿简单"，重要人物再多也不会突破预算，只会让升级名额变紧张。

### 7.10.3 注入格式（召回）

注入是一段**独立的资料块**，不是正文的延续。格式固定为：**抬头 + 人块**。

```
【人物档案参考】
本局写作人称：第二人称
当前：永安三年·冬 · 临安·旧港·码头

▍老陈
· 身份：旧港码头的账房 —— 他自称（永安元年·春）
· 最后去向：旧港码头 —— 主角确认过（永安二年·冬）
· 未了事项：欠南洋商行一笔钱 —— 林昭说的，其实是假的（永安二年·冬）

▍周
· 当前处境：受伤 —— 只是听说（永安三年·冬）
```

**抬头说清这是什么**（[ADR 0080](adr/0080-召回抬头与来源标注.md)）：第一行固定「人物档案参考」，第二行写**本局写作人称**（第一/二/第三人称），让模型知道正文里的「你／我」指谁。**不写主角名**——系统提示词里已经有「主角＝{{PLAYER}}」。系统提示词里另有一段话解释这块资料是干什么的。

**抬头下方必须给「当前游戏内时间 ＋ 地点」**（本轮 `gt` 与 `loc`）——就是上面示例的第三行。每条值自己带的时间是"**这条值被收进来的时间**"；当前时间＋地点让模型知道故事里现在是什么时候、在哪儿（[ADR 0053](adr/0053-快照地点与MVU勾选.md)）。**两个都没有就整行省略**；只有一个就只写那个。

**每一条值**：`条目名：值 —— 来源描述（时间）`

- **来源描述**由**指针的来源组**渲染（`[态度, 来源, 时间?, 约定?]`）：「他自己确认过／他听某人说的，拿不准／他认为这是错的」这一族（[ADR 0083](adr/0083-写入流程-命题与指针.md)）。
- 早期那套**信度码**（`"0"`～`"9"`、`"X"`/`"N"`、`r42`）已经**整体退役**——它一维地混着"谁说的"和"真不真"，且是主角单视角，在第三人称下会崩。完整考古与替代关系见 [ADR 0108](adr/0108-信度码退役.md)，本节不再复述那张表。
- **不写「亲眼见过」**：主角可能是在衙门查档案确认的、或者亲耳听到的，不是用眼睛看见的（[ADR 0080](adr/0080-召回抬头与来源标注.md)）。也不写人称代词——「你亲眼见过」在第三人称卡里是病句。
- **时间**取该条值自己的 `gt`；没有就不写这一段。
- 一个条目最多 2 条值（最可信 + 最新），见 §7.10.2。
- 一个都没命中 → 整段不注入。

> **视角人物**目前取酒馆的 `{{user}}`；后续会加「在本插件里指定档案视角人物」的设置（见[ROADMAP](ROADMAP.md) M4-10）。

**模式二：RRF 名次融合**

> 分 = Σ 1 / (60 + 该信号下的名次)

- `60` 为 RRF 通用常数；
- 把每个信号当作一个排序列表，按名次而非绝对值融合；
- 算出后除以本轮最高分做归一化，**仅用于展示与比较，不用于卡档位**。

分档按**最终名次**：

| RRF 排名 | 处理 |
|---|---|
| 第 1 名 | 完整召回（还要过"玩家允许"那道门，否则降为详细） |
| 第 2～4 名 | 详细召回 |
| 第 5～8 名 | 简单召回 |
| 第 9 名以后 | 提示召回或不召回 |

同名消歧改看**名次是否互有胜负**：两个候选在四个信号的排名里各自都拿过第 1 → 视为分不清；一方四项全胜 → 分得清。

**选用建议**（同时写在设置页说明里）

- 平时独白、对话，命中的通常只有一两个人 → **用等权**（能判断“这个命中其实很弱，不该召”）；
- 群戏、长文、多方势力，同轮候选很多 → **用 RRF**（只比名次，避免被个别极端分数带偏）。

### 7.11 沉降（冷档）

长期没人提起的人物会**沉底**：退出召回的主力通道，面板折叠成一个「冷档」分组。**档案数据一个字不删**（[ADR 0031](adr/0031-回头测试与沉降.md)）。

**是算出来的，不是存字段**

```
gap  = 当前轮次 − 最后确认轮次
沉降 = gap ≥ 沉降轮数  且  非★
```

- `最后确认轮次` ＝ `flags.seen[编号]`（定义见 §2 离场判定）；取不到就当 `0`；
- **沉降状态本身是现算的**（不存字段），所以回退时只要 `flags.seen` 正确，沉降状态就自动正确；
- 状态值仍然是 `0/1/2/3`，**不新增状态**；
- 实现在 `plugin/lib/` 的纯函数里，可本地单测。

**设置项**

| 设置项 | 默认 | 范围 | 说明 |
|---|---|---|---|
| **沉降轮数** | **20 轮** | 5～999（999＝不沉降） | 从「最后确认轮次」算起 |

**沉底后只发生三件事**

| # | 变化 |
|---|---|
| ① 面板 | 折叠成「冷档（N）」，默认收起，点开可见全部 |
| ② 召回 | 正文**明确写出姓名或别名 → 照常召回**；只沾到索引词 → **不召回** |
| ③ 排序 | 不参与按时效分／关键度往上顶的主通道 |

> 为什么第 ② 条要分开：正文写出「老陈」三个字，是作者在明确叫这个人；写出「鱼」只是顺带沾到。冷档不该占这种顺带便宜的便宜。

**怎么浮起来**：本人出场／被提到名字／写入新值／玩家编辑／点★——任何一件都刷新 `最后确认轮次`，gap 归零，立刻回活跃区。

**豁免**：只有 **★ 重要人物** 永不沉降（与 [ADR 0011](adr/0011-时效分档与普通角色封顶.md)「★ 人物时效不衰减」同源）。**手动锁定 🔒 不豁免**——锁只拦写入，沉降只折叠显示、不改数据，两件事无关（[ADR 0037](adr/0037-锁与眼睛解耦.md)）。

**和现有几个倒计时各管一段**

```
他最后一次出场 ───────────────────────────────
   ├─ +3 轮   模糊离场（程序判，改状态）
   ├─ +3 轮   **离场缓冲**（刚离场不召回，免得太念叨）
   ├─ 之后    正常可召回，时效分从高往下掉
   └─ +20 轮  沉降（沉底，只响应姓名命中）
```

**明确不做**：不删数据、不加状态值、不改在场／离场语义、**不动存储结构**。沉降治的是「面板吵」和「召回误伤」，不治存储。

>

> **设置页**（`SettingsView`）：**组级手风琴**，默认只展开「档案写入方式」「召回」，其余只显示标题 +「N 项」，点标题开合（段级折叠仍按原来的偏好存盘）。
>
> **字体与字号跟酒馆走**：面板不指定字体族（`panelRoot` 写 `fontFamily: 'inherit'`），表单控件靠一条受控样式（`.ca-panel input/textarea/button/select { font-family: inherit }`）补继承——浏览器默认不让表单控件继承字体。字号**不写死像素**：面板根上把宿主的实际字号量一次写成 `--ca-base`（`getComputedStyle` + `setProperty`，切回面板或改窗口大小时重新量），所有字号写成 `calc(var(--ca-base) * 倍数)`（阶梯见文件顶部 `font`）。**为什么不用裸 `em`**：`em` 是相对父元素的，父级 0.9em 里再写 0.82em 会叠乘成 0.74em，嵌套一深反而更小。提示词编辑框保持等宽字体（那是代码/规则，等宽更好读）。
>
> **历史快照下拉**（`snapshotLabel`）：读作「第 N 轮 · 时间 · 地点」，缺哪段省哪段（不再用竖线拼接）。
>
> **「数据位置」说人话**：宿主给的 key 在客户端映射成「插件自己的文件夹／历史存档（回退时用）／废文件（自动清）」这类说法（宿主新增 key 自动回退它自己的 label）；「立即清理」先弹确认（写明是死数据、删了不进回收站）。
>
> **颜色走酒馆主题变量**：文件顶部抽了一组语义色（`ui.text／muted／line／fill／soft／danger`），一律 `var(--SmartThemeXxx, 兜底)`——兜底值就是旧观感，取不到变量时看起来跟以前一致；纯功能性的强调色（闪烁、拖放允许／禁止、状态绿／琥珀）按注释保留。
>
> **人物行与模糊建档候选都可拖**：拖到在场／离场改状态、拖到冷档手动沉底；**模糊离场不收任何东西**（亮红框、浏览器直接显示禁止光标）。人物行**只有标题那一行可拖**（`cursor: grab` 给提示），展开后的正文区不接拖拽——整行可拖时，在正文里想标选一段文字会变成拖动人物（2026-11-06 玩家反馈）。
>
> **主角那一行带「主角」徽章**（`p0`），且**置顶、不显示 ★、永不冷档**；名字跟「本局设置」的玩家称呼双向同步。第二人称卡里主角的姓名常常就是「你」——没有徽章会被当成误建档的 NPC。**代词不是名字，但它是主角的指代**：第二人称下模型报的「你」、第一人称下的「我」，都由 `resolvePersonRef` 认成 `p0`，不新建人物（第三人称不映射，「他」可能指任何人）。
>
> **人物详情是「二选一」的两块**（不是并排：顶部「按栏目浏览／按认知浏览」两个按钮切换 `browse`，同一时刻只画一块）：「**他是什么样**」（关于他的命题，按栏目分组，**空栏目也列**）与「**他的认知**」（他的指针，按命题的栏目分组，带「关于谁」）。两块各自可折叠（标题行「▸ 标题 · N 条」，默认展开）；**单栏超过 6 条只显示前 6 条**，剩下的「还有 N 条（点开）」再展开。容器是 `flexWrap` + 每块 `flex: '1 1 240px'`：侧栏拉宽时两块能并排吃满（切到同一块时单块吃满整行），拉窄时自动上下堆叠，不会挤成两条缝。玩家可以手动加命题（每栏「＋」）。**NPC 手动改名也自动把旧名存进别名**（设置页「改名 · 旧名自动存别名」可关，默认开；模型改名一律保留）。
>
> **人物行的按钮常显（「⋯」折叠已撤）**：名字紧跟右侧依次是「主角」徽章（主角档才有）、★ 重要人物，再往右是状态 chip（在场／离场）和一行小按钮——改名 ✏、锁 🔒/🔓、眼睛（对模型隐藏）、删除 🗑。**为什么撤回折叠**：玩家反馈每次操作都要多点一下，宁可密一点也不藏（2026-11-06）。值行后的**索引词小标签仍默认收起**，只显示「索引词 N」开关，点开才看 chip 和编辑入口（没有索引词时直接给 ✎，否则新命题永远加不上词）。旁边另有一个**灰色虚线小标签「自动词 N」**：程序从这条内容里切出来的词（§7.0②），点开能看、**不能编辑、不落盘**，用来解释"这人凭什么叫得回来"；它**不混进索引词字段**（分不清来源、词表升级对老数据失效、编辑会污染，[ADR 0107](adr/0107-通用词自动抽与查档限次.md)）。
>
> **操作图标一律内联 SVG**（`ICON_SVG` 一块底板 + `EyeIcon`／`EyeOffIcon`／`TrashIcon`／`PencilIcon`／`LockIcon`）：`1em` + `currentColor`，跟旁边的字同色同大小、随宿主字号缩放。以前用 `🙈`／`👁`／`✏`／`🔒`／`🔓`／`🗑` 这些 emoji/字符，不同系统长得不一样（有的还是彩色方块），在深色主题里也不一定看得清；`tests/clientStructure.test.mjs` 现在禁止这几个字符再出现在 `client.js` 里。
>
> **命题和认知都能删**：每行末尾一个红色小 🗑（都要先 `confirm`）。「他是什么样」里删的是**命题本身**——指向它的「谁知道」一并摘掉（不留悬空）；「他的认知」里删的**只是这个人对它的认知**，命题仍留在「他是什么样」里（宿主 `delete-claim` / `delete-cognition` 两个接口，`dropClaim` / `dropPointer`；不做撤销）。⚠️ **只剩最后一条认知时会被拒绝**并提示改用命题行的 🗑：零指针的命题会被下一轮结算的 `pruneOrphanClaims` 当孤儿悄悄摘掉（豁免只给本轮新建的），那样就成了"我只删了认知，命题自己没了"（评审 2026-11-06 抓到的阻塞项）。
>
> **变化可见**：`panelView` 给每个人算出 `lastChangeTurn`（他自己的认知指针与「关于他」的指针里最大的指针第 4 格）和 `changedThisTurn`（`> 0` 且等于当前轮）；**排序**改成「主角 → ★ → **最近有动静**（露面轮次与改动轮次取较大者）倒序 → 改动轮倒序 → 露面倒序 → 名字」。为什么不是"改动轮倒序"直接比：改动轮是绝对轮次，第 3 轮记过一笔的人会永远压过第 40 轮刚出场的人。界面上：人物名字左边一个主题色小圆点（title「本轮有变化」），分组标题「在场 · 7」并追加「本轮 N 处变化」（0 不显示）。
>
> **档案页顶部有「看历史快照」下拉**：列出可用轮次（文案「第 N 轮 · 时间 · 地点」，缺哪段少哪段），按轮次正序、最多显示 5 条可滚动；选中后**只读**预览那一轮的人物册（分组＋人名＋状态），「回到当前」返回。宿主接口 `snapshot-list` / `snapshot-at`，预览不落盘。
>
> **设置页只有「全局级」一段**（全部设置跨卡共用；「离场」组也已并入这一段，组里现在只看得到模糊离场判定轮数）。存储组有「trash 保留多少天」（7～90，默认 15）；「数据位置」区显示 trash 数量并有「立即清理」按钮。

### 8.1 主入口

侧栏「人物档案馆」，两个可折叠分组，从上到下：

> **离场 → 在场**

- 点组名展开／收起；
- 组内行不重复显示状态；
- 小锁标记，点击切换锁定／解锁；
- **分组依据**：状态 `0` → 离场组；`1` → 在场组。

### 8.2 组内人物行

- 显示哪些栏目由玩家勾选，**两个分组共用一套**；
- 默认：姓名、关系、身份/职业、离开时间、最后地点；
- 可按展示栏目排序，支持正序／倒序；
- 点人物行就地展开详情。

### 8.3 人物详情

**层级结构**：

```
人物（🔒锁、👁可见性 在这一层）
  └─ 条目（如「预计去向」）
       └─ 值（可多个：A地 / B地 / C地）
            └─ 每个值各自带信度
```

**各层能做与不能做**：

| 对象 | 可以 | 不可以 |
|---|---|---|
| **值** | 编辑、删除（删除需点两次） | — |
| **MVU 条目** | — | **删除**、**改名字**（去映射表）、**改值**（去酒馆变量面板） |
| **个人条目** | 改名、删除（删除即清空该条目下所有值） | — |
| **人物** | 🔒锁、👁可见性 | — |

> ⚠️ **下面这段是旧「条目／值」UI 的描述，2026-11-05 已退役**。面板现在只有「**他的认知**」一块：每条＝一条命题（点一下改内容）＋ 每个来源组的态度下拉／来源输入。旧的「值」区（`＋/改/删`、空栏目折叠、MVU 值配色）连同 `/set-value`、`/delete-value` 两个接口一起删了——它们读写的是人物第 4 格 `p[3]`，新写入只写命题＋指针，那一格基本是空的，留着只会让人以为"值丢了"。删除确认里的条数也改成数**认知（指针）**，不再数旧条目。

**交互**：

- 展开人物后显示全部条目，空条目显示为折叠按钮；
- 默认只读，点「编辑」后才解锁可改；
- 悬停值右侧出现「编辑」「删除」；点编辑 → 变成输入框，按钮变「保存」，回车或点保存生效；
- MVU 条目在程序层拦截：界面上不给编辑入口，即使通过对话修改也会被拒绝；
- **MVU 值单独配色**：淡蓝底 + 右侧小「MVU」标签，悬停提示「该值来自状态机，优先级最高」；无信度值（`"X"`）显示为灰色。
- 详情最底部「添加」：填展示名、键名、追踪内容简述，并选择**唯一值／可多值**（默认可多值）；
- 再点人物行或其他条目即收起；
- 组名行与人物行吸顶常驻。

### 8.4 组级编辑

组名行悬停右侧出现「编辑」，相当于**全选组内所有人物**，批量新增或删除**个人条目**；映射条目自动跳过，不受批量删除影响。

### 8.5 详情页顶部

贴一行**姓名 ＋ 别名**（半角逗号分隔，中英文逗号都认）：

- 姓名必须非空；别名可留空；
- 姓名和别名一起提交、一起校验（旧姓名可以直接挪进别名，不用绕占位符）；
- 别名全部参与召回匹配，所以"触发召回的关键词"就是这一行——没有单独的关键词字段了。

### 8.7 人物行上的三个开关（★／锁／眼睛）

人物行里有三个图标，**各管一边、互不联动**：

| 图标 | 管什么 | **不管**什么 |
|---|---|---|
| ★ 重要人物 | **召回的预算份额**：拿剩余预算的 60%（并在 ★ 之间平分），而且**不会沉到冷档** | 不影响写入 |
| 🔒 锁 | **写入**：锁上则禁止写入 | **召回照常**——他还会被注入正文 |
| 👁 眼睛 | **召回**：闭上则前台模型看不到 | **写入照常**——正文提到他，档案照样更新 |

> ★ 的标记存在整局数据 `flags.star`，接口是 `/toggle` 的 `star` 字段（2026-11-05 才补上写入口——此前只有读取、没有按钮，等于死功能）。
>
> **主角（`p0`）不显示 ★**：他本来就走「回场全量注入」、也不进冷档，标了没意义。
> **置顶优先级：主角 → ★ 重要人物 → 最近活跃 → 名字**。主角和 ★ 在每个状态组里都排最前面。
> **主角永不进冷档**：程序按轮次判的、玩家手动拖的，都不算——他是玩家自己，不是"没人提起的配角"。

**四种组合都合法**（[ADR 0037](adr/0037-锁与眼睛解耦.md)）：

| 🔒 锁 | 👁 眼睛 | 效果 | 典型用途 |
|---|---|---|---|
| 解锁 | 睁开 | 正常：能召回、能写入 | 绝大多数人 |
| **锁上** | 睁开 | **只读**：照常召回，模型不改他 | 你自己精心写好的档案 |
| 解锁 | **闭上** | **只写**：不主动提起，但剧情说了什么照记 | 幕后黑手：还没揭晓，先别念他 |
| 锁上 | 闭上 | 全关：召回与写入都停，只剩玩家手动编辑 | 暂时藏起来不让程序碰 |

规则：

- **两个标记互不联动**——"能写不能读""能读不能写"都是**允许**的状态；
- 两者都不写入快照，存插件自己的整局数据；回退时人物保持原样；
- 其他通道是否跟随，由设置页三个开关决定（见 8.6）；
- **锁不影响沉降**：锁住的人照样会被沉底折叠（沉降只改显示，不改数据）。

**改姓名 / 别名**：行上的 `✏`（或双击名字）快速改姓名；**展开后在顶部那一行可以姓名与别名一起改**。**不许留空、不许和别人的姓名或别名重名**，主角名也不能占；**名字里不许出现括号、逗号、顿号**（括号会跟编号尾巴打架，逗号是别名分隔符），字符白名单比正文更严——不做"特殊输入也能用"的兼容。留空会被拦下并提示——姓名留空的人既召回不到、也写不进去（[ADR 0084](adr/0084-姓名与别名的唯一性与导入体检.md)）。**两个值一起提交**是有意设计的：分开改会卡死（别名不许等于现在的姓名，姓名又不许撞现在的别名），一起提交则按「提交后的样子」校验，把旧姓名挪进别名一步就完成。这些按钮不参与上面「召回 / 写入」的分工。

**锁只管「档案内容」，不管两件事**（[ADR 0038](adr/0038-锁的写入边界.md)）：

| 事 | 锁住后 |
|---|---|
| **改状态**（离场／在场） | **照常**——锁不算写入。锁防的是内容被瞎改，状态是剧情事实，应该跟着正文走；否则锁住的人永远停在「在场」，再也进不了召回池 |
| **进入【写入】素材** | **不列**——判定照常发他（好让他能被改状态），但合并后的写入段不列他的栏目清单：列了他也不能改，纯烧 token |

> 条目级、值级的锁**现在没有**，要锁只能锁整个人 → 见 [ROADMAP](ROADMAP.md) M5-6。

### 8.8 条目预设库

> ⚠️ **「MVU 人物字段映射」已于 2026-11-05 退役**（[ADR 0091](adr/0091-MVU人物字段映射退役.md)）：`stat_data` 里的人物字段**不再抄进档案**，一律由模型读正文写入。面板上只剩**「MVU 时间与地点（兜底）」**两个下拉——选「程序自己找不到时间／地点时用哪个字段」；自己找得到就不看映射。
> 下面从「MVU 映射视图」开始的那套（行级勾选表、通用预设自动对应、「存进卡里」）都是**退役前的设计**，留作将来可能加回来的参考，**别照着实现**。

**一个库，一个视图**：只有「条目预设」。卡有没有 MVU 都一样——时间和地点的兜底下拉在没有 MVU 时直接显示"没读到 MVU 变量"。

**「条目预设」视图**：管理条目本身——名字、抓取提示词、**是否唯一值**、是否全员共有。

**唯一值条目与「人物识别」的关系**（[ADR 0044](adr/0044-姓名升到人物级别.md)）

姓名已经**升到人物级别**（存在人物记录里，不是条目）。所以：

- **默认预设里一个唯一值都不开**——玩家想给某个条目加唯一值，自己点；
- **导入预设时必须至少有一个唯一值条目**，否则**拒绝导入**并提示「这份预设里没有唯一值条目，无法确定用什么当人物识别」；
- **有多个唯一值时**，取**预设表里第一个**唯一值条目，**抬升到人物行**作为人物识别方式：它的值直接进人物记录的姓名字段，**它本身不再是条目**；其余唯一值条目照常保留为条目；
- 抬升是**导入那一刻**决定的，之后玩家想换识别字段，按「人物改名」处理（旧名进别名，[§2](#同名改名与合并)）。

**「MVU 映射」视图**（**已退役**，见上方警告；现在是「MVU 时间与地点（兜底）」）：管理 MVU 字段与条目的对应关系（见下）。

| MVU 字段 | 对应档案条目 |
|---|---|
| **⏱ 时间源字段**（第一行，单独配色标识） | 选择 MVU 中的日期字段 ▼ |
| 星岁（只读） | 年龄 ▼ |

- **第一行是「时间源字段」**，标不同颜色以便区分；它决定计划类条目如何算到期；
- 左边字段名不可编辑；
- 右边下拉只列**全员都有**的条目；
- 可在映射表新增条目，新增后三个组所有人都加一条；
- 不需要填「追踪什么内容」的说明；
- **MVU 值要玩家勾选才收**（[ADR 0053](adr/0053-快照地点与MVU勾选.md)）：勾了的才抄成条目；**取消勾选就删掉那条条目、本局不再捕获**；删掉已映射的条目也等于取消映射；

**库的存储：条目预设库 + 卡绑定**

不再「一张卡一张表」，改为**命名的条目预设库**：

```
条目预设库：
├─ 通用预设（内置，所有卡可用）
├─ 我的古风卡预设
└─ 某作者的卡预设
```

每份预设包含：

- **条目定义**：名字、抓取提示词、**是否唯一值**、是否全员共有；
- **MVU 映射**（仅在该卡有 MVU 时有意义）：MVU 字段 ↔ 条目候选与生效项；
- **时间源字段**。

**存储与绑定**

- 预设存**插件数据区**（`savePluginData`），**不放在插件文件夹**（更新会整体替换文件夹），也不写死在某个卡 ID 上；
- 卡与预设**分开存**：绑定关系单独记录，可自由**绑定／解绑／换绑**；
- 换绑在**下一轮起生效**（即下一次玩家输入到正文输出这一轮）。

> **当前状态：这一段（命名库／卡内副本／绑定解绑换绑／「存进卡里」）都还没实现。** 真正在用的只有「**全局一份 + 按卡覆盖**」（[ADR 0093](adr/0093-预设全局默认按卡覆盖.md)）：插件数据里的 `presets` 是全局默认，玩家点「按卡保存」才写 `presetsByCard[卡]`，读取顺序＝卡级覆盖 → 全局 → 内置默认；代码里搜不到绑定的存储，也没有一处调 `updateCardRaw`（`index.mjs:599` 那句注释写着"以后可以手动存进卡里"）。下面几张表留作设计参考。

**优先级：显式绑定 > 卡内副本 > 通用预设**

| 优先级 | 来源 | 何时使用 |
|---|---|---|
| 1 | **显式绑定**（给这张卡指定了库里某份预设） | 有绑定就永远优先 |
| 2 | **卡内副本**（写在卡 `extensions` 里的那份） | 没有绑定时读取 |
| 3 | **通用预设** | 前两者都没有时兜底 |

**各操作的副作用**

| 操作 | 结果 |
|---|---|
| **绑定** | 建立显式绑定，立即压过卡内副本；界面显示「当前使用：XX 预设（已绑定）」 |
| **解绑** | 清除绑定 → 回落到卡内副本；界面提示「已解绑，将使用卡内的映射」 |
| **换绑** | 等价于「解绑＋绑定」，新绑定下一轮生效 |
| **保存到人物卡** | 把**当前生效的那份**写进卡扩展，供分享时兜底 |

**导出与导入**

> **当前状态：单独导出／导入预设没做，已排下一版**（[ROADMAP](ROADMAP.md) **P10**，[ADR 0052](adr/0052-砍掉单独预设包.md) 砍掉的就是它）。现在预设只跟着**档案包**一起走：导出侧 `buildPresetExport` 仍是内部函数（面板只调档案导出），导入侧 `importBundle` 已经能认 `kind:'preset'` 的纯预设包但面板没有入口。下面三条是「要做成什么样」。

- 可导出「通用预设」，也可导出任意一份自己的预设；
- 格式为 JSON，走浏览器下载，**存到哪个位置由玩家自选**；
- 导入时选择文件 → 校验版本与字段合法性 → 存入**条目预设库** → 之后可绑给任意卡。

**预设与条目槽位怎么联动**

- **映射表里存的是文字名字**（左＝MVU 字段名，右＝条目名），不存任何码；
- 原因：映射表跨局复用（存库里、跟卡绑），而条目码属于某一局，存码必然对不上；
- 应用映射表时把「MVU 字段 → 条目名」接起来，条目名落到**当前局**的槽位：
  - 名字命中已有单字母槽 → 直接用该槽；
  - 是新名字 → 占用一个**空闲的单字母槽**，并在该局写入条目定义（默认「可多值」）；
- 单字母槽用满（上限 **50 条**，含内置栏目）后，映射表新增条目会提示「槽位不足，请先清理不用的栏目」；
- **换映射表就是改单字母槽的名字**，不新增、不删除槽位，**不产生字典垃圾**；
- **双字母条目（玩家手动建的）完全不受映射表影响**；
- **MVU 字段名本身不进字典**——它只在读取变量时用于匹配，从不写进快照。

**映射记录的结构与校验**

```json
{ "mvu": "星岁", "candidates": ["年龄", "岁数", "出生年"], "effective": "年龄" }
```

| 字段 | 含义 |
|---|---|
| `mvu` | MVU 字段名（左） |
| `candidates` | **候选**条目名，可多个，**不生效**，仅作自动匹配的备选 |
| `effective` | **当前生效的那一个**，有且只有一个 |

- 候选可以随便存多个；
- **保存时只校验 `effective`**：一个 MVU 字段只有一个生效项，一个条目也只能被一个 MVU 字段的 `effective` 占用；冲突则拒绝并提示是哪两个字段抢同一个条目；
- `effective` 为空 → 该字段视为「未映射」，不会往档案写值。

**保存到人物卡（可选）**

- 用 `updateCardRaw` 以 JSON Pointer 写入卡内扩展区（示意：`extensions.renwu-lengcundang`）；
- 单次操作 ≤200 项、值 ≤2 MB；酒馆**保留原始导入版**，玩家可还原；
- 写入失败（卡只读、被改过导致 `REVISION_CONFLICT`）→ 提示「这张卡无法写入，映射只保存在本机」；
- 打开一张卡时，若卡内已有映射，**优先读取卡内那份**，没有再用条目预设库里的绑定；
- 不需要「打开卡」事件：需要时通过 `getCard`／`getTurn` 现场解析当前卡即可。

### 8.10 对话式修改

侧栏面板内**只有一个对话框**（不保留多会话），玩家可以用自然语言描述要改什么。

**运行方式**：强制使用一个**专属常驻后台成员**（`member`），**不跟随设置页的「自动维护」开关，也不可关闭**。因此即使自动维护设为「关闭」，这个对话框仍然可用。

**执行方式**：

1. 玩家输入 → 交给该成员（带一组工具：查人物、改值、删值、加个人条目、改人物状态）；
2. 模型**先返回改动清单**：谁、哪个条目、动作、原值→新值；
3. 玩家点「应用」才真正写入 → 程序校验 → 落到**当前正在编辑的那份快照**；
4. 模型也可以直接针对**历史快照**提出修改，同样先预览再应用。

**硬约束**：

- MVU 条目的值与名字**在程序层拦截**，模型提出修改会被拒绝并回错误说明；
- 唯一值条目只能覆盖、不能新增第二条；
- 「第 N 条」必须真实存在。

**系统提示词（草案）**

> **身份**：你是「人物冷存档」插件的助手。玩家会用自然语言让你查看或修改本局的人物册。
>
> **数据结构**：组（离场／在场）→ 人物 → 条目 → 值；同一人物可以有多个条目，同一回答下可以有多个值，每条值独立带信度与轮次。
>
> **你能做的动作**：查询人物与条目；新增值；覆盖第 N 条；删除第 N 条；为某人物新增个人条目；在离场／在场之间切换人物状态。
>
> **硬性限制**：MVU 条目不能改名、不能改值；唯一值条目只能有一条值；「第 N 条」必须真实存在，不确定就先查询；不要臆造正文或玩家没说过的信息。
>
> **输出格式**：每次修改前先给**改动清单**，等玩家点「应用」：
>
> | 人物 | 条目 | 动作 | 原值 | 新值 |
> |---|---|---|---|---|
> | 老陈 | 外貌 | 删除第 1 条 | 戴帽子 | — |
> | 老陈 | 外貌 | 新增 | — | 左眼失明 |
>
> 不需要改动时直接说明原因，不要输出空表格。
>
> **写作规则**：每个条目按它自己的提示词写，不把一个条目的内容写到另一个条目；同一信息只写一处，重复用「覆盖」而非「新增」；一条值只说一件事；拿不准就查询或反问。

## 十、后台任务的轮次安排

### 10.1 一轮内的时序

| 时点 | 插件动作 |
|---|---|
| 正文生成前（`turnSection`） | 读人物册做**自动召回**（五道闸＋固定打分＋预算分配）；再把面板上排队的**手动召回**拼进去；两拨盖章一次落盘 |
| 正文写完 | — |
| 结算完成（`onTurnSettled`） | MVU 只兜时间与地点 → 程序记账（`flags.seen`／离场记录／模糊建档清理）→ 子代理：**①判定**（建档·离场·在场）→ 程序建档改状态、从模糊表摘掉 → **②写入**（命题＋指针）→ 校验应用 → **有变化才**存快照 |

主处理放在结算之后，因为需要**结算后的 MVU**。

> **已知限制**：`onTurnSettled` 由「本轮结算完」（`turn-settled`）事件驱动，而该事件只在结算周期真正跑完时发出。玩家把酒馆后台结算全部关闭时，这个回调不会触发，本插件的自动维护也随之不跑——**这是刻意与官方行为对齐**，不做额外兜底（据宿主源码；**未在「关掉全部结算」的实机局验证**）。

### 10.2 写入方式（三档）

> 设置项名称：**写入方式**

| 档 | 说明（设置页直接展示） | 行为 |
|---|---|---|
| **子代理** | 每轮结算后，用一个**DSH 子代理**（每局一个、可 resume）做两件事：**①判定**（建档·离场·在场）**②写入**（更新条目）。正文由我们喂**全文**；可能滞后一轮。 | `onTurnSettled` → 程序数轮次（模糊离场）→ 子代理「判定 → 写入」→ 校验 → 落盘 |
| **跟随后台**（**默认**，**已实现**，[ADR 0094](adr/0094-后台写入接member.md)） | 用 Tavern 的常驻成员（`member`）「档案员」，跟「书记」「润色师」同列。**正文由我们拼进工单**；成员带自己的**固定前缀**（规则＋交卷工具，[ADR 0095](adr/0095-系统提示词拆固定与动态.md)），前缀内容就是面板「提示词」页那份、保存即重挂、下一轮结算生效（[ADR 0096](adr/0096-面板提示词即成员前缀.md)）。**后台异步跑，不阻塞玩家输入**（宿主派发结算回调不 await）。 | `onTurnSettled` → `runTask({ member: 'character-archives' })` → 交卷工具存 payload → 同一套判人+写入校验落盘 |
| **关闭** | 不跑模型判断，只做被动维护。切换时弹窗确认。 | 只保留手动编辑与读取；不自动建档、不自动更新。**MVU 只兜底时间与地点**（人物字段不抄，[ADR 0091](adr/0091-MVU人物字段映射退役.md)） |

**交卷盒在派发任务之前定好**：`runPhase` 在 `runTask` **之前** `beginMemberRun(box)`，`try/finally` 里 `endMemberRun(box)`（超时、中止也收尾）；工具**只接收 `args`**——宿主调插件工具只传这一个参数，第二个永远是 `undefined`——所以交卷目标**不依赖工具调用的第二个参数**。没有活动任务时的提交直接返回 `{ok:false, error}`，不再静默成功（[ADR 0100](adr/0100-后台成员交卷按派发时定的盒子.md)）。调试日志的判定块会带一个「**交卷次数**」：`0`＝模型这一轮压根没调交卷工具；`>0` 却仍然没有动作＝程序侧读错了盒子——现场只有这一个线索能分开这两种情况。

**上一轮还没跑完 → 跳过本轮**：子代理与成员里的任务都是排队的；若上一个仍未结束，**不再往里塞**，记一条提示（[ADR 0028](adr/0028-写入三档.md)）。

**交卷形状三层兜底**（[ADR 0109](adr/0109-交卷形状三层兜底.md)）：模型可能把整份交卷 JSON 当字符串塞进一个自己编的键（`{"parameter":"{…}"}`），解析器只认顶层键，于是两段都读成 0 条——所以三层，缺一层会复发：

1. **schema 列出字段名**：两处交卷工具共用 `SUBMIT_PARAMETERS`，`properties` 里有 `回头测试／建档／改状态／改名／模糊建档／命题／撤回／地点`；`additionalProperties` 保留（多带字段不至于调用失败），**不加 `required`**（「交 `{}`」是合法行为）；
2. **解析前剥壳**：`index.mjs` 的解析入口写 `const combinedPayload = unwrapPayload(rawPayload)`，顶层已认得任何已知键就原样返回，否则逐个字符串值试解析，最多 4 层（认 ```` ```json ```` 围栏与单元素数组包装）；判定与写入共用这一份；
3. **形状不认就退回**：`normalizeSubmission(args)` 在交卷工具入口拦——剥不开的形状**不入盒**，回 `{ok:false, error}` 让模型重交，别再回 `ok` 让模型以为成功了；被退回的载荷记进盒子的 `rejected`，判定阶段调试日志报一条「交卷形状不认，已退回 N 次」——不留的话「交卷次数 0」会被按 ADR 0100 的读法误判成「模型没交」。

调试日志两面都留证：判定块补 `载荷形状` / `载荷`，写入块的 `载荷` 记**剥壳前**的原始形状（剥过壳的会盖住证据）。

**切到「关闭」时的弹窗**：

> 关闭后，插件不会自动判定离场，也不会自动建档或更新条目。  
> 已有档案仍可查看和编辑。  
> 确定关闭吗？

**两个「结算」要分清**

- 本开关只管**我们自己的判断任务**，不影响酒馆的变量结算；
- 只要酒馆结算还在跑，`onTurnSettled` 就能拿到结算后的 MVU；**但它现在只兜底时间与地点**，人物字段不再抄（[ADR 0091](adr/0091-MVU人物字段映射退役.md)）；
- 若玩家把酒馆后台结算也关掉，`onTurnSettled` 不再触发，本插件自动维护整体停止——与官方行为一致，不额外补偿。

### 10.3 唯一落盘点与工作形式

**`onTurnSettled` 是唯一入口，也是唯一落盘点。**

| 环节 | 谁干 | 干什么 |
|---|---|---|
| 每轮结算完成 | `onTurnSettled` | 程序数轮次（连续 N 轮没出现 → 判模糊离场）＋ 记账 ＋ **一次正文扫描同时干三件事**：刷新 `flags.seen`、得出【本轮提到的人】＋状态、得出模糊建档里本轮露脸的人；然后调起模型（子代理 / 成员，看设置） |
| **一次调用**（判定＋写入） | 模型的同一个会话 | 发**合并素材**：判人段（正文全文＋当前 gt＋本轮提到的人及其状态＋模糊建档）＋ 写入段（判人前在场人物的栏目清单，含空栏目；锁住的人跳过不发）→ 返回**一个对象**：判人五块 + `命题` 数组 |
| 返回后 | 插件程序 | 先应用判人（发编号、建档、改状态、写离场记录），再用判人后的档案校验命题：每条动作**四级找命题**（序号→精确→宽松→新建），每条「认知」写成一条指针（「自己」那组只有本人能写、别人最多 3 组）；最后应用 `撤回`（只摘本人指针、零指针即清命题，[ADR 0102](adr/0102-撤回指针.md)）→ 写人物书 + **有变化才**存快照 |

- **判人和写入合并成一次调用**（[ADR 0092](adr/0092-判人与写入合并成一次调用.md)）：后台结算档每轮只能发一次消息，两次 followup 在那里走不通；
- **判人块缺失不挡写入**：同一次返回里各块独立解析，模型只交 `命题` 也能应用；

- 不再使用 `settlementSection` / `settlementTool` 蹭车；
- 全程只有一处写入，不存在抢写与重复快照；
- 常驻成员提示词固定、缓存命中高，能延续上一轮的判断上下文；
- 「每轮一次性 runAgent」费用高、「自建 DSH 子 Agent」复杂度高，均不采用，后者留作以后需要多步推理时的后手。

注意：用成员时必须处理生命周期——删局释放、回退或重新生成时中止或丢弃过期结果。

### 12.2 宿主接口速查（契约要点）

| 接口 | 关键点 |
|---|---|
| `turnSection({name,text,position?})` | `text` 可为函数，收到 `{gameId, turn, input}`（input 是玩家本轮原文）；每轮算一次、随该轮保存、重试沿用；出错或 30 秒跳过该段；单段 ≤ 8000 字 |
| `onTurnSettled(handler)` | 收到 `{gameId,turn,textVersion,greeting,text,rawText,card,variables,settledAt}`；处理函数**不必等完成才返回**；同一 `textVersion` 只通知一次；开场白不触发 |
| `settlementTask({name,title,phase,run})` | `phase` = `before`/`parallel`/`after`；单任务 5 分钟；**下一轮会等它们跑完**；每 `textVersion` 一次；开场白不触发 |
| `runTask({gameId,prompt,tools?,signal?})` | 返回 `{text}`；一次性会话；`tools` ≤ 8 个、一次最多调 16 次；10 分钟超时 |
| `getTurn({gameId,turn})` | 含 `variables`；未结算的最新轮返回 `null` |
| `getTurnState({gameId})` | `{gameId,turn,textVersion,greeting,generating,settling,busy,settled}` |
| `getHistory({gameId,from,to})` | 一次最多 **50 轮**，返回 `[{turn,input,text,rawText}]` |
| `handle(name,handler)` | 参数 ≤ 256 KB，返回 ≤ 4 MB；浏览器侧用 `ctx.tavernUi.callHost` 调 |
| `publishState({gameId,name,data})` | `data` ≤ 256 KB，只存最新一份，**只在内存** |
| `saveTurnData` / `readTurnData` | 每条 ≤ 64 KB；校验 `textVersion`；`readTurnData` 读「该轮及之前**最近一份**」 |
| `saveGameData` / `readGameData` | 整局 ≤ 256 KB；不随回退变、分叉复制、删局清空 |
| `savePluginData` / `readPluginData` | 插件自己的数据 ≤ 256 KB；**跨局、跨设备** |
| `onTimelineChanged(handler)` | 收到 `{gameId,kind,turn?,textVersion?,fromGameId?}`；`kind` = `rollback`/`undo-rollback`/`regenerate`/`edit`/`fork`；通知在变化保存**之后**发出 |
| `onGameRemoved` / `versionSignal` | 删局；版本失效即中止 |

> ✅ **已核实（2026-11-01，直接查源码）**：`member({name,title,system,tools})` 在 `tavern-plugin/lib/plugin-api.js:878`，`job(...)` 在 `:344`；`settlementTask` / `manualTask` 也都支持 `member` 参数。**但官方参考文档 `plugin-api-prompt.md` 里一个字都没写。**
>
> **本项目决定使用 `member`**（见 §10.3 写回架构）：每局一个常驻 Session，带自己的 `system`／`tools` 与提示词缓存；`runTask({ member })` 就是往它投一条消息并排队。这份 `system` 就是面板「提示词」页那份——面板保存即重挂注册，**下一轮结算生效**（[ADR 0096](adr/0096-面板提示词即成员前缀.md)）。
>
> ⚠️ 风险：**官方未文档化 = 不保证**。酒馆升级若改掉这个接口，需要退回「每轮一次性 `runTask`」。决策记录见 [ADR 0015](adr/0015-采用member常驻成员.md)。

## 十三、代码模块清单

`plugin/lib/` 是**纯逻辑**（不 import 酒馆接口、不接触 `ctx`），所以能本地单测。宿主交互只在 `plugin/index.mjs`（宿主侧）与 `plugin/client.js`（浏览器侧）。

**设置一律嵌套读**：`resolveSettings()` 返回的是分组结构，按扁平键读（`settings.cooldownOn`、`mode: settings.writeback`）会静默拿到 `undefined`——2026-11-06 就是因为这个，「调用模型方式」选「关闭」不生效、召回整组设置读的是默认值。读法固定为 `settings.recall?.xxx` / `settings.writeback?.mode`；`tests/settingsWiring.test.mjs` 守着这条，既不许出现扁平读，也不许把嵌套读整段删掉蒙过去。

**浏览器侧 hook 必须排在标签页分支之前**：`ArchivePanel` 里有一串 `if (view === …) return …`，hook（`useState`/`useEffect`/`useMemo`/`useRef`）只要写在它们后面，切标签页时「这次渲染跑了几个 hook」就会变，React 直接抛 `#300 Rendered more hooks than during the previous render`，整个面板崩进错误边界（2026-11-06 踩过一次）。`tests/clientStructure.test.mjs` 用守卫锁住顺序：`useState('archive')`、`useFitHeight()`、`--ca-base` 那段 effect、样式注入都必须在那串分支之前。

## 附录 A　术语表

| 术语 | 一句话解释 |
|---|---|
| **快照** | 某一轮的人物册副本，形状 `{v,t,p,gt,loc,c,pt}`；回退时看的是对应轮次的那一份 |
| **整局数据** | `saveGameData` 里那份，不随回退变、分叉时复制、删局清空 |
| **字典** | 把长文本编号存进 `d[]`／`t[]`，快照里只存下标，省字节 |
| **栏目码** | 单字母（a~z、A~W、Y、Z，**不含大写 X**）＋双字母；一码对应一个栏目 |
| **命题** | 一句"发生过什么"，存 `c`，全局扁平一份——不归属任何人的判断 |
| **指针** | 某个人对某条命题的态度，存 `pt`；一人一命题只有一条 |
| **来源组** | 指针里的一组 `[态度, 来源, 游戏时间?, 约定状态?]` |
| **态度** | 真／假／未定。默认未定；推断类（性格／动机／想法／关系性质／评价）只能未定（[ADR 0104](adr/0104-两类命题的态度.md)） |
| **来源** | 他自己（`''`）／某人（`p7`）／未知来源（`'?'`） |
| **约定状态** | 没完成／完成了／过期了／失败了；模型报，程序**只存不判**（[ADR 0087](adr/0087-约定类命题程序只存不判断.md)） |
| **关键度** | 人物重要程度。**当前未实现**（§六） |
| **主角** | `p0`：名字跟玩家称呼同步、称呼空着就叫「主角」、永远在场、不能删（[ADR 0085](adr/0085-主角入档与召回规则.md)） |
| **离场记录** | 人物离场那一刻的轮次与 `gt`；**在场的人不记**——看状态就知道 |
| **离场（明确）** | 正文明确写了告别／离开／死亡／退场，当轮就判。判者＝模型（要读语义） |
| **模糊离场** | 连续 N 轮没出现（N＝设置项，默认 3）。判者＝**程序**，数够就判，不问模型（[ADR 0030](adr/0030-术语统一与模糊离场归程序.md)） |
| **回头测试** | 建档的前置关：「站在街上喊这个称呼，会只有他一个人回头吗？」（[ADR 0031](adr/0031-回头测试与沉降.md)） |
| **索引词** | 命题上挂的 0～3 个**专名**（2～10 字，必须是内容原文片段），正文碰到它就能想起这条（[ADR 0021](adr/0021-关联词的抽取规则.md)；上限由 [ADR 0107](adr/0107-通用词自动抽与查档限次.md) 从 0～2 放到 0～3） |
| **自动词** | 程序用分词器从命题内容里切出来的通用词（2 字以上、挡掉一张泛词表，不挡名词）。**只参与召回命中判定**（与索引词合并、短路只加一次分）、**不落盘、不写进索引词字段**，面板上只读（[ADR 0107](adr/0107-通用词自动抽与查档限次.md)） |
| **模糊建档** | 还没够格建档、但已经露过脸的人，先记在一张轻名单上；够格再转正（[ADR 0035](adr/0035-候选改名模糊建档.md)） |
| **最后确认轮次 `flags.seen`** | 整局数据里 `{人物编号: 轮次}`，记「他最后一次被提到是第几轮」；模糊离场和冷档都靠它数 gap（[ADR 0039](adr/0039-最后确认轮次seen.md)） |
| **沉降／冷档** | 长期没人提起的人物沉底：面板折叠。**现算不存字段**，默认 20 轮 |
| **命中** | 这一轮正文里出现了该角色的姓名／别名／单字／索引词 |
| **冷却** | **建立／修改／召回**三处盖章，粒度是**指针**（`pt:人物id:命题id`），默认 10 轮（[ADR 0086](adr/0086-召回冷却按指针记.md)） |
| **盖章** | 在冷却表里记一笔 `{lastTurn, until}`。**没真注入给模型就不盖** |
| **必带栏目** | 栏目定义里 `mustRecall: true`：不参与打分与预算竞争，优先强制给 |
| **详细档** | 有态度、来源、游戏时间、约定状态 |
| **简单档** | 只给命题内容 |
| **查认知** | 面板查阅：恒全量、不看冷却、**不盖章**、不进提示词 |
| **召回（手动）** | 面板点名：下一轮注入，按设置里的档位，**真注入了才盖章** |
| **锁定 🔒** | 模型**不许写他**（命题与指针都不给写），但**召回照常** |
| **眼睛 👁** | 可见性。闭眼＝不召回、面板收起 |
| **落盘点** | 唯一写入整局数据的地方（`onTurnSettled`） |
| **单字名** | 姓名为一个字的角色（如"周""溯""枭"）；匹配规则见 §7.10.1（仍有效） |
