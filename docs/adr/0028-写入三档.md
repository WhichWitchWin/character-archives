# 0028 写入三档：子代理（默认）／后台任务（member）／关闭

- **状态**：已采纳（第一版只实现「子代理」和「关闭」）
- **日期**：2026-11-01
- **supersedes**：ADR 0027 的两档（自动维护／关闭）

## 背景

核实过两条平台事实：

1. **Tavern 的 `runTask` 会给任务垫上"最近一轮"的剧情**：取最后两条消息（玩家输入 + 正文），**每条截到末尾 2400 字符**（`index.js:2667-2668`）。所以走 member 这条路，模型**能直接看到本轮正文**，不必再由我们贴一遍——省 token。
2. **插件自己的 member 会话清不掉、也不随剧情压缩**（`timeline: false`）；而 **DSH 子 Agent 可以 resume、可以压缩、可以 dispose**（`narrative-anchor` 就是这么跑的）。

两者各有取舍，用户决定：**拆成两档，第一版只做子代理档**。

## 决定

### 1. 三档

| 档 | 名字 | 模型载挂在哪 | 正文谁提供 |
|---|---|---|---|
| **①（默认）** | **子代理** | DSH `agents.create`／`resume`，每局一个 | **我们自己喂全文** |
| **②** | **后台任务** | Tavern 的 `member` + `runTask` | **成员会话自带**（见下） |
| **③** | **关闭** | 不调模型 | — |

### 2. 后台任务档的正文来源（重要）

走 member 时，Tavern 会把「本轮玩家输入」和「本轮正文」各截**末尾 2400 字符**放进任务上下文，**不需要我们再喂一次**。

⚠️ 前提：**注册成员时不带自定义 `system`**。带了的话 `messages: []`（`index.js:2670`），正文归零。

### 3. 第一版的范围

- **实现**：子代理档（默认）＋ 关闭档；
- **后台任务档写进 ROADMAP**（M4-13），等子代理跑顺了再做。

### 4. 子代理档的做法（照 `narrative-anchor` 验证过的形状）

```
agents.create({ meta: { parentSession: gameId, origin: 'subagent' } })
  → 每轮 agent.followup({ id, role:'user', content:[{type:'text', text: 任务}] })
  → await agent.whenIdle()
  → 删局时 handle.dispose()
```

正文由 `onTurnSettled` 拿全文，塞进任务消息。

## 后果

- **收益**：默认档可控（可压缩、可释放）、正文完整；后台任务档留着做"省 token"的选项。
- **代价**：子代理档要自己喂正文（每轮几千 token）；后台任务档的正文只有**尾部 2400 字**，长正文会缺头。
- **边界**：后台任务档的会话会一直涨且清不掉——这是它排到后续版本的主要原因。
- **被否决的方案**：
  - *只留 member 档*：会话不可控，且正文被截断；
  - *只留子代理档*：多花 token，而"省 token"对部分玩家是刚需。
