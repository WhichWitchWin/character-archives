# ADR 0089 · 召回装配：预算、打分、必带条目、地点

- **日期**：2026-11-04
- **状态**：已定；召回引擎尚未实现（§8 注入抬头格式仍待定）
- **相关**：[ADR 0082](0082-召回改成在场人物认知指针-提案.md)、[ADR 0085](0085-主角入档与召回规则.md)、[ADR 0086](0086-召回冷却按指针记.md)、[ADR 0087](0087-约定类命题程序只存不判断.md)

## 1. 预算

总预算沿用 **3000 字**（现有设置 `recall.budgetChars`）。分三段：

| 段 | 额度 | 规则 |
|---|---|---|
| 主角全量 | **1000 字** | 只在「离场 → 在场」那一刻；超了按打分截断；不参与其余竞争 |
| ★重要人物 | **60%**（约 1800） | 这堆人平分 |
| 普通角色 | 剩下的 | 有就分，没有就不给 |

## 2. 打分（固定常量，不精调）

| 加分项 | 分值 |
|---|---|
| 命题的「关于」是**在场其他人物** | +3 |
| 命题的「关于」是**当前地点** | +2 |
| **索引词**在本轮文本里命中 | +2 |
| 其他（场景③） | +0 |

**同分排序**：最后变动轮新的在前 → 再同 → 命题起始轮新的在前。

## 3. 两档，不要提示档

| 档 | 长相 |
|---|---|
| 详细 | `他怕张三：真（三年五月十二日，他自己确认过）` |
| 简单 | `他怕张三` |

装得下给详细，装不下给简单，简单也装不下就丢。**「提示档」取消**（"还知道 3 件关于他的事"这种不给内容、模型反而更想编）。

## 4. 必带条目

栏目级新增布尔标记 **`mustRecall`（必带召回）**：这类栏目属于**人物属性**（人生目标、身份、性格这类"定义这个人"的东西）。

- 标记了它的命题**不参与打分、不参与竞争**，在预算里**优先强制给**（详细档）。
- 优先级在主角全量之后、★人物之前；如果必带就撑爆预算，**先保必带**，其余按打分装。

## 5. 当前地点怎么来

三路取，**要求拿到的一定是"已存在的地点"**：

1. **MVU 有值** → 直接用它（`snapshot.loc` 的来源）。
2. **MVU 没值** → 程序从本轮正文里抓候选地名。
3. 还缺 → 让**写入阶段**的模型在返回时多报一个「当前地点」（同一次调用里加字段，不需要额外握手；成本只是提示词多一句 + payload 多解析一个字段）。

**校验**：候选地点必须命中**本局的地类索引词**——也就是**这一局**里、已有命题抽出来的「地」类词。**不认全局专名词库**（别的局的地名在这里没有任何意义），也**不认新地名**：没命中就丢弃、当空处理。新地点意味着没人来过、没存过索引词，拿它去匹配召回只会空转。

## 6. 主角回场：程序判断，不用模型额外报

- 检测点：写入阶段应用动作后，主角 `status` 由 `离场(0)` 变 `在场(1)` → 记一个 `flags.playerBack = { turn, gt }`。
- 下一轮召回读到这个标记 → **主角全量注入一次**（1000 字上限）→ 标记清掉。
- 不需要模型报"主角回场了"，状态字段本身就是信号。
- 回退：跟其他 `flags` 一样按轮次回退；同一轮里"离场又回场"只算**最后一次**状态变化。

## 7. 约定类：取消周期提醒

**周期提醒整条取消**（原 ADR 0087 那一节作废）：不再有「在场角色约定提醒轮次」这个设置项，也不做 `(当前轮 − 立约轮) % N` 的轮次比较。

理由：**如果这条约定跟在场的人、跟当前地点都没关系，那就不该被想起来**——常规召回（场景①②）已经覆盖了"该想起来"的全部情况。

## 8. 注入抬头重做

旧抬头「【人物档案参考】+ 本局写作人称」作废，新格式在实现时按新块结构重新定（不在本条展开）。

## 9. 正文模型查档案的工具（`modelQueryTool`）

设置项 `recall.modelQueryTool` **保留并要实现**（原来是个死开关）。给正文模型一个工具，让它能在写正文时**主动点名召回某个角色的指针**：

| 参数 | 内容 |
|---|---|
| 角色 | 姓名或别名（走 `resolvePersonByName`，重名不猜） |
| 档位 | **全量** / **详细** / **简单** |

三档给什么：

| 档 | 给什么 |
|---|---|
| 全量 | 这个角色的**所有指针**（连同命题内容），不看冷却、不看预算 |
| 详细 | 按打分排序，装进"一个人的详细额度"——每条带态度、来源、时间 |
| 简单 | 只有命题内容，一行一条 |

用途：玩家/模型写正文时觉得"这个人应该有更多细节"，就主动拉一次。**全量那一档是玩家显式要求，注入时不看冷却**——但**注入完要盖章**：这批指针全部按 ADR 0086 的「召回盖章」处理（`until = 当前轮 + N`），下一轮常规召回不会重复给。

## 10. 排序算法留给以后

`recall.algorithm` 设置项**已删除**（原来也是死开关，2026-11-04 清掉）：现在的固定打分（+3/+2/+2）是**第一版**。以后要上更复杂的排序算法，再按 [ROADMAP](../ROADMAP.md) P18 重新加设置项。
