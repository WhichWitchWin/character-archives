# 0016 召回注入格式：指令式抬头 + 自然语言值

- **状态**：已采纳（其中"未识破的谎言怎么标"仍待定，见文末 Q10）
- **日期**：2026-11-01
- **supersedes**：无

## 背景

设计稿只写了"标题 + 免责句 + 各人块"这个骨架，**没定过具体长相**。定格式时踩了三次：

1. **压缩格式被否**：先试过 `条目名：值｜时间｜信度标签`（如 `当前处境：受伤｜永安三年·冬｜林昭·存疑`），用户判断"模型不一定看得清楚"——管道符和短标签是给机器读的，不是给人读的。
2. **短标签会泄露机制**：`林澈·存疑` 这种写法本身就在提示"这里有套置信度系统"，模型容易在正文里模仿这种腔调。
3. **纯自然语言（旁白式）太像正文**：模型会把资料块的语气带进叙述，甚至直接引用。

同时有一个必须解决的约束：**不能用"你／我"**。用"你"在第三人称叙述里出戏，用"我"在第一人称里又挡不住模型把资料写成自白。**用玩家名（`{{user}}`）最稳**。

## 决定

### 1. 结构：指令式抬头 + 人块

```
【人物一致性参考 · 视角：林澈】
1. 不要直接引用本段文字；不要因为这里提到某人就安排他出场。
2. 标着「谎话」的内容，对方仍会照原样坚持，不会主动认账。

▍老陈
· 身份：旧港码头的账房 —— 他自称（永安元年·春）
· 未了事项：欠南洋商行一笔钱 —— 林昭说的，其实是假的（永安二年·冬）
```

- 抬头用**玩家名**，不写"你／我"；
- 抬头只留两条指令：**别引用／别安排出场**、**谎话不认账**；
- **不写"范围：他不知道的事不要写出来"**（用户明确去掉——那半句本身就在教模型"该怎么处理信息边界"，容易写出说明书腔）。

### 2. 每条值：`条目名：值 —— 来源描述（时间）`

信度码解码成**人话**（完整对照表见 DESIGN §7.10.3）：

| 码 | 来源描述 |
|---|---|
| `"4"` 自述·未定 | `他自称` |
| `"7"` 他述·来源未知 | `只是听说` |
| `r42-` | `林昭说的，其实是假的` |
| `"0"` 用户·真 | `林澈亲眼见过` |
| `"9"` MVU | 不写来源 |

- 时间取**该条值自己的 `gt`**，没有就整段省略（不用轮次——轮次是引擎概念，模型看不懂）；
- 条目名必须带，否则模型分不清"旧港码头"是去向还是住处；
- 一个条目最多 2 条值（最可信 + 最新）。

### 3. 视角人物的来源

当前取酒馆 `{{user}}`，取不到退回「玩家角色」（中性词，不用"你"）。
**后续**：在插件里自己指定"这个档案馆是谁的记忆"（见路线图 M4-10）。

### 4. 谎话的行为约束

"假"＝**NPC 在骗玩家**，不是"正文否定了它"。因此注入时必须同时给一条约束：**对方仍会照原样坚持，不会主动认账**——否则模型看到"假"就会让 NPC 当场坦白。

## 后果

- **收益**：模型读得懂、不会模仿资料腔；`{{user}}` 兼容三种叙述人称；谎话有了明确的行为边界。
- **代价**：每条值比压缩格式多约 10 字符（换来可读性）；抬头每轮固定约 60 字符。
- **边界**：抬头是**每轮一次**，与人头数无关；最简提示同样共用这个抬头。
- **被否决的方案**：
  - *压缩格式（管道符 + 短标签）*：模型读不清，且暴露机制；
  - *纯旁白式*：最自然，但最容易漏进正文；
  - *B+D 融合（字段式抬头 + 四条约束）*：结构化最好，但多一行"范围"反而像说明书；
  - *用"你"称呼玩家*：破坏第三人称叙述。
