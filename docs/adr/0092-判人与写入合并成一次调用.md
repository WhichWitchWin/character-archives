# ADR 0092 · 判人与写入合并成一次调用

- **日期**：2026-11-05
- **状态**：已定并已实现
- **相关**：[ADR 0028](0028-写入三档.md)（后台任务档）、[ADR 0029](0029-子代理一轮流程.md)（两次 followup）、[ADR 0083](0083-写入流程-命题与指针.md)（写入流程）、[ADR 0063](0063-三段提示词可编辑.md)（提示词模板）

## 背景

原来一轮结算跑**两次**子代理调用（[ADR 0029](0029-子代理一轮流程.md)）：

1. **判人**：`buildJudgePrompt` → 模型交 `{回头测试, 建档, 改状态, 改名, 模糊建档}`；
2. **写入**：`buildWritePrompt` → 模型交 `{命题:[…]}`。

两次调用各带一份完整的系统提示词（约 3500～5000 token），一轮就是两份；往返也是两次。

更要命的是**后台结算档**（[ADR 0028](0028-写入三档.md) 的 member 档）：正文生成和结算共用**一次**模型调用，每轮只能发一次消息、收一次返回。两次 followup 的旧链路在那里**根本走不通**。

## 决定

**判人和写入合并成一次调用。**

### 素材

一次发出去，前半判人段、后半写入段（`lib/followup.js` 的 `buildCombinedPrompt`，内部复用 `buildJudgePrompt` + `buildWritePrompt`）：

```
【判定】
【当前游戏内时间】…
【本轮提到的人】…
【模糊建档】…
【本轮正文】
…

【写入】
【老陈 · 在场】
  （这些栏目还空着：…）
```

写入段的在场名单用**判人前**的状态——刚建档的人素材里没有，但模型自己知道刚建了谁，可以直接在 `命题` 里写他。

### 输出

**一个对象**，判人五块 + `命题` 数组：

```json
{
  "回头测试": { "通过": [], "不通过": [] },
  "建档": [], "改状态": [], "改名": [], "模糊建档": [],
  "命题": [ { "关于": "…", "栏目": "…", "值": "…", "认知": [] } ]
}
```

### 程序处理顺序

1. 解析 → 过滤已删除的人 → 校验并应用**判人动作**（建档/改状态/改名/模糊建档）；
2. 用**判人后**的档案算在场名单（含刚建档的人）；
3. 用同一次返回的 `命题` 校验并应用写入（`allowedIds = 判人后的在场名单`）。

## 为什么

- **省一份系统提示词 + 一次往返**：一轮从 2 次调用降到 1 次；
- **后台结算档必须这样**：member 档每轮只有一次调用机会；
- **减少"判了没写"的不一致**：老陈曾经连续 5 轮只进「通过」名单、没进 `建档`，写入阶段又写他的命题被拒——合并后模型在同一次输出里能看见自己判了谁，`命题` 里可以直接引用刚建的人。

## 代价与边界

- **写入素材不含刚建档的人**：素材在判人前构建，新档栏目本来就是空的，模型自己写即可；
- **单次输出更长**：模型（尤其 flash）更容易漏块，所以提示词里写死「一次交一个对象」「先判人、再写命题」；
- **旧函数保留**：`buildJudgePrompt` / `buildWritePrompt` 不删，但**只给单元测试用**（面板手动建档走 `/create`，不经过它们）；生产链路只走 `buildCombinedPrompt`；
- **判人改了已有的人时，写入段还是旧样子**：素材按判人前渲染，模型这一轮把某人「改名」或「改状态→离场」，写入段里仍是旧名／「在场」；模型照素材写 `关于: 旧名` 会被 `resolvePerson` 判「不在档案里」、离场者不给建指针——**安全失败（进 `bad`），不崩不脏写**；
- **调试日志**：合并后一次调用同时产出判人/写入日志，`/debug` 里按 `kind` 区分（judge / write / reject）。

## 实现落点

- `plugin/lib/followup.js`：新增 `buildCombinedPrompt`；
- `plugin/index.mjs`：`runWriteback` 只调一次 `runPhase`，`judgePayload` 与 `writePayload` 共用同一个返回；
- `plugin/assets/system-prompt.txt`：输出段改成「一次交一个对象」；
- `tests/followup.test.mjs` / `tests/hostWiring.test.mjs` / `tests/promptTemplates.test.mjs`：新增合并素材、只调一次 `runPhase`、输出形状的守卫测试。
