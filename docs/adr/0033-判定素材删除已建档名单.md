# 0033 判定素材删除「已建档」名单：去重是程序的事

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0032](0032-判定素材带状态.md) 的「决定 3：【已建档】压成一行保留」

## 背景

[ADR 0032](0032-判定素材带状态.md) 决定 3 保留了【已建档】一行：

```text
【已建档】老陈、周、林昭、独眼陈……（共 47 人）
```

理由是"防止模型把老人当新人重复建档"。

但这个理由站不住：

### 1. 去重本来就是程序的活

0032 决定 1 已经让**程序扫本轮正文、匹配已建档人物**了。既然程序手里有全档、也有匹配能力，它报上来的"建档"自己就能核对：

- 名字已在档里 → 丢弃或转成追加别名
- 不在 → 正常建档

**模型拿到名单也帮不上忙，反而多一道它做不好的判断。**

### 2. 名单越长，模型越会乱认人

正文里冒出"王掌柜"，模型瞟一眼 200 人的名单看到"王五"，很容易下结论"是同一人"，直接报成改状态。**给的名字越多，乱认的概率越高**——这是给名单**新增**的风险，不是收益。

### 3. 成本随档案规模线性增长

一局几百轮，档案越攒越多，这一行每轮都要重发一遍。而它省下的只是"可能少报一次重复"——一次都不值。

## 决定

### 1. 判定素材删掉【已建档】整段

现在【判定】只有：当前 gt ／【本轮提到的人】＋状态 ／【候选人物】＋轮次 ／ 正文全文。

### 2. 提示词删掉那句「别名算同一个人」

> ~~· 别名算同一个人（"陈账房"就是老陈，不要当成新人重复报）。~~

**这句在模型这里是空的**：正文只写"陈账房"，它凭什么叫它知道档里有"老陈"？就算给了名单，它也只能猜。

用户的原话是："不是模型的事你说给他干什么。" 删掉，不留替代句——**不去提它，模型才不会去想它**。

### 3. 去重责任归程序

模型**只如实报名字**；程序拿名字去比对全档（精确 ＋ 已收录别名），重复的丢掉或转成追加别名。

### 4. 别名模糊匹配延后到 v0.2

程序现在只能做**精确匹配 ＋ 已收录别名**。像「陈账房」＝「老陈」这种需要猜的，留到 [ROADMAP](../ROADMAP.md) **M4-14「别名匹配与人物合并」**：同姓＋职业、老／小／阿前缀、去姓简称，匹配不上就在面板提示疑似同一人、让玩家一键合并。

## 一条能推广的尺子

> **素材里只放「模型自己算不出来的东西」。**

| 素材 | 模型算得出来吗 | 结论 |
|---|---|---|
| 正文全文 | ❌ | 留 |
| 【本轮提到的人】＋状态 | ❌ 跨轮状态它不知道 | 留 |
| 【候选人物】＋出现轮数 | ❌ 跨轮计数它不知道 | 留 |
| 【已建档】全名单 | ✅ 程序自己比对就行 | **删** |
| 当前 gt | ❌ | 留 |

## 后果

- **收益**：判定素材更短；模型不再被诱导乱认人；成本不再随档案规模上涨。
- **代价**：程序匹配不到的别名（"陈账房"）会**多出一个档**。玩家能看到两个相似的人，手动合并。真正的解法在 M4-14。
- **边界**：模型**完全不做**"这两个名字是不是同一个人"的判断。误合并的责任不再落在它身上。

## 被否决的方案

- **保留「共 47 人」这个总数**：对模型毫无用处，纯占字数。
- **保留名单但截断到最近 N 个**：截断更糟——随机漏掉，模型以为"不在名单里就是新人"。
- **让模型自己判断别名**：它没有判据（不知道档里有什么），只会瞎猜；猜错比不猜更麻烦。
- **在提示词里写"去重不是你的事"**：多余的提醒本身就是干扰。直接不提。

## 待定

- M4-14 的匹配规则细节（哪些算同一人、合并时条目冲突怎么取）。
- 程序侧"疑似同一人"的判定阈值：同姓＋同职业就提示，还是要求更强的证据？误提示太多会变成噪音。
