# 0075 模糊建档候选按「多久没露面」自动清理

- **状态**：有效
- **日期**：2026-11-03
- **相关**：[ADR 0036](0036-模糊建档表的存储与扫描.md)、[ADR 0074](0074-模糊建档候选可见.md)

## 背景

模糊建档表 `state.flags.draft` 记着"露过脸、但还不够格建档"的人。它**只进不出**：除了「转正建档」和「玩家手动移出」，没有第三种出口。

ADR 0036 与 ADR 0074 都把这件事留在「待定／过期多久本次不定」。现在它有了实际代价：

1. **每轮都要全表扫正文**——`scanDraft` 拿**每个名字**去正文里跑一次 `matchText`，300 个候选就是 300 次全文匹配；
2. **面板上越堆越长**，玩家看到的多数是早就不出场的人。

> 顺带排除一个误判：**分词用户词典不累积**。`syncUserWords` 每轮整体重建（`setExtraWords` 内部先 `extra = new Map()`），上一轮摘掉的名字下一轮就没了；一个不再出现的名字留在词典里也影响不了别处。真正随表变大的是上面第 1 条。

## 决定

### 1. 值的含义改了，但不加字段

| | 以前 | 现在 |
|---|---|---|
| 值 | **入表轮次** | **最后一次露面的轮次** |

入表时＝当前轮；之后每轮正文命中就刷成当前轮。一个整数同时回答两件事：

- 面板要显示的「已经几轮没露面」＝ `now − 值`；
- 该不该清掉＝ `now − 值 ≥ 上限`。

不另开 `lastSeen` 字段，是因为这张表要尽量小（整局数据 256 KB），一个整数够用。原「入表轮次」的唯一用途是面板显示"第 N 轮记的"，信息量本来就不高，换掉不心疼。

### 2. 清理规则

**连续 N 轮正文里都没提到他 → 移出候选表**。

- 设置项：`draft.maxIdleTurns`，**全局级**，默认 **5**，范围 **1～10**；
- 最小 1：设成 0 会把刚入表的人当轮就删掉，那不是清理是失控；
- 非法值（`NaN`）回落默认 5；
- **轮次不是整数的脏数据一律不删**——清理不该误伤来历不明的东西。

### 3. 时机与顺序

放在**判定阶段之后、写入阶段之前**，紧跟 `pruneDraft`：

```
判定 → 建档/加候选 → pruneDraft（刚转正的人摘掉）→ expireDraft（太久没露面的清掉）→ 写值阶段
```

顺序不能反：先摘掉刚转正的人，再判过期。判定阶段整个失败也照样清理——**露没露面是程序算的，跟模型无关**。

### 4. 面板语义跟着变

候选行从「第 37 轮记的」改成「第 37 轮露面，已 2 轮没见」。

## 后果

- **收益**：这张表终于有出口了。稳定状态下表的大小≈"最近 N 轮里露过面、但还没够格的人"，不再无限增长。
- **代价**：一个**偶尔才露一次面**的重要人物会被清掉。补救途径有两条——模型下次再报「模糊建档」，或者玩家在面板手动加回来。
- **代价**：升级那一刻，老数据里的"入表轮次"会被当成"最后露面轮次"。结果是一批早就该清的条目被立刻清掉，这正是我们想要的效果，无需迁移脚本。

## 待定

- 玩家**手动**加进候选的人要不要豁免清理？（现在：不豁免，跟着一起过期）
- 被清掉的名字要不要留一份"曾经考虑过"的记录，免得下次又从头判一遍？
