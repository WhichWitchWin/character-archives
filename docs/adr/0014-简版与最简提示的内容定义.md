# 0014 简版与最简提示的内容定义

- **状态**：已采纳
- **日期**：2026-11-01
- **supersedes**：无（补齐设计稿 §7.3／§7.10 未定义的部分）

## 背景

三处窟窿，都是实现时才发现的：

1. **「最简提示」从来没有内容定义**。设计稿 §7.10 只写「0.30～0.50 → 最简提示或进候选」，没说提示长什么样；`compose.js` 只有 `brief` / `full` 两档，**提示这一档根本发不出来**。而单字命中（0.6 分）按规定最高就到这一档，等于单字的出口是堵死的。
2. **MVU 窗口 30 字符偏小**。一个稍长的值就把整段挤满，剩下的值全被截断，简版经常短得没有信息量。
3. **预算数字三处不一致**：设计稿 §7.3 写「默认 2000 字」，临时规则表写「上限 3000，可调 500～6000」，代码默认 3000。

## 决定

### 1. MVU 窗口 30 → 50 字符

仍然「按值从短到长填，装不下就截断」。

### 2. 三档共用同一个「身份层」

| 层 | 取什么 | 规则 |
|---|---|---|
| ① 唯一值条目 | 勾选了才有 | 必带，不参与排序 |
| ② MVU 值 | 信度位 `"9"` | 50 字符窗口，从短到长填 |

实现上抽成一个函数（`brief.js` 的 `pickIdentity`），简版和提示**永远不会漂移**。

### 3. 最简提示 = 身份层 + 离场时间

- 离场时间优先用 `anchors` 记的最后在场轮的 `gt`；没有就退回「离场第 N 轮」；都没有就不带；
- **不发任何剧情条目**——只告诉正文模型"有这么个人、什么时候走的"，要不要理会它自己判断。

### 4. 简版 = 身份层 + ③ + ④ + 行尾「第 N 轮」

③④ 的规则不变（来源必须在场、④ 与 ③ 不同源且随机）。全量 = 完整人物书。

### 5. 预算口径统一

**默认 3000 字符，可调 500～6000**。一人简版约 **200 字符**；一轮 10 人 ≈ 2000 字符，其余用于升级全量；调到 6000 时约 4000 可用于升级。

## 后果

- **收益**：提示档有了定义、能落地；单字命中终于有出口；两档共用身份层不会各写一套；预算只有一个口径。
- **代价**：MVU 窗口变大 → 单人简版变长（约 200 字符）→ 同样预算下能装的人少了一些。
- **边界**：提示**不带剧情条目**，所以它有没有用完全取决于玩家勾了哪些条目。若一个都没勾，提示为空，这一段不加进请求。
- **被否决的方案**：
  - *提示带上"凭哪个词命中"*：会诱导正文模型主动安排角色回场，和免责句「不要主动安排他们回场」直接打架；
  - *提示只给名字*：最省（2 字符），但丢掉最有用的一条信息——离开了多久；
  - *MVU 窗口保持 30*：稍长就截断，提示经常是空的，等于白做。
