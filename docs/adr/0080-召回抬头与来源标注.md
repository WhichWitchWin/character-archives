# 0080 召回抬头说清「这是什么」，来源标注不再写「亲眼见过」

- **状态**：有效
- **日期**：2026-11-03
- **相关**：[ADR 0019](0019-信度拆成两维.md)、[ADR 0023](0023-值级动作集与输出格式.md)、[ADR 0055](0055-身份设置按卡存.md)

## 背景

召回注入的那段文本，抬头原来是：

```
【人物一致性参考 · 视角：第二人称】
```

三个毛病：

1. **提示词里从没解释过它是什么。** 「人物一致性参考」只出现在渲染代码和可编辑模板里，系统提示词一次都没提。模型看到这行只能自己猜。
2. **「视角」和「写作人称」混为一谈。** 「视角」原本指的是**人**（设计稿的例子是 `视角：林澈`，意思是"这些档案是从林澈眼里记下来的"），所以下面才会写「林澈亲眼见过」。改造时把「写作人称」（第一/二/三人称）塞进了同一个变量，于是渲染出 **「第二人称亲眼见过」** 这种病句——「第二人称」不是一个人。
3. **「亲眼见过」太窄。** 主角可能是在衙门**查档案**确认的、或者**亲耳听到**的，不是用眼睛看见的。提示词里定义的「用户来源」本来就写着"亲眼见到／亲耳听到"，标注却只写"看见"，两边对不上。

## 决定

### 1. 抬头说清这是什么，人称单独一行

```
【人物档案参考】
本局写作人称：第二人称
当前：永安三年·冬 · 临安·旧港

▍老陈
· 当前处境：在旧港码头养伤 —— 主角确认过
```

- 抬头名从「人物一致性参考」改成「**人物档案参考**」——直说它是资料，不是剧情。
- 「本局写作人称：X」告诉模型正文里的「你／我」指谁。
- **不再写主角名**：系统提示词里已经有「主角＝{{PLAYER}}」，召回里重复一遍没意义。

### 2. 来源标注不写人称代词

| 码 | 以前 | 现在 |
|---|---|---|
| 0 | 第二人称亲眼见过 | **主角确认过** |
| 1 | 第二人称记不清了 | **主角记不清** |
| 2 | 第二人称知道这是假的 | **主角知道是假的** |

「确认过」涵盖看、听、查、验——凡是主角亲自核实过的都算，不预设用什么方式。3～8（自述／他述）本来就不带主语，不动。

### 3. 系统提示词加一段解释

在「本局视角」那一行后面加：

> 你可能会收到一段「人物档案参考」——那是这局**已建档人物的资料**，用来让你写正文时保持人物前后一致，**不是剧情本身**。抬头里的「本局写作人称」告诉你正文是第几人称；每条值后面那截（「—— 主角确认过／他自称／只是听说」）表示这条信息是**怎么来的**。

### 4. 证据仍然不记

「主角去衙门查户口发现是李四」这件事**不会被单独记下来**——沿用 ADR 0023 的取舍：真值只登结论（未定 → 假），不登证据。当时在 Q14「是否加证据字段」里定的是初版不加。

## 后果

- **收益**：模型终于知道那段是什么、该拿它干什么。
- **收益**：召回正文不再出现「第二人称亲眼见过」这种病句。
- **收益**：「主角确认过」能覆盖查证、听来的，不会误导模型"必须用眼睛看见"。
- **代价**：召回抬头里不再有主角名。第三人称卡如果要靠召回确认主角叫什么，得回头看系统提示词（那里有）。

## 被否决的方案

- **`viewpoint` 传「我／你／称呼」**（第一人称→我、第二人称→你、第三人称→称呼）：治了病句，但没治"提示词没解释"和"亲眼见过太窄"这两个根；而且「视角：你」照样看不懂是什么。已放弃，`viewpointOf` 这个函数也随之撤掉。
- **抬头写「视角：第二人称」**：等于承认"视角"就是人称，下面「亲眼见过」的主语没了着落。

## 待定

- 信度码 3～8 的措辞（「他亲口说的，可信」／「听人说的，后来证实了」）要不要也统一成"谁说的 + 可信度"两段式？现在够用，没动。
