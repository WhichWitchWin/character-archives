# 0069 模型交回的 JSON 一律过输入限制；单字名标出来

- **状态**：有效
- **日期**：2026-11-03
- **相关**：[ADR 0061](0061-内部码不进模型.md)、[ADR 0068](0068-栏目名宽容匹配.md)、[ADR 0060](0060-称谓表退役改用分词.md)

## 背景

模型（或玩家）可能报出带引号、括号、反斜杠、控制字符的内容。这些东西：

- 拼进 JSON 就坏；
- 拼进逗号分隔的别名存储就错位；
- 塞进提示词就破坏结构；
- 而且**静默出问题**——值写不进去、面板显示错乱、下次读不出来，只能靠猜。

## 决定

### 1. 白名单，而不是黑名单

黑名单永远列不全（ASCII 有一百多个符号，中文标点又是一堆）。改成**白名单**：不在白名单里的一律拒。

**允许**（除汉字/字母/数字之外）：

| 符号 | 为什么留 |
|---|---|
| `·` | 名字里的间隔号（阿·卡、瓦西里·普希金） |
| `-` | 名字里的连字符（陈-九、Anne-Marie） |
| 空格 / 全角空格 | 「张 三」这种排版 |
| `（ ） 《 》` | 全角括号——**只允许成对的全角括号**，中文日常用法 |
| `， 。 、 ： ； ！ ？ ～` | 全角标点——中文日常用法 |

**全部拒绝**：所有半角标点（英文的 `, . ! ? ; : " ' ( ) [ ] { } < > / \ | ~ @ # $ % ^ * + = _ \``）和所有控制字符（换行、制表符、NUL…）。

### 2. 限制哪些字段

| 字段 | 上限 | 备注 |
|---|---|---|
| 姓名 | 24 字 | 建档、模糊建档 |
| 别名 | 24 字 | 每个别名单独查 |
| 人物（引用） | 24 字 | 改状态时引用的名字 |
| 栏目名 | 24 字 | 模型报上来的栏目名本身 |
| **值** | 30 字 | 原有上限不变 |
| 来源者 | 24 字 | |
| 索引词 | 10 字 | 另有"必须在值里原样出现"的子串校验兜底 |

### 3. 与「栏目名宽容」的关系（不冲突）

| | 管什么 | 规则 |
|---|---|---|
| ADR 0068 | **是哪一栏** | 原样或归一化后相同即可 |
| ADR 0069 | **字符合不合法** | 白名单 |

顺序：**先过字符限制，再查是不是某一栏**。所以「身份 / 职业」（多个空格）能认，「身份/职业」（带斜杠）会被拒——斜杠不在白名单。

### 4. 单字名标出来给玩家看

**单字名（景、周、张）可能召不回来**：正文里「景」常是「景公子」的一部分，分词切不走，词边界判不准。

面板上给这类人物加一个 **「单字名」** 标记（橙色），鼠标悬停说明原因：**给他加个两字以上的别名就好**。

这是提示，不是禁止——单字名能不能用，最终看正文里怎么叫他。

## 后果

- **收益**：模型报任何怪东西都被挡在门外，且**报错说得出是哪个字符**（不是"不合法"）。
- **代价**：模型偶尔报个带英文标点的值（比如「陈-九」用成「陈_九」）会被拒——下一轮它会改。
- **边界**：只管**字符**。值讲不讲得清、名字是不是泛称，那是别的关卡管（ADR 0062／0067）。

## 待定

- 要不要把这个限制也用在**玩家手动编辑**的路径上？（面板手动建档／改值现在**不**查字符——那是玩家自己的输入，界面上也难做提示。）
