# 0038 锁的写入边界：改状态不算写入、锁住的人不进写入素材

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：无（补齐 [ADR 0037](0037-锁与眼睛解耦.md) 留下的两条待定）

## 背景

[ADR 0037](0037-锁与眼睛解耦.md) 把「🔒 锁」定成"只管写入"，但留下两个没说清的问题：

1. **「改状态」算不算写入？**（锁住的人还能不能被改成离场／在场）
2. **锁住的人还要不要出现在【写入】素材里？**（列了他的栏目清单，模型又不能改）

两条都直接影响实现，不定就会各写各的。

## 决定

### 1. 改状态**不算**写入

锁住的人，**照样**能被模糊离场／明确离场／回场改状态。

**理由**：锁防的是**档案内容被瞎改**（值被乱写），状态是**剧情事实**，应该跟着正文走。

如果算写入，后果很荒谬：

```
一个人被锁上 → 状态永远冻在「在场」
           → 在场人物不召回
           → 他这辈子再也不会被注入正文
           → 锁一次 = 这个人从剧情里消失
```

而玩家锁他的本意只是"别改我写好的那些内容"。

### 2. 锁住的人**不进【写入】素材**

判定（第一次 followup）**照常发他**——不改状态就需要它；但写入（第二次 followup）**不列他的栏目清单**。

**理由**：列了他也不能改。给他几十行栏目和值，换回来必然是一串被丢弃的动作，纯烧 token。

## 后果

- **收益**：锁住的人仍然"活着"——状态照常跟着剧情走，只是内容不被改动。
- **收益**：写入素材更短，锁得越多省得越多。
- **代价**：玩家要理解"锁上 ≠ 冻结"，面板上得说清（`锁` 的 tooltip 写明只挡内容）。
- **边界**：锁住的人如果本轮改状态了，第一次 followup 会看到他，第二次看不到——两次素材里的人数不一样，**属正常**，别当 bug。

## 被否决的方案

- **改状态也算写入**：等于锁一次就把人从剧情里注销，和玩家的本意相反。
- **锁住的人两次素材都不发**：那他就永远判不了离场／回场，同上面的问题。
- **锁住的人也照发写入素材**：白烧 token，还会产生一堆注定被丢弃的动作，日志变吵。

## 待定

- 无。条目锁／值锁的同类问题（改状态不受影响、不进写入素材）等 M5-6 一起定。
