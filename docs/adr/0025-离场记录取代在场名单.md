# 0025 用「离场记录」取代在场名单；轮次绝不注入

- **状态**：已采纳
- **日期**：2026-11-01
- **supersedes**：ADR 0014 里「离场时间优先用 `anchors`、没有就退回「离场第 N 轮」」这条；以及设计稿里以 `anchors` 作为"最后在场轮／离场时间"来源的写法（ADR 0005 早就把 `anchors` 标为临时结构，本 ADR 是执行那次约定）

## 背景

原来有一张**滚动的在场名单 `anchors`**（`{人物编号: {turn, gt}}`），记每个人最后在场是哪轮、当时的游戏内时间。

建档提前（ADR 0024）之后，这张表**一半的用途没了**：

- "谁在场"——每个在档的人自己就带状态（`0`~`3`），看状态即可，不需要外挂名单。

但"离场时间"仍然要精确。**不能用"最新条目的 `gt`"代替**，用户点出了一个真实场景：

> 老陈三年前就走了。这轮正文有人提到他（一条传言），给他更新了一条带今天 `gt` 的条目。
> 若拿"最新条目"当离场时间 → 会显示成「离场于今天」。**错的。**

## 决定

### 1. 去掉 `anchors`，换成「离场记录」

```js
flags.left = { p7: { turn: 12, gt: '永安三年·冬' } }
```

- **只在状态从"在场"变成"离场"时写一条**；
- **在场的人不记**——看状态就知道；
- 玩家手动改状态时，同样写这条记录。

### 2. 注入里凡是时间，**只用 `gt`**

| 情况 | 处理 |
|---|---|
| 有 `gt` | 正常写：「离场于永安三年·冬」 |
| **没有 `gt`** | **整段省略**（不写"离场第 N 轮"） |

### 3. 轮次只供插件内部用，**绝不发给模型**

轮次是引擎概念，正文模型看不懂，写进去还可能被它抄进剧情（"第17轮"出现在小说里就出戏）。

内部用途：快照定位、冷却、归档缓冲、回退重算、排序。

## 后果

- **收益**：少一张滚动表（存储更小）；"离场时间"语义准确（真的是他走的那一刻）；不会把引擎概念泄漏给模型。
- **代价**：状态切换必须可靠——1→0 那一刻没捕获到，离场记录就缺（缺了就省略那段，不报错）。
- **边界**：回退到"离场之前"时，这条记录要清掉（写进 §3.6 的回退表）。
- **被否决的方案**：
  - *保留 `anchors`*：建档提前后它只剩"离场时间"一个用途，为这点功能养一张滚动表不划算；
  - *用最新条目的 `gt` 当离场时间*：会被"提到他的传言"带偏（本 ADR 的核心反例）；
  - *没有 `gt` 时退回轮次*：模型读不懂，还会污染文风。

## 待定

无。
