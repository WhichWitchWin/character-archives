# ADR 0109 交卷形状三层兜底：补 schema、解析前剥壳、形状不认就退回

- **日期**：2026-11-13
- **状态**：已定并已实现（未在真实故障数据上回归；2026-11-14 用户真机试用反馈「暂时没问题」，属于「未复现问题」，不等于逐项验过——剥壳分支与「退回重交」分支未单独确认）
- **相关**：[ADR 0092](0092-判人与写入合并成一次调用.md)（判人与写入合并一次调用，所以一层壳同时打死两段）、[ADR 0100](0100-后台成员交卷按派发时定的盒子.md)（「工具回 ok 却空转」上一次的同类教训）

## 背景

2026-11-12 22:28 之后的每一轮（`session-bdfc62e8` 的 T54–T77，共 24 次触发）：**人能建、内容一个字都写不进去**。调试面板的表现是：

```
判定阶段返回 0 条动作｜交卷次数: 1
写入阶段返回 0 条值动作
快照 {"p":[…4 个人…],"c":[],"pt":[]}     ← 人有了，命题与指针全空
```

同一局的 `debugLog` 里，写入阶段的 `载荷` 字段每一轮都是同一形状：

```json
{"parameter":"{\n  \"命题\": [ … ]"}
```

而 11-12 之前正常那局（`session-a3b1df77` T49）的载荷是扁平的 `{"回头测试":{…},"建档":[…`，解析出 7 条动作。另一局（`session-d73ef44e` T2）里，同一个宿主的同一套代码，外层键变成了 `parent` + `https`，内容在第二个字符串里。

## 根因

1. **交卷工具的 schema 里 `properties` 是空的**（`{type:'object', additionalProperties:true}`，子代理档与后台成员档两处都一样）。模型手里一个字段名都没有，只能自己编一个键把整份 JSON 装成字符串；
2. **解析器只认顶层键**（`lib/payload.js` 的 `parseJudgePayload` / `parseWritePayloadBundle`），于是被包过的载荷两段都读成空；
3. **交卷工具的 `execute` 不看内容**，无条件合并进交卷盒并回 `{ok:true}`——模型以为交成功了，下一轮继续同样形状。

包装键名换局就变（`parameter` → `parent`+`https`），说明这是**模型侧的自造行为**，不是宿主统一包法。所以只改提示词不解决问题：换模型／换 provider 会以另一种形状复现。

## 决定

三层，缺一层都会复发：

1. **解析前剥壳（兜底，必需）**：`lib/payload.js` 新增 `unwrapPayload(payload)`——顶层已经认得任何已知键就**原样返回**（绝不误伤正常交卷），否则逐个字符串值试解析，最多剥 4 层；顺带认 ```` ```json ```` 围栏与单元素数组包装。接入点只有一处：`index.mjs` 解析入口 `const combinedPayload = unwrapPayload(rawPayload)`，判定与写入共用这一份，所以写一段就够。
2. **schema 补 `properties`（从源头少产生壳）**：两处 schema 抽成 `SUBMIT_PARAMETERS` 常量，列出七个字段名 + `地点`；`additionalProperties` 保留（模型多带字段时不至于整次调用失败），**不加 `required`**——「没有要做的就交 `{}`」是合法行为。
3. **形状不认就退回（让模型自纠）**：`normalizeSubmission(args)` 是两处交卷工具共用的守卫，认不得的形状**不入盒**、回 `{ok:false, error:SUBMIT_SHAPE_ERROR}`（错误话里写清「顶层就是那些字段、别包成字符串」）。被退回的载荷单独记进盒子的 `rejected`（不算「交过」），判定阶段的调试日志再报一条 warn——不然「交卷次数 0」会被按 ADR 0100 的读法误判成「模型压根没交」，等于把「看不见」从解析层搬到工具层。

另外把**判定阶段**的调试日志补上 `载荷形状` 与 `载荷`（原来只有解析后的动作数）——判定阶段是这次唯一看不见模型交了什么的地方，拖了 24 轮才发现就是因为它。写入阶段的 `载荷` 改为记**解析前的原始形状**，剥过壳的形状会盖住证据。

## 为什么这样定

- **剥壳优先、退回兜底**：先剥壳，能剥开的就当正常交卷（不打断模型节奏）；退回只对付剥不开的怪形状。顺序反了会让顽固包装的模型一直空轮。
- **「主动交空」不许误判成故障**：`{}` 和 `{"parameter":"{}"}` 剥完都是空对象，语义正确，必须放行。
- **顶层数组退回**：`parseJudgePayload` 的老形状认数组，但交卷盒只收对象；放进去等于静默丢内容，所以交给「退回」处理，让模型重交成对象。
- **剥壳不放在 `memberBox.submitMemberPayload` 里**：原始形状要留到解析层，`/debug` 才看得出模型套了壳。

## 代价与边界

- **本机没能在真实数据上回归**：出故障那两局（`session-bdfc62e8` / `session-d73ef44e`）不在本机的插件数据目录里（本机 `games/` 最新是 11-06 的开发局），所以「真实载荷剥完能读出命题」这条**未在真数据上验证**；已用 8 条形状用例（含按 `debugLog` 记录复刻的 T77 前缀形状）覆盖。
- **已空的 24 轮不补**：插件只向前写，历史那几轮要补只能回退重跑。
- **只剥「整份对象被包成字符串」这一种壳**：`{parameter:"{…}"}`、`{parent:"{}",https:"{…}"}`、``` 围栏、单元素数组包装都认（最多 4 层）；XML 标签包裹等其它形状没有实例，未处理（剥不开会走「退回」分支，不会静默）。
- **已知仍会静默丢内容的三种形状（评审确认，本次不做）**：① **顶层已含已知键时一律原样返回**——`{命题:[B], parameter:"{命题:[A]}"}` 会丢掉壳里的 A（`unwrapPayload` 不猜哪份为准，见 ADR 里「绝不误伤正常交卷」的取舍）；② **值本身被字符串化**——`{"命题":"\"[{…}]\""}`（只有值被转成字符串）仍是 0 条命题、回 ok，属未覆盖形状；③ **同键分两次交**——同一轮两次 `{命题:[A]}` 与 `{命题:[B]}` 走浅合并，结果是 `{命题:[B]}`（ADR 0100 的「后交不覆盖先交」只对不同键成立），这两条都在同一条「静默丢内容」链上，要修得改合并语义（逐份剥壳后再按 key 拼接），单独一次改。
- **系统提示词没动**：`assets/system-prompt.txt` 的「六、输出」示例本来就是扁平对象，方向没错；这次靠 schema + 剥壳 + 退回解决，避免改生成物。
- **解析层仍兼容顶层数组，入口守卫不再收**：`parseJudgePayload` 认老形状的动作数组，但交卷盒只存对象，所以 `normalizeSubmission` 一律退回——放着不管等于静默丢内容。

## 守卫

- `tests/payloadUnwrap.test.mjs`：剥壳的形状用例（含 4 层上限）+ `acceptShape` / `normalizeSubmission` 的放行与退回；
- `tests/memberBox.test.mjs`：套壳载荷照收（原样留痕）、怪形状不入盒且报错、**退回单独留痕**（`rejected`，与 `submissions` 分开）、顶层数组退回；
- `tests/hostWiring.test.mjs`：「两处 schema 都用带 `properties` 的常量（含 `地点`），且没加 `required`」「两处 `execute` 都过形状守卫」「退回记录要一路带到 `phase.rejected` 并落进判定日志」「解析前剥壳且判定阶段留痕」。
