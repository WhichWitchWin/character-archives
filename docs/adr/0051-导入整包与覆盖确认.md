# 0051 导入：整包导入、默认不覆盖、攒到下一轮落盘

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0050](0050-导出必须带预设.md) 的「待定：导入怎么做」那一条

## 背景

导出做好了，导入还没有。ADR 0050 留了两个问题：

1. 导入时的版本校验与冲突提示怎么做；
2. 包里到底要带哪些东西，才能"插件拿到直接就能处理好"。

还有一个实现上的硬约束：**写快照要带 `textVersion`**（酒馆会拒掉旧版本的写入），而**导入发生在两轮之间，拿不到它**。

## 决定

### 1. 包要"自解释"：把导入需要的东西全带上

导出的档案包现在包含：

| 字段 | 为什么要带 |
|---|---|
| `preset.entries` / `preset.order` | 值是按**单字母条目码**存的，没定义就是乱码 |
| `archive.dict` | 值的原文可能是**字典下标**，没字典解不出来 |
| `archive.nextId` | **不带的话导入后新建人物会从 p1 开始，撞上已有的号**（ADR 0004 号码永不复用） |
| `archive.snapshotVersion` | 导入侧要判断这个结构能不能读 |
| `archive.stats` | 面板上显示"这份包里有几个人、几条值" |
| `archive.turn` / `gt` | 还原"导出时是哪一轮、什么时候" |

`nextId` 缺失时按**现有编号最大值 +1** 兜底，绝不给 0。

### 2. `importBundle()` 把包翻成"可以直接写进整局数据的东西"

返回 `plan`：`{ entries, order, persons?, dict?, nextId, turn, gt }`。
预设包只有 `entries/order`；档案包额外带人物册、字典、计数器。

### 3. 默认**不覆盖**已有档案

| 情况 | 行为 |
|---|---|
| 当前局还没有档案 | 直接导入 |
| 当前局**已经有档案** | **拒绝**，返回「会把它整个替换掉，确认后再导入」 |
| 玩家显式 `force` | 才允许覆盖 |

导入别人的档案是破坏性操作，默认必须让玩家先看一眼。

### 4. 快照攒到下一轮落盘

导入时拿不到 `textVersion`，所以**不立刻写快照**：

```
导入 handle → 校验 → 把 plan 放进 state.pendingImport → 存整局数据
下一轮 onTurnSettled → 用那一轮的 textVersion 把 pendingImport 写成快照 → 清掉
```

好处：不用赌"省略 textVersion 能不能写"，也不会因为版本过期被拒。

代价：导入后**要等到下一轮结算才真正生效**，面板上得说清这一点。

## 后果

- **收益**：包是自解释的——拿着这一份 JSON 就能完整还原每个人物，不需要额外的文件或上下文。
- **收益**：默认不覆盖，不会手一抖把现有档案冲掉。
- **代价**：导入不是即时的，要等下一轮结算。
- **边界**：只导入**人物册**；候选表、冷却、离场记录这些"运行时状态"不跟着走（换局没意义）。

## 被否决的方案

- **导入时直接写快照**：拿不到 `textVersion`，赌不起。
- **默认覆盖**：一次误操作就丢一局档案。
- **包里不带 `nextId`**：导入后新建人物撞号，`rp7` 会指向另一个人（ADR 0004 的反例）。
- **包拆成两个文件（预设＋档案）**：容易走散，用户只发一个就废了。
