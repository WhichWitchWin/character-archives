# ADR 0112 批量删除命题与认知

- **日期**：2026-11-14
- **状态**：已定并已实现（未在真实对局上点过）
- **相关**：[ADR 0083](0083-写入流程-命题与指针.md)（命题＋指针两层，所以删命题要连带摘指针）、[ADR 0088](0088-删人连带摘命题与指针.md)（删人连带的先例）、[ADR 0111](0111-手动补写.md)（同一个面板、同一批「写回链」的维护入口）

## 背景

单条删除早就有了（命题行的 🗑、认知行的 🗑），但档案一多就只能一条条点：

- 每个条目一次 `callHost`，每次后端都要「读整局数据 → 读快照 → 改 → 写快照 → 更新酒馆指针」，删 20 条就是 20 次读盘写盘；
- 中途失败会留下「删了一半」的中间态，面板刷新后看不出停在哪；
- 「清一批模型写错的记录」是真实场景（尤其配合 ADR 0111 的补写：补写跑出来的内容不对，要成批撤回）。

## 决定

1. **新增两个批量 handle**：`character-archives/delete-claims`（`{gameId, claimIds}`）与 `character-archives/delete-cognitions`（`{gameId, personId, claimIds}`），一次读快照、一次 `saveSnapshot` 落盘（有冷却要清时另写一次整局数据）；`MAX_BATCH_DELETE = 200`，超了直接拒绝（校验在读快照**之前**）。
2. **写回进行中就让路**：四个删除入口（单条两条 + 批量两条）都先问 `writebackBusyReason()` → `isWritebackInFlight(gameId, turn)`。删除和写回都基于**同一轮快照**、各持一份内存副本再整份写回，后写覆盖先写——先删后写会让删掉的命题「复活」，先写后删会抹掉写回刚产出的内容。这条是评审抓到的（与 ADR 0111 的 C1 同源）。
2. **纯逻辑抽到 `lib/batchDelete.js`**（`dropClaims` / `dropCognitions`），**单条接口也改用它**——单条与批量必须是一套规则，不能养两份：
   - `dropClaims`：命题 + **所有**指向它的指针一起删；返回 `removedClaims` / `removedPointers`；不存在的 id 静默跳过，重复 id 只算一次；id 只认「数字或纯数字字符串」（`Number()` 太宽：`true`→1、`'0x10'`→16 都能删错东西）。
   - `dropCognitions`：只摘指针、绝不删命题；如果某个 id 摘掉这个人的指针后**一条都不剩**，整条跳过并记 `skipped:[{claimId, reason:'last-cognition'}]`——零指针命题下一轮会被 `pruneOrphanClaims` 当孤儿清掉，而面板承诺「命题本身不动」。脏数据里同一个人对同一条命题可能挂多个指针，真删时**循环摘到底**（只摘一条会「删了还在」）。
3. **删命题时按号清冷却**：命题编号会被复用，留着旧冷却会压住将来同号的新命题（ADR 0086 那套）。
4. **面板**：人物详情里加「多选」开关，打开后命题行/认知行出现勾选框，另有「全选命题」「全选认知」「清空」与两个危险按钮（`删除选中命题(N)` / `删除选中认知(M)`），删除前 `window.confirm`；选中集合按 `String(claimId)` 归一（面板里同一个编号可能是数字也可能是字符串）。
5. **回执**：批量认知删除可能「删一部分、跳一部分」，返回 `removed` / `skipped` / `skippedIds` 与一句人话（`删了 N 条；另有 M 条是「最后一条认知」…`），面板直接显示。

## 不做：防止「下一轮又写回来」

用户明确定调：**不做**防复写。删掉的命题下一轮可能被模型按正文重新写出来（新编号、可能措辞略变），这是**已知行为，不是 bug**：

- 写入素材只给「当前快照里的命题」，删掉后素材里没有它，但模型读的是同一段正文，可以重新推导；
- 要彻底防，得存「已删命题指纹」并在写入时过滤，还要配解封入口——本轮不做（记录在此，将来要做时从这里起）。

## 代价与边界

- **不可撤销**：和单条删除一样是真删（面板上删完就没了）；要留底只能靠导出包。
- **一次最多 200 条**：超过就拒绝，避免面板误传几千个 id 扫一遍快照。
- **只对「当前结算轮」的快照生效**：落盘轮次由 `editTurnOf()` 决定（一般是 `meta.updatedTurn`）。**正在生成/结算，或这一轮的写回还没跑完时，接口会直接拒绝并说明原因**（见「决定 2」）；等它结束再删即可。
- **未实测**：本机没跑过真实对局，面板的多选交互（勾选 → 二次确认 → 回执）要装进酒馆点一次才算验过。

## 守卫

- `tests/batchDelete.test.mjs`（8 条）：命题与指针一起删、脏 id/重复 id、**id 只认数字或纯数字字符串**、空输入、认知只摘指针、最后一条认知跳过、本来没有这条认知不算跳过、**同人重复指针一次摘到底**；
- `tests/hostWiring.test.mjs`（+2 条）：两个批量 handle 各只 `saveSnapshot` 一次（并禁掉「把落盘塞进循环」的写法）、指针取自 `snapshot.pt`、写回进行中要让路、面板有「多选」/勾选框/两个批量按钮；另把三条旧的单条删除守卫改成「委托纯逻辑 + 指针取自快照」的口径（「一起摘」「最后一条跳过」的规则由纯逻辑测试覆盖）。
