# 0077 全局专名词库：跨局记住地名、店名、组织名

- **状态**：有效
- **日期**：2026-11-03
- **相关**：[ADR 0060](0060-称谓表退役改用分词.md)、[ADR 0076](0076-索引词跟着值走.md)

## 背景

分词器（`segment.js`）靠一份用户词典决定"哪些词不可拆"。现在每轮灌进去的只有：

1. 已建档人物的**姓名、别名**
2. 模糊建档表里的名字

**地名、店名、组织名一个都没有**。后果是「香格里拉酒吧」被切成「香格里拉／酒吧」，「青龙帮」被切成「青龙／帮」——遇到复合专名就散架。

索引词本来就在抽这些专名（ADR 0021），只是从来没被拿去喂分词。

## 决定

### 1. 索引词加类别

写值时索引词从字符串改成 `{"词":"香格里拉酒吧","类":"地"}`，类别只有四个：**人 / 地 / 组织 / 物件**。

用模型给类别，不用程序猜后缀——「香格里拉」没有「店/馆/楼」尾巴，规则一定会漏；而模型本来就知道这句话里哪个是店名。老格式（纯字符串）照样能读，只是当"未分类"，不进词库。

### 2. 只有「地 / 组织 / 物件」进库

人名已经由姓名/别名每轮单独灌进词典，再进一遍是重复占地。**类别就是筛选器。**

### 3. 放自持区，跨局共用

`<数据根>/global-words.json`，结构 `{ v: 1, map: { "香格里拉酒吧": 12 } }`（词 → 最后命中轮次）。

- 不放插件数据：那边总共 256 KB，已经挤着设置和提示词；
- 不放插件目录：升级会被清掉（ADR 0058 的老教训）；
- **跨局共用**：一个故事里的"镖局"到了另一个武侠故事里大概率还是词。这跟索引词不一样——索引词是**这一局的事**，所以跟着值走（ADR 0076）；词库是**语言常识**，所以全局。

### 4. 滚动 LRU，上限 2000 条

- 超过上限就按「最后命中轮次」**从旧往新删**；命中一次就刷成当前轮，所以常用词永远活着，冷门词自然沉下去。
- **单个词最多 10 字**——这是性能的真正开关：分词的最大词长由最长词决定，一个 20 字的"词"会让每个位置都多试十几格。超长的直接不收。

### 5. 灌进分词的时机

- 每轮开始：`syncUserWords(快照, 候选表, 全局词库)` —— 仍然是一次**整体替换**，不累积；
- 本轮写完值、词库有新增：立刻再灌一次，否则刚写进去的专名要等下一轮才分得准。

## 后果

- **收益**：复合专名不再被切开，召回和索引词匹配都更准。
- **收益**：跨局复用，2000 条上限 + LRU 保证它不会无限长，也不会拖慢单轮（Map 查词 O(1)，2000 条对分词的影响可忽略）。
- **代价**：词库**不跟着回退**。玩家回退到很早的轮次，词库里那些专名还在。这是有意接受的——它是"语言记忆"，不是"局内状态"，留着不会让剧情出错。
- **代价**：索引词格式变了。老数据（纯字符串）能读，但不进词库；没发版，不做迁移。

## 被否决的方案

- **程序按后缀规则猜专名**（店/馆/楼/公司…）：零成本，但漏得厉害（「香格里拉」没后缀）、也会误收。放弃。
- **存插件数据**：256 KB 挤不下，且它跨局，本来就不属于"插件配置"。
