# 0020 写入判断真假时，带上「视角说明」

- **状态**：已采纳
- **日期**：2026-11-01
- **supersedes**：ADR 0019 里「**第三人称**叙述下」这个限定（顺带关掉 Q12）

## 背景

ADR 0019 定的例外是：

> 第三人称叙述下、正文明确写了主角亲眼见到 → 「真」

**漏洞立刻显现**：第一人称和第二人称的游戏里，"真"永远不会出现——哪怕主角就站在现场亲眼看着。而插件本来就要兼容三种视角：

- 第一人称：正文写"我"；
- 第二人称：正文写"你"；
- 第三人称：正文写主角的名字，而且**主角不一定在场**。

用户给出的解法：把"人称换算"直接告诉写入模型——我们有「视角人物」这个设置，顺手把叙述人称也带上就行。

## 决定

### 1. 本局设置项：叙事人称

| 档 | 视角说明（写进提示词） |
|---|---|
| 第一人称 | `本局为第一人称；「我」＝主角林澈` |
| 第二人称 | `本局为第二人称；「你」＝主角林澈` |
| 第三人称 | `本局为第三人称；主角＝林澈` |

主角名沿用 M4-10「指定档案视角人物」（默认 `{{user}}`，取不到用「玩家角色」）。

### 2. 判断规则不再依赖人称

```
正文明确写了"主角在场并亲眼见到" → 真
其余一切                        → 未定
拿不准                          → 未定（宁可少标真，不可乱标真）
```

- 第一人称："我亲眼看见他搬货" → 真；"我听说他是账房" → 未定；
- 第二人称："你看见他搬货" → 真；
- 第三人称：主角在场景里且写明看见 → 真；主角不在场 → **只能未定**（这正好反映"他没看见"）。

### 3. 设置错了怎么办

人称设置与正文不符时，模型可能把"我听说"误判成"我见到"。两道缓解：

- 提示词里要求"**只有明确证据才给真**"，其余留未定；
- 设置项放本局（换局要重设），避免一局用错影响所有档案。

## 后果

- **收益**：三种视角统一；第一/第二人称不再"永远没有真值"；规则从"看人称"变成"看主角在不在场"，语义正确。
- **代价**：多一个本局设置项（叙事人称）；设置错了会污染真值判断（靠"拿不准留未定"兜底）。
- **边界**：第三人称且主角不在场的轮次，**所有新值都只能是未定**——这不是缺陷，是对"主角不知道"的如实记录。
- **被否决的方案**：
  - *按人称写死规则*（第三人称才算真）：第一/第二人称永远无真值；
  - *让模型自动猜人称*：猜错的代价是整局真值错位，不如让玩家选一次。
