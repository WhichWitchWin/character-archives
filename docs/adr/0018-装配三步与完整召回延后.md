# 0018 装配三步走；完整召回第一版砍掉

- **状态**：已采纳
- **日期**：2026-11-01
- **supersedes**：ADR 0017 里「完整召回参与装配」的那部分

## 背景

ADR 0017 定了四档，完整召回也在里面。接着聊"装配怎么排"时，用户给了一个反直觉但更合理的顺序，并顺手把完整召回判了缓刑：

> 「本质上一局游戏里真有一个人非常重要，那他的条目里大概率有一大堆对于主角来说完全用不上的值。」

也就是说：**越值得完整召回的人，完整召回的性价比越低**——档案里塞满外貌标签、过期旧处境、互相矛盾的旧说法。再加上三重门（全局开关 + ★ + ≥0.90）和"装配排最后"，它几乎永远不会触发。

## 决定

### 1. 装配三步（不含完整）

| 步 | 干什么 | 给谁 |
|---|---|---|
| **① 保底** | 每人先塞一个**简单** | 所有**非提示档**的人 |
| **② 升详细** | 够详细分的升成**详细** | ≥0.60 的人，按分数降序 |
| **③ 填提示** | 还有预算才塞**提示** | 提示档的人（或单字命中被压下来的），按分数降序 |
| — | 任一步装不下就停，剩下的丢掉 | — |

### 2. 完整召回：第一版不做

- 档位枚举与判档函数**保留**（`TIER.full = 0.9`、`tierOf({ fullAllowed })`，默认 `false`）；
- **装配层不实现**——所以实际上永远触发不了；
- 完整方案（三重门、每轮最多 2 个、每人上限 800、装配排最后）**原样存进 [ROADMAP §6.1](../ROADMAP.md)**，以后要捡直接照做。

### 3. 详细召回的内容口径（草案，待定）

每条目最多 2 条值（最可信 + 最新）、条目按"本轮相关 → 预设顺序 → 信度"排、含计划的条目永不裁、每人 400 字符上限——**这些还没定稿**，留作 Q11。

## 后果

- **收益**：v0.1 只需实现三档内容装配，省掉"全档案怎么拼"整整一层；也省掉"完整要不要预留预算"这一串讨论。
- **代价**：玩家可见的「完整召回」暂不存在；★标记第一版只影响时效（0.6 地板）。
- **边界**：`TIER.full` 留着不会误触发（`fullAllowed` 默认 false）；将来接手时别以为它已经能用。
- **被否决的方案**：
  - *完整排在最前*：一个人升完整就能吃掉全部剩余预算，把详细的人压回简单；
  - *完整召回 = 1.0 分*：四项全满，几乎永远不可达；
  - *完全删掉完整档*：留着枚举和判档几乎零成本，删了以后还得重写。
