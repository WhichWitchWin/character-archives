# ADR 0110 分叉继承：新分支要接住父局分叉点之前的那份档案

- **日期**：2026-11-13
- **状态**：已定并已实现（未在真实分叉上实测）
- **相关**：[ADR 0057](0057-自持文件存储.md)（自持文件存储，本条补的是它没做的事）、[ADR 0058](0058-数据放插件数据区.md)（数据目录）、[ADR 0009](0009-条目定义加轮次并回收.md)（回退清理的思路）、[ADR 0109](0109-交卷形状三层兜底.md)（同一轮修的另一件事）

## 背景

玩家自己玩时发现：**一分叉，新分支的人物档案是空的**（人、栏目、命题全没了）。

查下来的因果链（都有证据）：

1. **分叉＝开一局新游戏（新 `gameId`）**：官方文档「`fork` 时 `gameId` 是新游戏，`fromGameId` 是原游戏」（`plugin-api-game.md:408`）；宿主实现 `tavern-plugin/lib/index.js:2567` 就是 `timelineChanged(fork.sessionId, { kind:'fork', turn: lastTurn, fromGameId: source.sessionId })`。
2. **插件自己的文件按 `gameId` 存**：`games/<gameId>.json`、`snapshots/<gameId>/…`、`deleted/<gameId>.json`（`lib/store.js`）。
3. **官方文档明说这条代价**：「自己写的文件**不会**随存档、分叉带走」（`plugin-api-data.md:264`）；只有酒馆侧那份整局数据（几十字节指针）会被复制到新游戏（`:223`）。
4. **插件从没订阅过时间线事件**：全 `plugin/` 搜 `onTimelineChanged`／`fork`／`fromGameId` 零命中，只接了 `onTurnSettled`。
5. 于是 `loadGameState` 在子局读到「指针在、文件不在」→ `createGameState()` 空局（`index.mjs:398-404`）。

这与 [DESIGN.md](../DESIGN.md)「人物书属于**当前这一局**，随剧情版本回退、分叉」的设计意图不符——意图写了，「创建分支时的那一步」没写。

## 决定

订阅宿主的 `ctx.tavern.onTimelineChanged`（**名字是 Changed**，不是 Change；官方 `plugin-api-game.md:406`，宿主实现 `plugin-api.js:679`，卸载时自动撤销），只在 `kind === 'fork'` 时动手，把父局搬一份给子局。

**分叉点从哪儿来**（顺序固定，**绝不退回「父局最新轮」**）：① 事件里的 `turn`（宿主只在 `turn > 0` 时才带这个字段，`plugin-api.js` 的 `known` 判断）；② 事件没带就问子局自己——`ctx.tavern.getTurnState({gameId: 子局}).turn`（分叉时宿主已把正文前缀复制到新局，`plugin-api.js:416-425`），这一条覆盖「在开场白／第 0 轮分叉」；③ 都拿不到按 `0` 处理（宁可只继承人、不继承历史，也不把未来搬过去）。退回父局最新轮会把父局到最新轮为止的快照与 `flags` 全搬进新分支——静默、且比「档案全空」更难查。

1. **整局数据**：`inheritGameState(parent, { forkTurn })`（新 `lib/forkInherit.js`，纯逻辑）——`meta.updatedTurn` 与 `snapshots.index` 截到分叉点；`flags` 交给回退那套 `pruneFutureFlags` 剪掉未来记录（另外补一刀 `lastHits`，它同样带轮次）；`dict`／`nextId` 照抄；**预设三样（`entries`／`mvuChecklist`／`settings.checkedCodes`）丢掉**（它们归「全局 + 按卡」，`saveGameState` 一直故意不写进整局数据，抄回来就成了第二真相源）；`cooldowns` 只留 `lastTurn ≤ 分叉点` 的（`lastTurn > 分叉点` 是分叉之后才立下的冷却，带过去会压住新分支的召回好几轮）；分叉点是第 0 轮时，带轮次的 `flags` 与 `cooldowns` 一律清空；`debugLog` 清空（新局从头记）。父局数据坏成数组时当没数据。
2. **快照**：`store.copySnapshotsUpTo(parent, child, 分叉轮)`——只搬 ≤ 分叉轮的那几份。**以父局索引为准**，因为父局同一轮可能有残留的两份文件（换版本时 `moveToTrash` 失败会静默返回 null），照文件搬会把同一轮搬成两条；子局已有的索引**按轮合并**（不是整片覆盖），同轮换文件时把子局旧文件挪 `trash/`。
3. **已删名单**：`store.copyDeleted`——不带过去的话，父局里删过的人到新分支会被模型重新建档，玩家删了个寂寞。
4. **补一条酒馆侧指针**：`saveGameData({ gameId: child, data: { v, store:'file', at } })`。宿主分叉时本来会复制这条指针，但不赌它——指针不在的话 `loadGameState` 会当这局没数据，我们刚写的文件等于白写。**顺序是先指针、后写文件**：指针写不进去就停在这一步，子局仍是「没有数据」、闸门可重试；反过来先写文件会让闸门从此焊死。写完再读回一遍，读不到就 `dropGame`（挪 trash，不硬删）恢复可重试。
5. **两道闸门**：① `store.hasGame(child)` 在**队列任务里**复查（进队前先查一次只省时间），为真就整段跳过——子局已有自己的数据＝已经继承过或已经结算过，**绝不覆盖玩家进度**；② 整段跑在现有 `stateWriteQueue` 里，别和同局的写回交错。
6. **失败只 warn，不抛**：继承失败最多让新分支从空档案开始，不能把「分叉」这个动作本身搞崩。

## 为什么

- **只能靠事件**：文件是我们自己写的，酒馆不会替我们复制；除了 `kind:'fork'` 这个通知，没有第二个地方能知道「父子关系」。
- **必须剪到分叉点**：分叉是「回到过去另开一条」，父局在分叉点之后的 flags（露面／离场／候选／玩家回场）全是**还没发生的事**，带过去会让候选表凭空多出人、离场判定算错——和回退要剪未来是同一个道理，所以直接复用 `pruneFutureFlags`。
- **冷却只按 `lastTurn` 剪，不按 `until` 剪**：一条冷却 `{lastTurn, until}` 说的是「第 lastTurn 轮召回过某人，压到第 until 轮」。`lastTurn > 分叉点`＝这条召回根本没发生在新分支的历史里，要丢；`until > 分叉点` 则只是「冷却自然延续」，留着才对（丢了会变成「刚召回完就又立刻召回」）。评审建议的「按 until 剪」会把这个语义弄反，没采纳。
- **不搬的东西**：`trash/`（死数据）、`global-words.json`（跨局专名词库，本来就不属于某一局）。
- **幂等优先于补全**：宿主的事件可能重投（`docs` 说明「以后可能增加新的 kind」「通知在变化保存之后发出」），所以宁可「已有数据就跳」，也不做合并——合并猜错就是改玩家的档。

## 代价与边界

- **宿主不 await 我们**：`timelineChanged` 是 `void Promise.all(...).then(dispatch)`（`plugin-api.js:1629`），不等处理器跑完。真正兜住的是**时序**（新分支要玩家输入 + 一次模型生成才可能落盘，而复制只是几毫秒的 fs 同步操作）；`hasGame` 闸门在队列里复查，负责的是「别覆盖已经写进去的进度」，不是这次竞态。
- **面板要刷新**：分叉后立刻打开面板，可能赶上复制还没跑完；复制完成后刷新页面即可。
- **已经分叉出去的旧分支不补**：没有父子关系记录（只有事件当时的那一次通知），要补只能手动导出／导入。
- **分叉点是第 0 轮时只继承「人」以外的静态部分**：没有快照可搬，人物册会是空的（此时父局的历史也确实不属于这条新线）。
- **未实测**：本机没有可跑的真实分叉（需要重启酒馆并实际操作一次分叉），已用 15 条单测覆盖变换与搬运逻辑。

## 守卫

- `tests/forkInherit.test.mjs`（9 条）：分叉点之后的 flags 被剪（含 `lastHits`）、`meta` 与快照索引截断、字典／编号照抄但预设三样丢掉、冷却按 `lastTurn` 剪、父子互不影响（深拷贝）、调试日志清空、拿不到轮次时不剪、分叉点第 0 轮清空带轮次的记录、父局坏成数组当没数据。
- `tests/store.test.mjs`（+5 条）：`hasGame` 闸门、`copySnapshotsUpTo`（未来轮次不搬／重跑幂等／**父局同轮残留只搬索引认的那份**／**子局已有索引按轮合并**）、`copyDeleted`（空名单不落空文件）。
- `tests/hostWiring.test.mjs`（+1 条）：index.mjs 订阅了 `onTimelineChanged`、只认 `fork`、用了 `fromGameId`、闸门在队列任务里、搬三样东西、补 `saveGameData` 指针、**turn 缺失时问子局而不是退回父局最新轮**。
