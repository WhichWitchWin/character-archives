# ADR 0088 · 删人要连带摘命题与指针，且必须可恢复

- **日期**：2026-11-04
- **状态**：已定并已实现
- **相关**：[ADR 0066](../DESIGN.md)、[ADR 0081](0081-信度改成事实加指针-提案.md)、[ADR 0087](0087-约定类命题程序只存不判断.md)

## 背景

「删人」原来是**只把人物从 `snapshot.p` 里拿掉**，命题表 `c` 和指针表 `pt` 一字不动。换成「命题 + 指针」之后这就漏了：

- 他名下的命题还在 → 关于一个已删除的人的认知还留在表里；
- 他作主体的指针还在 → 召回时会去问「一个不存在的人知道什么」；
- 别人指向他命题的指针还在 → 命题没了，指针悬空。

**删人不是物理删除**（ADR 0066：进「已删除」名单，可恢复），所以这些连带数据也不能真丢。

## 决定

1. **删人时一起摘三样**：
   - 他**名下的命题**（命题第 2 格是他）；
   - 他作**认知主体**的指针（第 1 格是他）；
   - **别人指向他名下命题**的指针（命题走了，指针必须跟着走）。
2. **一起存进「已删除」记录**（`claims` / `pointers` 两个字段），跟人物本身躺在一起。
3. **恢复时原样补回**：命题按命题 id 去重、指针按「主体 + 命题」去重（两条删除记录可能都带着同一条）。
4. **永久删除（purge）时才真正丢掉**——那时记录从名单里删掉，这些数据也就没了。
5. 回退语义不变：删除与恢复都走正常的 `saveSnapshot`，回退到删除之前，人被恢复出来、连带数据也跟着回来。

## 实现

- `lib/deleted.js` 新增两个纯函数：`claimsOfPerson(claims, personId)`、`pointersOfPerson(pointers, personId, claimIds)`（有测试守着）。
- `delete-person`：收集 → 写进删除记录 → 从 `snapshot.c` / `snapshot.pt` 摘掉。
- `restore-person`：补人物 → 补命题（按 id 去重）→ 补指针（按主体+命题去重）。
- `purge-deleted`：不变（记录一删，连带数据随之消失）。
