# 0017 四档召回与「完整召回」三重门

- **状态**：已采纳
- **日期**：2026-11-01
- **supersedes**：ADR 0011 的 T1（★重要人物时效恒 1.0）、ADR 0014 里的三档分档

## 背景

三档（全量／简版／提示）不够用，两个矛盾同时冒出来：

1. **「全量」这个名字已经不成立**。用户要求全量也像"记忆"而不是"档案导出"，可"多少都给"和"挑着给"不能是同一档。
2. **★人物恒 1.0 太粗暴**。重要人物一多，大家的时效全是 1.0，排序失去区分度；而且等于给"重要"发了一张免死金牌，离场再久都不掉分。

## 决定

### 1. 四档，名字即含义

| 档 | 分数 | 给什么 |
|---|---|---|
| **完整召回** | ≥ 0.90 | 整个档案：所有勾选条目的所有值 |
| **详细召回** | 0.60～0.90 | 挑过的记忆：每条目最多 2 条值（最可信 + 最新） |
| **简单召回** | 0.40～0.60 | 名片：唯一值 + MVU + 最重要一条 + 再一条 |
| **提示召回** | 0.20～0.40 | 印象：唯一值 + MVU + 离场时间 |
| 不召回 | < 0.20 | — |

### 2. 完整召回是三重门，不是分数自挣的

```
① 全局开关「启用完整召回」打开
② 该人物被标 ★
③ 总分 ≥ 0.90
```

缺一，最高只到**详细召回**。代码里 `tierOf` 的 `fullAllowed` **默认 false**——忘了传，代价是"给不到完整"，不是"误给完整"。

### 3. ★人物的时效：地板 0.6，不是恒 1.0

```
★：  0.6 + 0.4 × e^(−0.01 × 离场轮数)     // 上限 1.0，地板 0.6
普通：0.9 × (下限 + (1−下限) × e^(−0.01 × 离场轮数))   // 上限 0.9，下限看剧情节奏
```

剧情节奏档位 → 普通角色的地板：**慢 0.7 / 中 0.5 / 快 0.2**。

### 4. 单字保护改为"压到提示档"

原来压到"候选"（一个中间态），现在四档里没有候选，直接压到**提示召回**。

## 后果

- **0.90 的数学**：四项等权平均，要 0.90 就得总和 ≥ 3.6（只允许总共缺 0.4）。
- **一个刚好的巧合**：★人物的地板 0.6 ＋ 另外三项满分 3.0 ＝ 3.6，**正好 0.90**。所以"极其重要 + 这轮全是他的线索 + 走了很久"仍能压线拿到完整召回。
- **普通角色永远到不了 0.90**：上限 0.9 只够时效一项，三项满分也才 0.8625——和"完整只给★"天然一致。
- **单字更危险了**：0.6 的匹配配高先验／高时效能到 **0.6225**，落进「详细召回」。所以 `weakOnly` 这道闸比以前更要紧。
- **代价**：`compose.js` 的装配要从"两档"扩成四阶梯（提示 → 简单 → 详细 → 完整），这次没动。

## 被否决的方案

- *★恒定 1.0*：重要人物一多就失去区分度，且违反"离场久了该淡出"的方向。
- *完整召回 = 1.0 分*：四项必须全满，几乎永远触发不了；0.90 才摸得到。
- *完整召回只由分数决定*：玩家失去对"全灌"的控制权——全档案很贵，应该是玩家亲手给的权限。
