# 0120 注入写明「关于谁」

- **状态**：有效
- **日期**：2026-11-22
- **supersedes**：无（补充 §7.10.3 注入格式）

## 背景

一条命题是「**关于谁** × 栏目 × 值」三件事，而注入的每一行只写了**值**：

```
▍老陈
· 演员：真（他自己确认过）
```

这句在数据里是「**周可人**的职业是演员，老陈记得」。可「周可人」三个字在注入里**一次都没出现**——
模型最自然的解读就是「**老陈**是演员」。2026-11-22 玩家实测发现正文把这件事写错了，才查到这一层。

为什么以前没暴露：大部分命题是「关于持有者自己的」（老陈的处境、老陈的管家），加不加前缀都一样；
一旦是「他知道的别人的事」，信息一缺就认错人。

## 决定

### 1. 只在「关于别人」时加人名前缀

```
▍老陈
· 小s的管家：真（他自己确认过）        ← 关于老陈自己：不加
· 周可人 · 演员：真（他自己确认过）    ← 关于别人：加「人名 · 」
```

判断在纯函数 `aboutIdOf(claim, holderId)`（`lib/pointers.js`）：命题第 2 格（关于谁）与持有者
不同才返回那个人的 id，相同则返回空串。

**为什么关于自己的不加**：注入预算是硬上限（默认 3000 字），每行多 4～5 个字就少放一两条；
而"关于自己"本来就不会认错。

### 2. 三处拼行的地方统一改

注入的措辞有三条出口，必须一起改，否则同一个人的同一条认知在两条路上写法不一样：

| 出口 | 在哪 | 用在哪 |
|---|---|---|
| 自动召回（按人分块） | `recallEngine` 的 `renderPerson` | 每轮正文生成前 |
| 主角回场（全量） | `recallEngine` 的 `playerBack` 段 | 主角回到在场时那一次 |
| 查档案 | `recallQuery` 的 `queryPerson` | 面板「查认知」＋正文模型的 `archive_query` |

## 后果

- **收益**：模型不会再把「他知道的别人的事」当成「他自己的事」。
- **代价**：每条关于别人的认知多 4～8 个字（含分隔符），预算里能少放一两条。
- **边界**：人名取的是档案里的**姓名**（`nameOf`），不是别名；改名后注入跟着变。
- **边界**：命题第 2 格为空（脏数据）时按"关于自己"处理，不加前缀。

## 被否决的方案

- **每行都加前缀**（包括关于自己的）：白白多花字数，注入预算本来就紧。
- **用括号**（`· 演员（关于周可人）：真`）：比 `周可人 · ` 多 3～4 个字，且读起来更绕。
- **只改自动召回**：`archive_query` 是玩家/模型最常主动看的那条路，漏了它等于没修。
