# 0070 预设表界面：条目定义与 MVU 映射放在一起

- **状态**：有效
- **日期**：2026-11-03
- **相关**：[ADR 0008](0008-条目定义的存放位置.md)（条目定义）、[ADR 0054](0054-配置存储位置.md)（配置存储位置）、[ADR 0013](0013-设计稿改由AI维护.md)、[ADR 0069](0069-输入限制与单字名标记.md)

## 背景

两件事撞在一起了：

### ① 条目的描述从来没被用上

`lib/presets.js` 里每个条目都有一句 `prompt`（写作说明）：

| 栏目 | 描述 |
|---|---|
| 职业 | 社会定位、职务、所属组织；不写具体能力与持有物 |
| 能力资源 | 可动用的本领、权力、财物、人脉；不写性格与身份头衔 |
| …共 8 条 | |

**但这些描述从来没被发过给模型**——`buildWritePrompt` 只给栏目**名字**和现有值。

后果很具体：模型不知道「职业」该写什么，于是把「周也的随从，**管车与早饭**」塞进「职业」——身份和日常职责混在一起，因为「职业」的描述里那句「**不写具体能力与持有物**」它根本看不见。

### ② MVU 映射没有界面

MVU 勾选表（这张卡的「身份」「关系」等字段抄到哪一栏）**存着但看不见**——只能改代码里的 `mvuChecklist`。

## 决定

### 1. 面板加「预设」标签页

一个页面里同时管两样东西：

- **条目定义**：名字、**描述**（给模型看的写作说明）、勾选、唯一值
- **MVU 映射**：这张卡的每个字段 → 抄到哪一栏（或不抄）

### 2. MVU 映射挪到**跟预设表一起存**

原来是「插件数据 · 按卡分区」（ADR 0054），现在是**整局数据的 `state.mvuChecklist`**——跟条目定义（`state.entries`）放在一起。

**⚠️ 与 ADR 0054 的冲突（已知并接受）**：

| | ADR 0054 | 现在 |
|---|---|---|
| 存储位置 | 插件数据 | 整局数据 |
| 作用域 | **按卡**（同一张卡的多个存档共用） | **按局**（每个存档各一份） |

**取舍理由**：预设表本来就是**按局**的（条目定义跟着局走），映射跟着预设表走更一致——玩家在一个地方改，另一个地方不用同步。

**代价**：同一张卡开第二个存档，MVU 映射要重配一遍。

### 3. 新的宿主接口

| 接口 | 干什么 |
|---|---|
| `presets-view` | 返回：条目定义、勾选、唯一值、这张卡的 MVU 字段清单 + 当前勾选表 |
| `presets-save` | 保存：条目定义（改名/改描述/唯一值）、勾选、MVU 勾选表 |

## 后果

- **收益**：条目描述**看得见、改得动**——这是把描述真正用起来的前提（下一步就是把它拼进写入素材）。
- **收益**：MVU 映射终于有界面了。
- **代价**：MVU 映射变成按局（见上）。
- **边界**：本 ADR 只做**界面与存储**；描述**还没拼进写入素材**（那是下一步）。

## 待定

- 条目描述是只放**写入素材**（跟着栏目走）还是也放**系统提示词**（跟着规则走）？——用户倾向后者，但素材更灵活（栏目会变）。
- 描述的措辞现在是「规则口吻」（"不写具体能力与持有物"），要不要改成更明确的**指引口吻**？
- 「职业」这一栏要不要重写描述（明说"别把日常职责塞进来"）？
