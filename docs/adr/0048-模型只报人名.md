# 0048 模型只报人名，不报编号；同名新人照建

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0033](0033-判定素材删除已建档名单.md) 里「已经在档里就拒建档」这条去重口径；[ADR 0032](0032-判定素材带状态.md) 里「判定素材带编号 `· 老陈 p7`」这条

## 背景

写回接上之后冒出三个问题：

### 1. 写入素材是多人块，动作却没说是谁的

素材里一屏列好几个人，而值级动作是 `{ "动作":"新增", "栏目":"身份职业", "值":"…" }`——**没有「人物」字段**，程序不知道往谁头上记。

### 2. 编号是引擎概念，不该给模型看

`p7` 这种编号和「第几轮」是一类东西（ADR 0025 已经定过轮次绝不发给模型）。素材里写 `【老陈 p7 · 离场】` 等于把引擎概念塞给正文模型。

### 3. 一改就撞上「同名」

不给编号，模型只报「老陈」，可 [§2](../DESIGN.md) 明写**同名不同人不自动合并**——局里真可能有两个老陈，程序分不清。

而「已经在档就拒建档」这条（ADR 0033）又会让**同名新人永远建不进来**。

## 决定

### 1. 值级动作加「人物」字段，填**人名**

```json
{ "动作":"新增", "人物":"老陈", "栏目":"当前处境", "值":"在旧港码头养伤", "来源":"自述" }
```

### 2. 素材里**不给编号**

- 平时：`【老陈 · 离场】`、`· 老陈 —— 离场`
- **只有重名时**：`【老陈(p7) · 离场】`，模型**连括号一起照抄**即可定位

这样平时零泄漏，罕见情况才临时借编号当区分符。

### 3. 程序负责把名字翻成编号

`resolvePersonByName()`：

| 情况 | 结果 |
|---|---|
| 名字（或别名）**唯一命中** | 返回编号 |
| 带 `(p7)` 尾巴且那个人存在 | 返回 `p7` |
| **重名**（对上 2 个以上） | **返回 null，绝不猜** |
| 找不到 | 返回 null |

解析不出来的动作 → **逐条丢掉 + 记提示**，接着处理下一条。不猜、不硬塞。

### 4. 建档：只拒「本轮被提到的已建档人物」

这条最要紧。原口径是「已经在档就拒」，会让同名新人建不进来。

新口径：

| 情况 | 处理 |
|---|---|
| 这个名字属于**本轮被提到的**已建档人物（姓名或别名撞上） | ❌ 拒（那是重复报同一个人） |
| 名字跟档里某人相同，但那人**本轮没被提到** | ✅ **照建**（同名不同人） |
| 全新名字 | ✅ 照建 |

模糊建档同理。

## 后果

- **收益**：模型完全看不到编号，素材干净。
- **收益**：同名不同人能正常建档，符合 §2 的边界。
- **收益**：多人同轮也能正确归属。
- **代价**：重名时素材里会出现 `(p7)`，模型要照抄括号——**这是唯一残留的引擎痕迹**。
- **边界**：程序判不出归属的动作一律丢弃，宁可这轮少写，也不写错人。

## 被否决的方案

- **始终带编号**：把引擎概念塞给模型，且和 ADR 0025 的精神相反。
- **同名就拆开、一人一次 followup**：准确但同名时多花调用，且实现更绕。
- **同名直接拒**：那两个同名的人这轮档案都更新不了。
- **建档一律允许（不设 knownNames）**：模型每轮都会把已经在档的人再报一遍，档案会被同名副本塞爆。

## 待定

- 重名时 `(p7)` 这种写法会不会被模型抄错（比如只抄名字、漏掉括号）——实机验证。抄错的话动作会被丢弃并记提示，不会写错人。
