# ADR 0099 记录门槛：动作不记、身份标配不记

- **日期**：2026-11-06
- **状态**：已定并已实现
- **相关**：[ADR 0031](0031-回头测试与沉降.md)（回头测试：同行的标配不算标识）、[ADR 0062](0062-回头测试前置-提案.md)（回头测试前置）、[ADR 0083](0083-写入流程-命题与指针.md)（写入流程）、[ADR 0095](0095-系统提示词拆固定与动态.md)（固定规则＋动态上下文）、[ADR 0096](0096-面板提示词即成员前缀.md)（面板提示词即成员前缀）、[ADR 0070](0070-预设表界面.md)（栏目提示词发给模型的来由）

## 背景

对局里出现这类记录：

> 管家帮主角叫来一辆车 → 「能力资源」里多一条「可以帮主角喊一辆车」。

这类值**脱离当前场景就不成立**：它是一次动作，不是这个人身上的东西。它占掉一个栏目、挤掉召回预算，却解释不了这个人以后会怎么做。同类问题还有「他刚才给主角倒了茶」「他去后院了」。

排查下来，问题不在某一条栏目文案，而在**四件事叠在一起**：

1. 栏目的抓取提示词是「内容清单 ＋ 排除项」的写法，读起来像待办表；
2. 「值不值得记」**没有统一门槛**——判人侧有回头测试，写入侧只有「拿不准就不动」；
3. 栏目侧的邀请是开放的（「能力资源」＝**可动用的本领、权力、财物、人脉**），与「别记琐事」直接对撞；
4. 排除项靠否定式穷举（「不写性格与身份头衔」），否定式提示本身会激活概念。

## 决定

**只改系统提示词，栏目一个字不动**（栏目名、栏目码、抓取提示词、性格栏「按 danbooru 标签化书写」全部保留）。

`plugin/assets/system-prompt.txt` 加四条：

| 位置 | 内容 |
|---|---|
| 「栏目定义」引导句 | 栏目表只说**这条内容记进哪一栏**；值不值得记、够不够格看硬规矩 3、4；**两者冲突时以硬规矩 3、4 为准** |
| 硬规矩 3 | **动作本身不记**：只记它给这个人留下的东西——露出的性格、欠下的人情、许下的承诺、结下的仇、藏着的秘密、变了的去向等，按【栏目定义】记进对应栏目；**没有合适的栏目就不记** |
| 硬规矩 4 | **这个身份本来就会的不记，跟同身份的人不一样的才记**（管家会叫车、厨子会做饭，有「他是管家」一条就够了）；**人在哪、伤好没好这类状态变化照记** |
| 「拿不准就不动」后补一句 | 这里的「拿不准」只指**该不该记**：栏目空着没关系；**是真是假拿不准照记**，态度按【认知口径】给 |

原「两条硬规矩」的标题随之改成「四条硬规矩」。

## 为什么

- **借既有判别力**：回头看这个人的「回头测试」本来就在判「同行的标配 vs 反常」（[ADR 0031](0031-回头测试与沉降.md)）。把它从「要不要给这人建档」扩到「值不值得给他记一条」，模型不用学一套新尺子；
- **门槛只写一遍**：写在系统提示词里（每局一次、能命中缓存），不往 8 个栏目里各抄一遍——栏目提示词每轮跟着【栏目定义】发，重复 8 次只会挤占召回预算；
- **修的是判据不是人**：不规定「性格里该写什么」，只删掉「动作可以直接进档案」这条路；人物仍然由对局里的行为慢慢长出来；
- **真假与取舍分开**：原句「拿不准就不动」同时压着判人侧，整句换掉会顺带放松建档纪律，所以**保留原句、补一句分清真假的拿不准**。

## 评审时否掉的方案

| 方案 | 为什么不采用 |
|---|---|
| 重写 8 条栏目提示词（含新增「说话方式／底线／软肋」） | 会删掉栏目间的分界（「后续计划」写「不写答应别人的承诺」、「未了事项」写「不写泛泛计划」），同一件事被两栏各记一次；把「会影响后续选择」这类话在 8 栏里各写一遍；并丢掉性格栏的 danbooru 标签化要求 |
| 把栏目定义搬进系统提示词 | 模型按**栏目名**回匹配，名字对不上整条丢弃（`plugin/lib/writeActions.js:73-92`）；而栏目是**每局数据**（可改名／删／新建），系统提示词是**全局一份**，搬过去等于玩家一改栏目就静默丢内容；另与 [ADR 0095](0095-系统提示词拆固定与动态.md) 冲突 |
| 按人限条数（档案预算） | 硬上限会把重要信息挤掉，且不解决「记录对象选错」这个根因 |
| 把 8 栏砍成 3 栏 | 栏目码按顺序从 `SINGLE_CODES` 取，改数量会让旧档案包与按卡预设错位 |

## 代价与边界

- **这是软约束**：靠模型自觉，**至今没有实测**。管家叫车这类是否真被挡住，要实际跑几轮看；
- **旧记录不会消失**：已经写进档案的动作式命题仍在，需在面板手动删（命题／认知删除**不可撤销**）；
- **生效时机**：成员前缀在插件加载时挂载（`plugin/index.mjs` 的 `apply`），改完 `assets/system-prompt.txt` 后要**重启 DSH**；或在面板把系统提示词保存一次，会立刻重挂（[ADR 0096](0096-面板提示词即成员前缀.md)）；
- **「还空着」那句没动**：`lib/followup.js` 对新人物会列出空栏目名，那是**建档扳机**（不列的话模型会直接交空、一个人都建不出来），所以保留，只受硬规矩 3、4 约束；
- **守卫**：`tests/promptTemplates.test.mjs` 新增 3 条，锁住「动作本身不记」「这个身份本来就会的不记」「冲突时以硬规矩 3、4 为准」「拿不准分两种情况」和「四条硬规矩」，改提示词会被测试拦下；
- **若实测仍泛滥**：机制层（不列空栏目、按人限条数）才是终局，留作后续版本，不在本条内。
