# 0047 子代理接线：用工具提交动作，不读自由文本

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0028](0028-写入三档.md) 第 4 节里「子代理档」的接口细节（补上源码实证）；设计稿 §7.6.2 里「模型返回纯 JSON 数组」的取回方式

## 背景

写回要用一个常驻子代理跑两次 followup（判定、写入）。两件事没定死：

1. **`agents` 服务到底挂在哪个对象上**——文档只写了「照 narrative-anchor 的形状」，没有实证；
2. **怎么把模型的结论取回来**——原设计是「模型只输出纯 JSON 数组」，但 `followup()` 是**单向**的（发出去就完了），拿回文本得去翻会话事件，而事件结构没有实证。

## 实证（读 `narrative-anchor` 源码得到，不是猜的）

```js
const agents = ctx.get('agents')              // ← 挂在 ctx 上，不是 ctx.tavern
const parent = agents.get(String(gameId))     // 父会话（子代理的挂载点）

handle = await agents.resume({ resumeSessionId, setup })     // 重启后接着用
handle = await agents.create({ sessionId, meta, setup })     // 新局

// setup 拿到子 ctx，系统提示词在这里挂一次
const setup = (childCtx) => {
  childCtx.systemPrompt.section({ name, order: 0, complete: true, text: () => 提示词 })
  childCtx.tools.register({ name: 'submit_actions', parameters, execute })
}

handle.agent.followup({ id, role: 'user', content: [{ type: 'text', text }],
                        source: { kind: 'plugin:<插件名>' } })
await handle.agent.whenIdle()
```

### ⚠️ 一个会炸的坑

`followup` 的 `source.kind` **不能写 `'plugin'`**。DSH 0.2.x（会话格式 v4）要求「producer-owned source kind」，写 `'plugin'` 会抛：

> `format v4 message requires a producer-owned source kind`

必须写成 `plugin:<插件名>`。narrative-anchor 踩过并留了注释，我们照抄。

## 决定

### 1. 用工具提交，不读自由文本

模型调 `submit_actions({ actions: [...] })`，工具 `execute` 里直接拿到**结构化参数**，塞进一个每轮重置的 box；`whenIdle()` 之后读 box。

- **收益**：不用赌会话事件结构；顺带解决「模型啰嗦两句再给 JSON」的解析问题。
- **代价**：`docs/系统提示词.md` 的「六、输出」从"只输出纯 JSON 数组"改成"调用 `submit_actions` 工具"。

`parseActions()` 保留——万一哪天工具不可用，还能从文本兜底。

### 2. 提示词落成代码常量

`plugin/prompt.js` 从 `docs/系统提示词.md` 生成（用 JSON 字符串，不是模板字符串——提示词里本身带反引号，模板字符串会被截断）。

**唯一真相源仍是 `docs/系统提示词.md`**，改那边就要同步这里。

### 3. 没有 `agents` 服务就静默跳过写回

老版本 DSH 没这个服务时，`ensureResident()` 返回 `null`，`runPhase()` 返回 `null`，写回整段跳过——**召回照常工作**。

### 4. 索引词顺路进缓存

写入动作里带 `索引词` 数组 → 子串校验（必须是值的原文片段，ADR 0021）→ 进 `savePluginData` 缓存。这正好补上了「线索匹配没有数据源」的缺口。

## 后果

- **收益**：写回链路完整——判定 → 建档改状态 → 写入 → 校验 → 落盘，全程唯一落盘点。
- **收益**：`index.mjs` 仍然只是胶水，逻辑全在 `lib/`（可单测，240 个测试）。
- **代价**：多一个代码侧的提示词副本，要和文档同步。
- **边界**：写回失败只跳过本轮，绝不影响游戏（整个 `onTurnSettled` 包在 try/catch 里）。

## 待定（重要）

**写入素材是「多人块」，但值级动作里没有「人物」字段。**

素材长这样：

```
【老陈 p7 · 离场】
· 身份职业
  1. 旧港码头的账房（自述·未定·永安元年·春）
【林昭 p12 · 在场】
· 身份职业
  1. 义庄的学徒
```

而动作是 `{ "动作":"新增", "栏目":"身份职业", "值":"…" }`——**没说是谁的**。

这一版的做法：动作里读 `人物`；素材里只有一个人时可以省略。**多人同轮时无法区分**，等于只能改到"省略后无法归属"的动作会被丢弃。

**要补的**：给值级动作加 `"人物": "p7"` 字段（写进系统提示词的动作示例 + ADR 0023 的动作集），模型照素材标题里的编号填。
