# 0067 层 1：名字必须来自正文（程序硬规则）

- **状态**：有效
- **日期**：2026-11-03
- **相关**：[ADR 0061](0061-内部码不进模型.md)（内部码不给模型看）、[ADR 0031](0031-回头测试与沉降.md)（回头测试）、[ADR 0062](0062-回头测试前置-提案.md)（提案，未落码）

## 背景：路人被收了进来

实测（第 6 轮），模型报：

```json
{ "动作":"建档", "姓名":"老头", "别名":"蓝布夹克老头", "称呼":"老头", "状态":"在场" }
```

正文原文只有：

> **老头**也跟着出了站，在他前头几步远，**蓝布夹克**敞着，胳膊底下的小板凳夹得挺稳。

**「蓝布夹克老头」正文里根本没有**——那是模型把两个片段**拼**出来的。

模型的动机不难猜：它要给「老头」这个泛称套个外壳，好让它"看起来像专名"、好过回头测试。

## 决定

### 程序硬规则：姓名与别名必须在本轮正文里**原样出现**

- 判定阶段把 `body`（本轮正文）传给 `validatePersonActions`；
- 建档动作的**姓名**、**每一个别名**都必须在正文里做**子串**判断；
- 有任何一个不在正文里 → **整条建档动作被拒**（宁可漏，不要错）；
- 判定用子串，正文带 markdown 标记（`**老头**`）不影响；
- **没传 body 就不查**——面板上手动建档/改状态（玩家自己的决定）不受这条管。

### 为什么这条规则值得

| | 靠提示词 | 靠程序 |
|---|---|---|
| 「不许自己起名」 | 模型会遵守 90%，剩下 10% 靠自觉 | **确定性 100%** |
| 代价 | 每轮多写一段文字 | 一行子串判断 |

而且它堵的是**最危险的一类错误**：造出来的名字**召不回来**（正文里没人这么叫他）——档案成了死档（[ADR 0031](0031-回头测试与沉降.md) 的原话）。

### 顺带：被拒的动作要看得见

判定阶段现在会把**被拒的人物级动作**记进调试日志（`人物动作被拒 N 条` ＋ 原因＋原动作）。
以前值级动作被拒有记录、人物级没有——"为什么没建档"只能靠猜。

## 层 1 解决不了什么（诚实记录）

**「老头」本身合规、正文里也确实这么写** —— 这一条程序判不了：

| 例子 | 正文里有吗 | 回头测试过不过 |
|---|---|---|
| 姓名「老头」 | ✅ 有 | ❌ 喊一声半条街回头 |
| 别名「蓝布夹克老头」 | ❌ **没有** → 被这条规则拒 | — |

所以层 1 之后，「蓝布夹克老头」这种**被拒了**，但模型如果只报「老头」（不带假别名），**仍然能建档**。

治这一类要靠：

- **层 2（提示词补强）**：反例补齐「年龄泛称/身份泛称」、明确「不能给通用称谓加外壳」、明确「实质互动＝跟主角本人」——**用户决定暂不做**；
- **ADR 0062（回头测试前置成独立动作）**：让模型先显式表态"能不能喊"，程序再校验——**提案，未落码**。

## 后果

- **收益**：模型不能再造名字；死档从源头少一类。
- **代价**：模型偶尔报了个正文里没写的别名（换了个说法），这一轮就不建档——**下一轮它会重报**。符合"宁可漏，不要错"。
- **边界**：只管**本轮正文**。跨轮才出现的人（只在更早的正文里出现过）这一轮不会被建档——但那种情况本来就该走模糊建档。
