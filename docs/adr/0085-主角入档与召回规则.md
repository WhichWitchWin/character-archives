# ADR 0085 · 主角入档与主角的召回规则

- **日期**：2026-11-04
- **状态**：第一步已实现（主角 `p0`、名字同步、一/二人称强制在场、不能删）；第二步（召回的四种情形）待召回引擎
- **相关**：[ADR 0024](0024-建档提前.md)、[ADR 0081](0081-信度改成事实加指针-提案.md)、[ADR 0082](0082-召回改成在场人物认知指针-提案.md)、[ADR 0084](0084-姓名与别名的唯一性与导入体检.md)

## 背景

信度体系换成「命题 + 指针」之后，**认知必须挂在一个人身上**（`pt = [人物id, 命题id, [...], 建立轮]`）。

原来「与主角同名的拒绝建档」（DESIGN §2、§8.6）是**旧体系遗留**：那时信度挂在条目的来源位上，主角不进档案也能表达"主角知道"。新体系下主角不在人物表，模型报「谁＝主角」时 `resolvePersonByName` 找不到人，**整条认知被拒**——于是第一/第三人称下主角亲眼看到的事记不进指针表，视角兼容只在提示词层面成立、数据层面是断的。

## 决定

### 1. 主角常驻一个档案项

- 编号固定 `p0`（不参与 `takePersonId` 的号码分配，永不复用问题不涉及）。
- 姓名与身份设置里的**玩家称呼双向同步**：改称呼 → 档案里的主角名跟着改。
- 由程序保证存在：没有就自动补一个，不要求存档迁移。
- 面板显示，带「主角」标记；**不能删除**。

### 2. 姓名唯一性的口径不变，但对象改了

原规则「与主角同名的**拒绝建档**」改成：**NPC 不许与主角同名**（主角本人那一档由程序维护，不走建档动作）。ADR 0084 的「姓名与别名一局内唯一」对主角一视同仁——主角的名字同样占着那个池子。

### 3. 在场规则

| 本局写作人称 | 主角的在场状态 |
|---|---|
| 第一人称 / 第二人称 | **永远在场**（不由模型改、面板也不给切） |
| 第三人称 | 可变：按正文判断，和普通角色一样 |

### 4. 召回规则

先分清两种东西：

- **主角的指针** ＝ 主角知道某事（认知主体是主角）；
- **指向主角的指针** ＝ 别人对「关于主角的事」的认知（命题的 `关于` 是主角）。

| 情形 | 召回「主角的指针」 | 召回「指向主角的指针 + 主角的命题内容」 |
|---|---|---|
| 一/二人称（主角永远在场） | **不给** | **给** |
| 三人称 · 主角在场 | **不给** | **给** |
| 三人称 · 主角离场 | ❌ 不给（**和普通离场角色一样**，照 ADR 0082） | ✅ 给（通过在场 NPC 的指针带出来） |
| 主角 离场 → 在场 | — | **全量注入一次**主角信息，之后不再重复，直到下次再离场 |

**一句话**：主角在场时**不是召回源**（他的认知就是正文本身），但**必须是召回内容的一部分**（NPC 知道的事里一大堆是关于他的）；主角离场时降级成普通角色。

**「主角的值」指什么**：新体系下人物条目已被命题取代，这里的"值"就是**关于主角的命题内容**（连同 NPC 对它的态度一起给）。

**「全量注入一次」的范围**：**只按指针来**——主角自己的所有指针，连同指针指向的命题内容。**指针才是认知**：关于主角、但他自己没有认知的命题（别人背着他谋划的事）**不注入**。

### 5. 与 ADR 0082 的关系

**不加任何例外**：主角离场后就是普通离场角色，照 ADR 0082「只召回在场人物的认知指针」处理。主角的特殊只有两处——**在场时不当召回源**，以及**离场→在场那一次按指针全量补一次**。

### 6. 冷却

离场 / 在场的召回都要纳入「离场在场冷却」。具体参数与触发点**另行讨论**，本条不展开。

## 为什么

- **数据完整性**：主角不入档 → 主角的认知无处挂 → 视角兼容是假的。
- **不重复**：主角在场时召回"主角知道的事"，等于把正文再喂给模型一遍。
- **不丢信息**：NPC 对主角的认知是剧情判断的关键（"老陈以为主角死了"），必须能被召回。
- **切换时补全量**：主角离场一段时间后重新登场，模型需要一次补齐他的状态，之后按常规召回即可。

## 实现拆分

| 步 | 内容 | 依赖 |
|---|---|---|
| 第一步 | 主角入档：`p0`、名字双向同步、面板显示与保护、姓名唯一性口径、写入侧能挂主角指针 | 无（现在就能做） |
| 第二步 | 召回规则：主角在场/离场的四种情形、离场→在场全量注入 | 召回引擎本身要从"整段关闭"恢复（ADR 0082）+ 冷却定稿 |

## 主角回场怎么判断（已定）

- **判定者**：**程序**，不需要模型额外报。
- **检测点**：写入阶段应用动作之后，主角的 `status` 由 `离场(0)` 变 `在场(1)`——这是**唯一**的回场信号，不靠正文匹配。
- **时序**：召回落后一轮（写入先跑、召回后跑），所以写入阶段记一个 `flags.playerBack = { turn, gt }`，下一次召回读到就做全量注入（上限 1000 字，见 [ADR 0089](0089-召回装配预算打分必带条目地点.md)），注入完清掉。
- **边界**：同一轮里"离场又回场"只算**最后一次**状态变化；回退时跟其他 `flags` 一样按轮次回退。
