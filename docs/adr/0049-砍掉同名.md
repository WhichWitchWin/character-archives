# 0049 砍掉同名：撞名一律拒绝建档

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0048](0048-模型只报人名.md) 里「同名新人照建」这条；以及设计稿 §2 原「同名不同人：不自动合并、按两份分别保存、允许存在同名角色」这条边界

## 背景

同名（局里存在两个「老陈」）看着只是"允许重名"，实际会牵动**五处**，每处都难：

| # | 环节 | 同名带来的问题 |
|---|---|---|
| 1 | **匹配** | 正文写「老陈」，两个人**都命中**——程序没有任何依据判断指谁 |
| 2 | **写入** | 素材得靠 `老陈(p7)` 区分，模型可能抄错；抄错这条动作就丢 |
| 3 | **召回** | 两个都满足条件 → 都注入 → 正文模型看到两个「▍老陈」 |
| 4 | **消歧** | 要做上下文打分（谁的索引词更对得上），还不保证分得清 |
| 5 | **面板** | 玩家看到两个"老陈"，只能靠别的栏目自己分辨 |

而且**最根本的一条**：正文写「老陈推门进来」时，**信息本身就不足以区分**——再聪明的消歧也只能猜。

ADR 0048 当时想用「同名新人照建 + 重名时带 `(p7)`」绕过去，但那只解决了**写入素材怎么写**，没解决「正文里那个老陈是谁」。

## 决定

### 1. 撞名一律拒绝建档

- 姓名或别名撞上档里任何人的姓名／别名 → **拒绝**，并在面板提示「局里已经有「X」了」；
- 与主角同名 → 照旧拒绝（ADR 0024）；
- 模糊建档同理：撞名不收。

### 2. 整套同名支持延后到 ROADMAP P9（优先级最低）

要做的内容包括：匹配层消歧、分不清时列候选/不召回、写入素材的区分方式、召回去重、面板可辨识。**难度高、收益低，排最后。**

### 3. 想绕开就用别名

给其中一个人起**专属别名**（「账房陈」「义庄陈」）。别名本来就全部参与匹配（§2），正文只要用得上那个称呼就能精确命中。

这是当前唯一可行的做法——**不是绕过程序，而是让文本本身变得可区分**。

### 4. `resolvePersonByName` 的 `(p7)` 尾巴保留

它现在是防御性代码（同名已不可能出现），但保留无害：万一将来 P9 做了、或者数据里有历史同名档案，还能定位。

## 后果

- **收益**：匹配、写入、召回、面板四处都不用再为同名做特殊处理，逻辑大幅简化。
- **收益**：绝不会"写错人"——撞名根本建不进来。
- **代价**：卡里本来就有两个同名 NPC 的，只能建一个；另一个得靠玩家手动改个称呼才能建。
- **代价**：玩家手动建同名也不行（程序层面拦）。想两个都留，必须起不同称呼。

## 被否决的方案

- **同名新人照建（ADR 0048 的做法）**：只解决了素材怎么写，没解决"正文里那个老陈是谁"。
- **同名就拆开、一人一次 followup**：准确但贵，且没解决匹配层分不清。
- **上下文打分消歧**：正文只写「老陈推门进来」时无从打分，等于猜。
- **同名时只召回关键度高的那个**：另一个的信息就永远不出现，等于半隐身。

## 待定

- 无。等 P9 再展开。
