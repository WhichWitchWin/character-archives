# 0059 别名也要查撞；单字姓名必须配别名

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：补上 [ADR 0049](0049-砍掉同名.md) 漏掉的一半（它只拦了「新人姓名撞别人」，没管别名）

## 背景

ADR 0049 定了「撞名一律拒绝建档」，但只检查了**新人的姓名**：

```js
if (findExisting(list, name)) { reject(…) }          // ✅ 姓名撞谁都拒
const aliases = String(action?.别名 ?? '').split(',') // ❌ 别名直接收下，不查
```

于是这三种情况全放行：

| 新人别名 | 撞上 | 后果 |
|---|---|---|
| `老陈` | 别人的**姓名** | 「老陈」对上两个人 |
| `陈先生` | 别人的**别名** | 同上 |
| `林澈` | **主角名** | 正文每轮都提主角 → 这个人**永远不算离场** |

一旦撞上，`resolvePersonByName` 会因为「对上 2 个人」返回 `null`，**每一条值级动作都被静默丢弃**（只记一条 warn 日志）。玩家看不出原因，只会发现"这个人怎么一直不更新"。

## 决定

### 1. 别名全量查撞，撞了就整条拒

| 检查 | 处理 |
|---|---|
| 别名 == 自己的姓名 | **自动去掉**，不算错 |
| 别名重复出现 | 去重 |
| 别名撞**任何已有姓名／别名** | **整条建档拒**，提示「别名『X』已经归『老陈』了」 |
| 别名撞**主角名** | **整条建档拒** |

不在程序里偷偷删掉撞的那条——那等于改模型的输出，下次它还会这么报。

### 2. 单字姓名可以留，但必须配 ≥2 字的别名

「周」这种单字名**过不了回头测试**（喊一声半条街回头），而称谓表只能猜、还常漏。所以：

- **姓名允许 1 个字**（档案里就叫「周」，玩家看得懂）；
- **但必须至少有一个 ≥2 字的别名**（「周老板」「周掌柜」），否则拒绝建档；
- 匹配以**别名**为准——它是精确字串，不需要猜。

这样单字能留下，又不必依赖称谓表猜「周」是不是在叫他。

> 字数按**码点**算（`[...str].length`），不用 `.length` —— 生僻字和 emoji 会算错。

### 3. 提示词同步

`docs/系统提示词.md` 的建档规则补两条：

```
· 别名不能和已有任何人重名（别人的姓名也算）；程序会拒掉整条建档。
· 姓名只有一个字时，必须配一个两字以上的别名（"周"→"周老板"）：喊一声"周"一堆人回头。
```

## 后果

- **收益**：写入链路不会再因为"称呼对上两个人"而静默丢数据。
- **收益**：单字姓名有了合法的存在方式（配别名），不用靠称谓表猜。
- **代价**：模型可能因为撞名被拒几次（提示词里已写明，应该很快学会）。
- **边界**：已有存量数据如果本来就有撞名，这次不回溯清理——只在新建时拦。

## 被否决的方案

- **只警告不拒绝**：撞名会让写入静默丢，警告等于没管。
- **自动删掉撞的那条别名**：偷偷改模型输出，它下次还这么报。
- **禁止单字姓名**：有些卡真用单字称呼，一刀切太硬；配别名就能两全。
- **扩称谓表**（加掌柜／师傅／大人…）：永远列不完，且只是"猜得更准"，不是根治。
