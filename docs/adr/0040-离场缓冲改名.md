# 0040 「归档缓冲」改名「离场缓冲」并正式定义

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：无（把一个只被引用、从未定义的词补上正经定义）

## 背景

### 1. 这是个「幽灵术语」

「归档缓冲」在设计稿里出现过三次，**一次定义都没有**：

| 位置 | 原话 |
|---|---|
| §3.6 回退表 | `归档缓冲计时（刚离场 N 轮内不召回）` |
| 附录A 术语表 | 「离场记录」……用于"离场于 X"与**归档缓冲基准** |
| [ADR 0025](0025-离场记录取代在场名单.md) | 内部用途：快照定位、冷却、**归档缓冲**、回退重算、排序 |

写 §7.11 时间轴图时，那一格只能写成 `+3~?`——**因为根本没有数字**。这就是信号：它在别处被当成已存在的机制引用，其实没人定过。

### 2. 它和「召回冷却」不是一回事

| | 离场缓冲 | 召回冷却（§7.5） |
|---|---|---|
| 触发 | **刚离场**的人 | **刚被召回过**的人 |
| 目的 | 别"人刚走就念叨他" | 别重复注入同一批内容 |
| 定义状态 | ❌ 从来没定过 | ✅ 开关＋默认 10 轮＋范围 0～20＋粒度 |

混着用会导致一种错觉：以为冷却已经覆盖了它。其实冷却管的是"重复"，它管的是"时机"。

## 决定

### 1. 改名：归档缓冲 → **离场缓冲**

「归档」两个字看不出它在管什么；「离场缓冲」一眼就知道是"离场之后的缓冲期"。

### 2. 正式定义

> 人物状态从**在场**变成**离场**后，**N 轮内不参与召回**。

- 计时基准：`flags.left.turn`（离场记录里的轮次）；
- 判法：`当前轮 − flags.left.turn < N` → 不召回；
- 回退到离场之前 → 离场记录被清掉 → 缓冲自动消失，不用单独处理。

### 3. 轮数

**待定**。建议 **3 轮**（与模糊离场判定轮数对齐）：模糊离场要等 3 轮才判人走了，判完之后再缓冲 3 轮，一共 6 轮——正好覆盖"刚告别那段"。

## 后果

- **收益**：一个被引用了很久却没定义的词，终于有了确定含义和数字位置。
- **收益**：与「召回冷却」的职责彻底分开，不再互相顶替。
- **代价**：多一个需要维护的计时器（但它复用 `flags.left.turn`，**不需要新存任何东西**）。
- **边界**：只管"刚离场"这一段；离场久的人不受影响，靠时效分自然排序。

## 被否决的方案

- **删掉它**：省一个计时器，但"人刚告别、下一轮档案就跳出来念叨"确实出戏，用户明确要保留。
- **并进召回冷却**：两者时机不同——冷却从"召回"起算，缓冲从"离场"起算，合并会算错。
- **继续叫「归档缓冲」**：名字看不出用途，而且已经幽灵了很多轮，正是名字含糊导致的。

## 待定

- **轮数**：建议 3 轮，未定。
- **要不要进设置页**：现在设置项里没有它。是固定 3 轮，还是给玩家可调（0～10）？
