# 0076 索引词搬进值条目：跟着值一起回退

- **状态**：有效
- **日期**：2026-11-03
- **取代**：[ADR 0021](0021-关联词的抽取规则.md) 里「索引词存在插件数据的全局缓存里」那一半
- **相关**：[ADR 0057](0057-自持文件存储.md)、[ADR 0077](0077-全局专名词库.md)

## 背景

索引词（每条值顺带抽的 0～2 个专名）原来存在**插件数据**里，结构是：

```js
indexWords: { v: 1, map: { "在旧港码头养伤": ["旧港码头"], … } }   // 键＝归一化后的值文本
```

三个毛病：

1. **回退不跟着走**。玩家回退到第 10 轮，值被回退了，但 `indexWords` 是另一份数据，纹丝不动。缓存里那些"值早就不存在了"的词还留着，对不上；更糟的是新写一条**文本完全相同**的值时，会捡到旧词——那可能是别人的、或者上一版剧情的。
2. **跨局污染**。这份缓存是全局的，A 局的值文本进了 B 局的索引表。
3. **抢地方**。插件数据总共 256 KB，设置、提示词、身份、UI 状态都在里面挤，索引词是最大的一块。

## 决定

**索引词直接存在值条目自己的第 6 位**：

```js
// [码, 值, 信度, 轮次, 游戏内时间, 索引词]
['a', '在旧港码头养伤', '自述·未定', 12, undefined, [{ 词: '旧港码头', 类: '地' }]]
```

- `WORDS_INDEX = 5`；没词就不占这一位（省空间）。
- **子串校验**（词必须是这条值的原文片段）挪进 `validateValueActions`，校验通过才挂上去。
- 召回时 `collectWords({ entries, checkedCodes })` 直接从条目读，不再有缓存参数。
- 「判定」只改真值、值没动 → 旧词照留；「覆盖」换了内容 → 换新词。
- 插件数据里的 `indexWords` 键作废，**不做迁移**（还没发版，老数据直接丢）。

## 后果

- **收益**：值回退，词一起回退。这条数据从此只有一份，不可能对不上。
- **收益**：跨局自动隔离——每个词的归属就是它所在的那份快照。
- **收益**：插件数据腾出一大块。
- **代价**：快照文件变大（每条值多 20～40 字节），最坏情况几百条值 ≈ 十几 KB，远低于自持区的限制（不比酒馆那 64 KB/条）。
- **代价**：写进条目的是**未编码的明文词**——值本身可能被字典压成索引，词不会。价值判断：词都很短，且要拿去和正文做子串匹配，编码反而更麻烦。

## 被否决的方案

- **把 `indexWords` 挪到自持区按局存**：回退时插件收不到通知（回退是酒馆行为，只有读快照时才发现 turn 变小），仍然对不上。
- **按值文本保留全局缓存 + 加版本号**：版本号得跟着回退走，等于又发明一套版本机制，比塞进条目复杂得多。

## 待定

- 老数据里已经存过的词要不要回填？（不回填的后果只是"暂时没有索引词"，召回退回只认姓名/别名，不漏不错）
