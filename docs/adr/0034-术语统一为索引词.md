# 0034 术语统一为「索引词」

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0021](0021-关联词的抽取规则.md) 的**术语**（规则本身不变）；[ADR 0023](0023-值级动作集与输出格式.md) 示例里的字段名 `线索`

## 背景

同一个东西，三个名字：

| 名字 | 出现在哪 | 例 |
|---|---|---|
| **`线索`** | JSON 字段名 | `"线索":["旧港码头"]` |
| **`关联词`** | 抽词规则、提示词第五节、ADR 0021 标题 | 「关联词怎么抽」 |
| **`关联线索`** | 召回打分、命中判定 | 「每条有效关联线索 0.5」 |

写代码、读提示词、调分数时三处对不上，每次都要在脑子里翻译一遍——和 [ADR 0030](0030-术语统一与模糊离场归程序.md) 处理「强信号／弱信号／疑似离场」是同一类问题。

而且两个旧名都有歧义：

- 「**线索**」带着侦探味，容易被读成"剧情线索""破案线索"；
- 「**关联词**」在中文语法里是"因为…所以…"这类连词，同形不同义。

它真正干的事只有一件：**正文里碰到这个词，就能想起这个人**——是个**检索锚点**。

## 决定

### 1. 术语统一为「索引词」

- 设计稿里「关联词」「关联线索」全部替换为「索引词」；
- JSON 字段名 `线索` → `索引词`。

### 2. 提示词补一条漏掉的规则

DESIGN §7.6 写着索引词「2～10 字」，但提示词里没写。现在补上：

> · 每个 2～10 字——要像「一个名字」，不像「半句话」

这条**只对模型有用**：它不知道长度限制，可能抽一个 15 字的短语，程序子串校验照样过，但那就不是"词"了。

### 3. 旧 ADR 不动

[ADR 0021](0021-关联词的抽取规则.md) 的标题、正文里的「关联词」一律保留（G3④ 只增不改）。**新名字以本 ADR 和设计稿为准**，读旧 ADR 时知道是同一个东西即可。

### 4. 代码标识符不改

`match.js` / `recall.js` 里的 `clues`、`clueWords`、`clueScore` 是英文标识符，**保留不改**——改标识符没有收益，还可能碰坏测试。只把中文注释里的叫法统一成「索引词」。

## 后果

- **收益**：一个名字，一处定义；提示词字段名和文档术语终于一致。
- **代价**：ADR 0021／0023 里还是旧叫法；拿到旧档案数据时字段名是 `线索`，迁移或兼容需要注意（目前未接线，尚无真实数据）。
- **边界**：字段名改动属于**输出格式变更**，`plugin/` 里解析模型输出的代码尚未编写，趁现在改零成本。

## 被否决的方案

- **统一叫「线索」**：侦探味太重，而且文档里已经到处是"关联线索""线索词"，越用越乱。
- **统一叫「关联词」**：改动面最小，但和中文语法里的"关联词"撞名。
- **三个名字并存**：迟早写错；这次就是因为它才被发现对不上。

## 待定

- 无。
