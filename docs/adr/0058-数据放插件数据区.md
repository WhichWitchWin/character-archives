# 0058 数据放酒馆的插件数据区，不放插件目录

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0057](0057-自持文件存储.md) 的「§4 存插件目录，不跟酒馆数据区」这一条

## 背景

ADR 0057 把自持数据放 `<插件目录>/data/`。查了叙事锚定的真实布局后发现不对：

```
C:\Users\121\.dsh\profile-data\tavern\data\plugin-data\narrative-anchor\
├─ anchors\session-<uuid>.json
├─ logs\
├─ session-worldbooks\
└─ worldbook-combos.json
```

它放在 **`plugin-data/` 专用区**，跟代码分开。而 `<插件目录>/data/` 的问题很实在：

> **插件更新/重装时那个目录可能被清掉，数据跟着没。**

## 决定

### 1. 挪到 `plugin-data/<插件名>/`

```
<tavern data>/plugin-data/dsh-tavern-character-archives/
├─ games/<sessionId>.json
├─ snapshots/<sessionId>/{index.json, <turn>-<hash>.json}
└─ trash/
```

### 2. 定位：从自身安装位置推断，不写死、不瞎猜

`lib/dataRoot.js` 的四级兜底：

| 顺序 | 来源 |
|---|---|
| ① | 环境变量 `DSH_TAVERN_ARCHIVES_DATA`（排错、搬家时用） |
| ② | 环境变量 `DSH_TAVERN_DATA_DIR` + `plugin-data/<名字>` |
| ③ | **从自身位置推断**：我们是 `<data>/plugins/<名字>/`，往上两级就是 `<data>` |
| ④ | 兜底：`<插件目录>/data/`（开发版、目录被改名时） |

第 ③ 条能成立是因为**位置是 tavern 给的**，不是我们猜的——目录名不等于插件名就自动放弃（见测试）。

### 3. 一次性迁移，只 move

启动时：若新目录不存在、而旧的 `<插件目录>/data` 存在 → `renameSync` 挪过去。

- **只 move**，不复制不删除；
- 目标已存在就什么都不做；
- 迁移失败就用旧位置继续跑，**绝不让插件起不来**。

## 后果

- **收益**：更新/重装插件不再有丢数据的风险。
- **收益**：代码与数据分离，符合惯例，也跟叙事锚定一致。
- **代价**：找数据要多钻一层 `plugin-data/`。
- **边界**：卸载插件时数据会留下（需要手动清），但比"更新就丢"好得多。

## 被否决的方案

- **继续放插件目录**：更新插件就丢，风险太高。
- **写死 `~/.dsh/profile-data/...`**：叙事锚定的注释里明确警告过——不写用户主目录，换机器/换 DSH_HOME 就失效。
- **做完整的结构发现**（找 `launcher-settings.xml` 读 `DataDirectory`）：那是为了"开发版与安装版行为一致"，我们只需要"被 tavern 装在哪儿就从哪儿推"，简单够用。
