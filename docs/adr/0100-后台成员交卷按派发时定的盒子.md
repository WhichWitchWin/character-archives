# ADR 0100 后台成员交卷要按「派发时定的盒子」

- **日期**：2026-11-06
- **状态**：已定并已实现
- **相关**：[ADR 0094](0094-后台写入接member.md)（后台写入接 member，本条修的就是它的实现）、[ADR 0092](0092-判人与写入合并成一次调用.md)（一次交一个对象）、[ADR 0096](0096-面板提示词即成员前缀.md)（面板提示词即成员前缀）

## 背景

玩家把「档案写入方式」切到**后台档**（`writeback.mode = 'background'`）之后，第 3 轮结算的表现是：

```
第 3 轮结算开始（正文 440 字）→ MVU 解析成功
判定阶段没返回动作（子代理不可用或没调 submit_actions）｜动作数 null｜原始 null｜子代理 null
写入阶段没返回动作｜载荷 null
写回完成：judgeActions null、created 0
```

第 3 轮快照里 `c:[] pt:[]`——**一条命题都没写进去**，而且面板上看不出任何报错。

## 根因

后台档的交卷工具这样找盒子：

```js
async execute(args, execution) {
  const box = memberBox(execution?.sessionId)   // ← 这个 execution 永远是 undefined
  ...
}
```

但宿主调用插件工具时**只给一个参数**：`plugin-task-execution.js` 里是
`tool.execute(structuredClone(args ?? {}))`（[宿主源码](<C:/Users/121/.dsh/apps/dsh-tavern/tavern-plugin/lib/domain/plugin-task-execution.js>) 的 `call`）。

于是 `execution?.sessionId` → `undefined` → `memberBox(undefined)` 取的是**键为空串**的那只盒子；而 `runPhase` 派发前准备的是按 `gameId` 存的那只。模型交的内容全落进没人读的盒子，`runPhase` 读到 `null`，日志就成了「没返回动作」。**工具还返回 `ok:true`，所以模型以为自己交成功了。**

顺带一个佐证：所有历史对局里只有这一局是后台档，也就是说**后台档从上线起一次都没成功过**；之前能出档案的对局都走子代理档（日志里 `子代理: {provider, model}` 非空）。

## 决定

1. **抽出纯逻辑模块 `plugin/lib/memberBox.js`**，三个入口：`beginMemberRun(box)` / `endMemberRun(box)` / `submitMemberPayload(args)`；
2. **派发前定盒子**：`runPhase` 在 `runTask` 之前 `beginMemberRun(box)`，用 `try/finally` 保证超时、中止也会 `endMemberRun(box)`；
3. **工具只往当前盒子写**：`execute(args)` 只收一个参数，直接 `submitMemberPayload(args)`，不再碰第二个参数；
4. **没派发就提交 → 明确返回 `{ok:false, error:'没有正在运行的档案任务，这次提交被丢弃'}`**，让模型能重试、日志里也留痕，不再静默成功；
5. **补一条可诊断字段**：调试日志的判定块加「交卷次数」——`0` 次＝模型压根没调工具，`>0` 次还空＝程序侧又读错了盒子，一眼能分开；
6. **加守卫**：`tests/memberBox.test.mjs` 锁住四个行为 + 一条接线守卫（不许再出现 `memberBox(execution`）。

## 为什么

- **不能改宿主**：宿主是酒馆本体，插件只能适配它的契约；
- **单一活动盒子够用**：宿主规定同一成员的任务串行跑，所以「当前这一轮」在任一刻只有一个；`endMemberRun(box)` 只在盒子还是自己那只时才清，避免两个局互相踩；
- **失败要吵**：这次最难查的地方不是 bug 本身，而是**工具返回 ok、日志没有异常**——修复的重点之一是让下次同类问题自己说话。

## 代价与边界

- **假设同一成员串行**：若将来宿主允许同一成员并行跑多个局，单一活动盒子会互相覆盖（那时要改成队列或按 gameId 传参）；
- **`archive_query` 不动**：那个工具走的是 `ctx.tools.register`，`execution.sessionId` 是**真的会传**的（正文请求的会话号），别把本条守卫套到它身上；
- **子代理档不受影响**：子代理的交卷工具用闭包直接拿 `resident.box`，从来没有这个 bug；
- **旧数据不补**：这一局的空白轮次不会自动补算，重新玩一轮即可；
- **修复后未实测**：本地 737 个测试全过只能证明接线和盒子语义对，**真实模型这一轮能不能交出动作，要重启 DSH 后实际跑一轮才知道**（重启后调试日志里应能看到「交卷次数 ≥ 1」）。
