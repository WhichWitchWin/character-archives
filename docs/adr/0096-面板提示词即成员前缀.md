# ADR 0096 面板的系统提示词就是后台成员的前缀

- **日期**：2026-11-06
- **状态**：已定并已实现
- **相关**：[ADR 0095](0095-系统提示词拆固定与动态.md)（固定＋动态拆分；本 ADR 推翻它「代价与边界」里的第一条）、[ADR 0094](0094-后台写入接member.md)（结算接 member）、[ADR 0063](0063-三段提示词可编辑.md)（三段可编辑）

## 背景

[ADR 0095](0095-系统提示词拆固定与动态.md) 留下的边界是：**玩家在面板里改的系统模板，在「跟随后台」档不生效**——成员前缀在注册那一刻取的是默认模板（`assets/system-prompt.txt`），之后面板怎么改都进不去。

实际后果是面板会说谎：

- 玩家在「提示词」页改了规则 → 面板显示新文本 → 后台结算仍按旧规则判人；
- 更隐蔽的一种：安装目录只读时，面板保存只落到插件数据（`prompts.system`），`system-prompt.txt` 写不进去。子代理档读插件数据（新文本），成员读 txt（旧文本）——两条路径当场分叉，玩家完全看不出来。

宿主侧的事实（有源码依据）：

- `tavern.member()` 把 `system` 存成成员的**固定前缀**（`lib/domain/background-members.js:52-55`）；
- 同名再注册会抛「成员 X 已注册」（同文件 `:51`），所以换前缀只能**先卸再挂**（注册返回的卸载函数）；
- 成员是**每局一个会话**（`plugin-api` 参考 `plugin-tasks.md`「成员的前缀和工单」），会话开头那份前缀不会跟着变。

## 决定

**面板里那份系统提示词就是后台成员的前缀，保存即重挂。**

1. `index.mjs` 把注册收进 `mountMember(ctx, system)`：先调用上一次注册返回的卸载函数，再用新文本注册；文本没变就跳过（不白扔宿主的模型缓存）。
2. **挂失败要回滚**：卸载成功了、新文本没挂上，等于成员凭空消失（派发时宿主会报「没有注册成员 档案员」，后台写回整档失效）。所以失败时用旧文本挂回去，宁可继续用旧的，也不能没有；返回 `false` 让调用方知道。
3. `apply()` 先用 `defaultSystemPrompt()` 挂上（同步、启动就有成员）；随后 `readPrompts(ctx)` 读完插件数据再挂一次——**面板显示的那份优先**。这次异步刷新带序号校验：读盘期间玩家保存过就不覆盖。
4. `set-prompts` 存完 `system` 段后立刻 `mountMember(ctx, templates.system)`，并把「成员挂上没挂上」如实回给面板。
5. 面板上限收到 **20000 字**（原来 30000）：系统提示词还要当成员前缀，宿主 `MAX_MEMBER_SYSTEM` 就是 20000，插件放得更宽就会出现「面板存得下、成员挂不上」。
6. 面板「提示词」页顶部常显生效边界：**保存后下一轮结算就生效**（子代理、跟随后台都一样），代价是改文本会让提供方的提示词缓存失效一次。

> **2026-11-06 修订**：本条原先写的是「跟随后台档要新开一局才注入，已经结算过的局仍用旧的」——**错**。读宿主代码后确认前缀不是烙进会话的：宿主的系统提示词段是组装时求值的函数（`background-agent-task.js:165-175`，`text: () => state.input.system`），而每次派发都会重读注册表、覆盖 `state.input`（`domain/plugin-task-execution.js:74`、`:93`；`background-agent-sessions.js:309`）。
>
> **再进一步（同日，查 DSH 本体）**：DSH 的 `assemble()` 对段的文本是 `typeof section.text === "function" ? section.text(context) : section.text`——**函数每次组装都重新求值**；而组装发生在**每一步之前**（agent 循环里 `await this.loopCtx.systemPrompt.assemble(...)` 紧跟 `agent/pre-step`），`complete: true` 的段在瀑布之后被提为整份系统提示词（多于一个 effective complete 段会直接报错）。也就是说**没有任何"按会话缓存组装结果"的机制**，「下一轮结算生效」成立。

## 为什么

- **面板不能说谎**：玩家看到的就是模型念的，否则改半天白改——这是「不同步」困惑的根源；
- **重挂是唯一手段**：宿主没有「更新成员前缀」的接口，只有注册/卸载；
- **不硬改已有局**：成员前缀是本局缓存的一部分，绕过宿主去改会话里的前缀没有公开接口（也不该做）。

## 代价与边界

- **只对新的一轮生效，不是立刻**：保存时正在跑的那一轮已经派发过了，用的是当时的前缀；下一次派发才读到新的。不用新开一局，也不用重开 DSH；
- **重挂会丢缓存**：换文本就等于换前缀，下一次调用从零开始提示词缓存——所以文本没变时 `mountMember` 直接返回；
- **动态占位符仍不填**：面板里写的 `{{PERSON}}` 之类在成员前缀里不会渲染（[ADR 0095](0095-系统提示词拆固定与动态.md) 的拆分不变，动态上下文仍随工单发）；
- **恢复默认仍以 `prompt.js` 的内置文本为准**：面板清空保存 = 把 `PROMPT_TEMPLATE` 写回 txt 并重挂，玩家点「恢复默认」拿到的是**当前这一版内置规则**（`tests/promptTemplates.test.mjs` 守卫两者一致）。
