# ADR 0111 手动补写：面板上一个按钮，把最新一轮的写入再跑一次

- **日期**：2026-11-13
- **状态**：已定并已实现（未在真实对局上实测）
- **相关**：[ADR 0092](0092-判人与写入合并成一次调用.md)（判人与写入一次调用，补写重跑的就是这一次）、[ADR 0100](0100-后台成员交卷按派发时定的盒子.md)（自动写回是「射后不管」的后台任务，所以它会静默失败）、[ADR 0109](0109-交卷形状三层兜底.md)（交卷形状兜底，本次补写的搭档）

## 背景

自动写回是**后台异步**跑的（`onTurnSettled` 里 `runWriteback`，宿主不 await）。它会失败，而且失败是静默的：

- 模型交空（尤其 ADR 0109 修的那类「载荷被包了一层」早期版本）；
- 写回中途抛错（模型超时、宿主接口报错）——`index.mjs` 只 `log.warn` + 一条 `error` 调试记录，本轮就跳过了。

玩家那一轮的内容于是**永久缺一块**。补救办法只有两个：回退重跑那一轮（会连带重算 MVU、丢掉之后的进度），或者手动一条条补（面板能改，但一条条敲太费事）。

## 决定

面板「档案」页工具栏加一个**「补写这一轮」**按钮，走新 handle `character-archives/retry-writeback`：

1. **只补最新一轮**：轮次取自宿主 `getTurnState().turn`，正文、`textVersion`、**MVU 变量**都从 `getTurn({ gameId, turn })` 现取（这一轮可能被编辑/回退过，状态里那份可能过期；不传 MVU 的话，补出来的指针会挂上**上一轮**的旧游戏时间）。**面板不能指定轮次**——旧轮正文写进「现在」的状态会凭空冒出以后才发生的事（和 ADR 0110 是同一个坑）。
2. **复用 `runWriteback`**（D6）：判人 + 写入一次调用，跟自动结算走同一条代码路径。写入逻辑只有一份，不平行复制。
3. **不弹二次确认**（用户定的）：它不是危险操作——`applyWriteActions` 会先按「谁 + 栏目 + 内容」找已有命题，找到就复用（`lib/writeActions.js:122-138`），相同的说法不会写成两条；最多是把某条认知的态度/来源刷新成这次的结果。
4. **五种情况拒绝**：① 宿主 `busy`（生成中或结算中）——整局数据是**整份覆盖写**的，跟后台任务抢同一个文件会把结果冲掉；② **插件自己的自动写回／结算还在跑**（见第 5 条）；③ `settings.writeback.mode === 'off'`；④ 这一局还没结算过任何一轮；⑤ 读不到轮次（宿主没有 `getTurnState`，或返回值不是正整数——布尔/字符串冒充一律当读不到，`Number(true) === 1` 这种坑不能放行）。
5. **插件自己的占旗表（引用计数）**：宿主只在「前台生成／后台结算」时置 `busy`，它**不知道**插件自己的后台任务（`onTurnSettled` 的处理器它不等）。所以维护 `writebackInFlight`：键＝`局\u0000轮`（轮次严格正整数，字符串也归一），**用计数不用 Set**——同一轮可能有两处同时跑（自动结算＋补写、或重生成重投），Set 会被先结束的一方清掉。两条路径都 `writebackBegin`／`writebackEnd`：
   - **自动结算**：在处理器的**第一毫秒**占旗（`busy` 已经为假了，晚一步就等于放补写进来），`finally` 里在 `saveGameState`＋`publishState` **之后**才清（先清后落盘又是一条缝）；它开跑前也查一次旗——如果这一轮正被手动补写占着（重生成会重投同轮结算），**跳过这次自动结算**并记一条 warn。
   - **手动补写**：开跑前查旗（命中就回「这一轮的自动写回还在跑」），跑模型期间也占旗（防两个面板同时点，`retryLocks` 之外的第二道）。
6. **补写不做回退清理**：`runWriteback` 一进门会 `pruneAfter(turn)` 把「比这轮更晚」的快照挪走——自动路径需要它（刚回退过），补写不需要；万一玩家在跑模型期间推进了剧情，这一步反而会挪掉**刚写好的新一轮**。所以补写传 `prune:false`。
7. **同一局同时只许补一次**：模块级 `retryLocks` 集合挡双击／两头点。
8. **补写期间剧情推进了就作废**：跑完模型后再问一次 `getTurnState`；轮次变了**或读回来不是正整数**都算「作废」，**不**拿手里那份旧 `state` 整份覆盖回去（会把 `flags`／编号／`meta.updatedTurn` 写回过去），只把 `nextId` 抬到安全值（防人物编号复用，[ADR 0004](0004-信度来源用人物编号.md)）——抬编号这一步自己也套 try/catch，失败了记 `log.warn`（可能撞号，不能静默），再回一句「这次结果没保存（可以再点一次）」。
9. **回执用这一次的计数**：调 `runWriteback` 前先 `state.debugWriteback = null`——它在「本轮没有可写入的人」时会早退、根本不写这个字段，不清空就会把**上一轮**的数字当成本次结果报给玩家。
10. **补完推一次「档案变了」**：和自动结算共用 `publishArchiveChanged`，否则侧栏／另一个窗口里打开的面板一直是旧档案。
11. **失败回一句人话，不把面板打崩**：模型那边抛错时记 `log.warn` + 一条 `error` 调试记录（含 stack 前 4 行），并落盘保留这条记录；外层再兜一层 catch，读状态/读正文抛错也留痕。

**开场白允许补写**（明确记一笔）：宿主对开场白不发 `onTurnSettled`，所以第 1 轮的自动写回永远不会跑；开场白常常就是在介绍人物，玩家点一下就补上了，这是想要的。

handle 返回 `{ ok, turn, summary, counts }`（失败时 `{ ok:false, reason }`）；面板只用 `summary`／`reason` 两句人话。

判断与回执抽成纯逻辑 `lib/retryWriteback.js`：`retryRefusal({turnState, mode})` 与 `retrySummary(counts)`，可以脱离宿主单测。

## 为什么

- **为什么不自动重试**：自动重试要在后台再调一次模型，成本和等待都翻倍，而且失败往往是那一轮正文本身没什么可写的——交给玩家判断「这轮该不该有内容」更省。
- **为什么不做「挑一轮补」**：写入是「按当前快照算」，挑旧轮等于把过去的信息写进现在，还会和已经存在的后续轮次打架；要做就得引入一整套「从那一轮重建」的机制（回退的活儿），远超一个兜底按钮的范围。
- **为什么不弹确认**：确认弹窗是给**不可撤销**的操作准备的；补写可撤销（面板能删那条命题），而且频繁弹会让人不敢点——兜底按钮的价值就在「随手点一下」。

## 代价与边界

- **会对模型再收一次费**：每点一次就是一次后台模型调用（判人 + 写入合并成一次，所以只花一次）。
- **不是「替换这一轮」而是「再写一遍」**：已有的说法被复用，但模型这次换个措辞就会多一条新命题（这正是补漏的意义；不想要就在面板删掉）。
- **只覆盖「写回失败」这一种缺失**：写回成功但模型判断「这轮没什么可记」的，补写大概率还是空——那说明确实没什么可写，属于正常。
- **补写期间玩家推进剧情 → 这次作废**：结果不落盘、只抬 `nextId`，玩家可以再点一次。已经写下的第 N 轮快照会留在盘上——**但这不是完全无害**：快照里新加的命题若引用到这次才编号的字典条目，而那些条目没随状态落盘，回退到那一轮时那些值会显示成空（`decodeValue` 对缺号返回空串）。所以作废时**不要**指望这轮的补写内容还能用。
- **「抬编号」本身还有毫秒级窗口**：它是一次「读当前状态 → 改 `nextId` → 整份写回」，这中间若又有一轮结算落盘，仍可能被覆盖。窗口极窄，且失败会 `log.warn`（不静默）；彻底解决要把整局数据改成追加式/分片写，超出本轮范围。
- **旧 `textVersion` 会被宿主挡下**：补写期间正文被编辑/重生成时，`saveTurnData`／快照指针那一步会报「textVersion 不是这一轮当前显示的正文版本」，玩家收到的是可读的「补写失败：…」，**不是静默写错**（按宿主注释推断，未实测）。
- **`/debug` 里「各阶段快照」的 `writeback` 可能变成 `null`**：补写前清空 `debugWriteback` 是为了回执准确，代价是那一刻调试面板看不到上一次的计数（下一次结算会重新写）。
- **未实测**：本机没跑过真实对局；面板按钮的实际交互（点击 → 等待 → 回执）要装进酒馆、重启 DSH 后点一次才算验过。

## 守卫

- `tests/retryWriteback.test.mjs`（9 条）：三种拒绝（结算中／没结算过／读不到轮次）+ **自动写回在跑时拒绝** + 写入关闭 + 正常放行（含「结算失败但不在忙」也放行）+ 回执文案（正整数、全 0 的措辞）+ 拿不到计数不炸；
- `tests/hostWiring.test.mjs`（+2 条）：handle 复用 `runWriteback`、先问 `getTurnState`、落盘、`retryLocks`、**`writebackInFlight` 两侧都接**、剧情推进要作废、现取 MVU、补完推面板、不许面板指定轮次；面板上有按钮、调这个 handle、有「补写中」状态。
