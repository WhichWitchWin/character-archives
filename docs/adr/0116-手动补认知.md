# 0116 手动补认知：只能从已有命题里选；人名只从档案里选

- **状态**：有效
- **日期**：2026-11-22
- **supersedes**：无

## 背景

面板「他的认知」以前只能**改**已存在的行（内容、态度、来源、索引词、删除），**不能新增**：
玩家想手动补一条「李四知道张三在码头」，没有任何入口，只能等模型写。

另一个问题：「来源」原来是个**自由输入框**，玩家可以打任意人名。名字打错一个别名对不上，
后端 `sourceOf` 解析不了 → 整条 `update-pointer` 被拒，而界面上看不出为什么。

## 决定

### 1. 认知视图每栏加 `＋`，但**只能从已有命题里选**

点 `＋` 弹出一个下拉，列出**全体已建档人物的全体命题**（`人物 · 栏目：内容`），选中即给当前人加一条指针。

**为什么不在这里新写内容**：新内容要走「他是什么样」的 `＋`——那里有栏目存在性、
30 字上限、正文字典校验一整套。认知的本质是「**谁知道哪句已有的话**」；让它也能造内容，
等于开一条绕开全部校验的后门。

### 2. 认知的本质是指针，默认态度「未定」

新加的指针默认 `未定`（[ADR 0019](0019-信度默认未定.md) 的口径）：玩家只说了「他知道这件事」，
信不信由玩家再用下拉改。

### 3. 人名输入一律限制在已建档人物里

**来源**从自由输入改成下拉：`自己` / `未知` / 已建档人物名单（排除本人，选本人就等于「自己」）。

这条是通则：插件里任何「填人物名字」的地方都只给档案里已有的人，不允许自由输入——
写错名字只会得到一条静默失败的操作。

## 后果

- **收益**：跨人物认知能手动补了（以前只能等模型）。
- **收益**：来源不再因为打错名字而整条被拒。
- **代价**：`＋` 的下拉会列出全部命题，档案很大时这个列表会很长（本地渲染，点开才拉数据）；
  将来要按人物/栏目先筛。
- **边界**：补认知**不新建命题**；要新内容请去「他是什么样」。

## 被否决的方案

- **允许在认知里直接新写一条命题**：绕开栏目/长度/正文字典校验，还会制造重复命题。
- **来源继续自由输入 + 更强的提示校验**：治标；下拉是确定性的。
- **认知补一条时新建「关于某人」的命题并自动建两条指针**：动作含义不清晰，且和「他是什么样」的 `＋` 重复。
