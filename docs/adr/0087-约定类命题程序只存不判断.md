# ADR 0087 · 约定类命题：程序只存不判断

- **日期**：2026-11-04
- **状态**：已定；约定状态已实现（存在来源组第 4 格、模型报文字→程序存 0/1/2/3），召回引擎尚未接线
- **相关**：[ADR 0083](0083-写入流程-命题与指针.md)、[ADR 0005](0005-时间只记录不解析.md)、[ADR 0086](0086-召回冷却按指针记.md)

## 背景

栏目可以被玩家标成「**约定类**」（"明天卯时码头见""三日后交银"）。这类命题有"结局"：完成、过期、失败。

原来的想法（ADR 0083）是：程序按「约定轮次」判到期，成功就删、失败就转写。**这就等于让程序去理解约定**——而 `gt` 是原文（"明天卯时"），程序按 [ADR 0005](0005-时间只记录不解析.md) 根本不解析时间，判不了。

## 决定

1. **程序只存，不判断**。程序不会主动把约定类命题塞回给模型，也不判断它到底怎么样了。
2. **模型负责判断**。下一轮写入时，要求模型**改写这个约定的状态**。
3. **四个状态**（内部标记，语义值）：

   | 值 | 含义 |
   |---|---|
   | 0 | 没完成 |
   | 1 | 完成了 |
   | 2 | 过期了 |
   | 3 | 失败了 |

4. **状态记在「指向该约定命题的指针」上，各自独立**：
   - 主角知道这个约定 → 主角那条指针有状态；
   - 别人也知道这个约定 → 他也有自己的指针和状态；
   - 两个人判断不一致是**允许**的（他以为办成了、对方认为黄了）。
5. **不删除、也不封任何有效期**：状态只是标记。什么时候清理，另议。
6. **不设「到期该问了」的程序判断**：命题表里**没有**「约定轮次」这个字段（已删，和「结束轮」一起——两者都从来没被写过，是空字段）。
7. **约定状态存在「来源组」里**（组内第 4 格，可省略）：

   ```
   指针 = [人物id, 命题id, [ [态度, 来源, 游戏时间?, 约定状态?], … ], 最后变动轮]
   ```

   - 只有约定类命题的**那一组来源**才带第 4 格，普通认知没有。
   - **为什么不放指针级**：约定状态属于**这一次认知**——他可能听张三说办成了、听李四说黄了；两条来源本来就可以判断不一致。
   - **为什么不复用「态度」位**：一个人可以**相信**有这么一个约定（态度＝真），同时**认为它还没完成**（状态＝0）。挤一格会互相覆盖。
   - 没有游戏时间但有约定状态时，第 3 格用空串占位（`[态度, 来源, '', 0]`），保证第 4 格对得上。
8. **模型返回文字，程序映射成数字**：模型报「没完成／完成了／过期了／失败了」，程序存 0/1/2/3。守「内部码不进模型」——模型永远看不到数字码。

## 补充：约定类怎么召回（同日）

**只有一路：常规召回**——跟普通条目一样，跟在场其他人有关、或跟当前地点有关时才给（同一套场景优先级）。**约定类命题照样进常规池**（不因为它"是约定"就单独对待）。

> **2026-11-04 晚更新：周期提醒整条取消**。原方案（设置项「在场角色约定提醒轮次」＋ `(当前轮 − 立约轮) % N` 轮次比较）作废——理由：**如果这条约定跟在场的人、跟当前地点都没关系，那就不该被想起来**；常规召回已经覆盖"该想起来"的全部情况。相应地，那个设置项和 `disabledBy` 置灰机制都不再需要。
