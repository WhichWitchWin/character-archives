# ADR 0091 · MVU 人物字段映射退役，只留时间／地点兜底

- **日期**：2026-11-05
- **状态**：已定并已实现（**人物字段部分退役；将来可能加回来，见文末**）
- **相关**：[ADR 0005](0005-时间只记录不解析.md)、[ADR 0053](0053-快照地点与MVU勾选.md)、[ADR 0070](0070-预设表界面.md)、[ADR 0083](0083-写入流程-命题与指针.md)、[ADR 0090](0090-预设按卡存.md)

## 背景

「MVU 映射」原设计有两半：

1. **人物字段映射**：卡里 `人物[*].身份／关系／好感` 这些字段，按玩家勾选的表**原样抄**进档案的某个栏目（[ADR 0053](0053-快照地点与MVU勾选.md)、[ADR 0070](0070-预设表界面.md)）；
2. **时间／地点**：`时间` / `地点` 进快照头，只记录不解析（[ADR 0005](0005-时间只记录不解析.md)）。

第 1 半在实机上有两个硬问题：

- **认不出卡的形状**：字段发现只认 `stat_data.人物` **是数组**这一种写法。写成对象表（`人物: {老陈: {身份}}`）或换个键名的卡，映射表整片空白，玩家不知道该干什么；
- **抄了也白抄**：2026-11-05 之前它写进人物第 4 格（旧「条目」结构），而召回引擎只读命题表／指针表、面板也只读指针——**MVU 抄进来的值永远不被召回、也看不到**。把它改迁到命题＋指针（`mergeMvuIntoClaims`）虽然修好了，但也暴露出更根本的问题：**这套映射需要玩家逐字段配一遍，收益却和"让模型读正文写"重复**。

模型本来每轮都在读正文写命题，MVU 抄一遍等于同一件事做两遍，还多一份"信谁的"的歧义。

## 决定

**人物字段映射退役**。`stat_data` 里的人物字段不再抄进档案——**一律由模型读正文写入**（[ADR 0083](0083-写入流程-命题与指针.md)）。

**只保留时间／地点的兜底映射**：

| 项 | 做法 |
|---|---|
| 程序先自己找 | 时间：`statData.时间.日期／时刻／时段`；地点：`statData.地点`（字符串，或对象各值拼 `·`） |
| 抓不到才用映射 | 面板上两个下拉，选项来自这张卡 MVU 的**所有叶子路径**（如 `世界.当前时间`、`世界.位置`），每条带样例值 |
| 抓得到就绝不覆盖 | 自己已经抓到时间／地点时，玩家选的字段**不生效**——避免随手一选把好数据顶掉 |
| 存哪 | 整局数据 `state.mvuTimeLoc = { time, loc }`；空串＝自动 |
| 默认 | 两个都空＝完全按程序自己的规则，行为与退役前一致 |

删掉的：面板的字段勾选表、`applyChecklist` / `mergeMvuIntoClaims` 的调用、`mvu.checklist` 的生成。

**保留但不调用**：`lib/mvuMap.js` 的 `buildChecklist` / `applyChecklist` / `mergeMvuIntoClaims` / `mergeMvuIntoPersons` 全部留在原地并标 `@deprecated`，`state.mvuChecklist` 的读写也保留——旧数据不炸，将来要加回来时能直接接。

## 为什么

- **同一件事不用做两遍**：模型每轮都在读正文写命题，MVU 再抄一遍只会两边打架（"模型说他在码头，MVU 说他在船上"该信谁）；
- **配置成本极高、收益极低**：玩家得先让卡跑出 MVU 变量、再逐字段配栏目，配错了还静默失效；
- **卡的形状太杂**：数组、对象表、换键名、嵌套对象……插件猜不完，猜错就是整片空白且没有任何提示；
- **但时间和地点真的需要兜底**：`gt` 和 `loc` 抓不到时，"离场于 X"整段消失、每条认知也不带时间——这两个字段值得留一个简单的手动指定。

## 加回来的条件（写给将来的自己）

人物字段映射不是错的，只是**现在不划算**。重新考虑它的触发条件：

1. 出现**大量**非 MVU 卡也想玩这个插件，而模型从正文抽字段的准确率不够；
2. 或者需要"**MVU 是唯一真相源**"的场景（例如 MVU 侧有玩家手填、正文里没写出来的数据）——那时它不是"重复抄一遍"，而是**补充正文里没有的信息**，性质完全不同；
3. 加回来时**别再走旧路**：直接复用 `mergeMvuIntoClaims`（写命题＋指针），并先把「认不出卡形状」这件事解决掉（形状诊断已经在面板上了，见下）。

## 顺带留下的诊断

`presets-view` 返回 `mvu.survey`（MVU 一级键、形状、条目数、字段数）与 `mvu.ok` / `mvu.turn`。面板在没路径可选时会直接摊出这些——「这局还没结算过」「拿到的是第 N 轮」「MVU 顶层键：时间（map）、人物（3 项）」一眼可见。以后再遇到"映射表空白"，不用靠猜。
