# 0030 术语统一与模糊离场归程序

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0024](0024-建档提前.md) 中「判定＝程序初筛 + 模型对疑似名单确认」这一条

## 背景

### 1. 同一件事三个名字

| 出现在哪 | 叫什么 |
|---|---|
| 设计稿 §2 正文 | 强信号／弱信号 |
| 设置项 | 模糊离场判定轮数 |
| 提示词 | 疑似离场 |

写代码、读提示词、调设置时三处对不上，每次都要在脑子里翻译一遍。

### 2. 更要紧的：弱信号那一支其实是空转

原设计是「程序初筛出疑似名单 → 模型读本轮正文确认」。问题在于——

> 一个人既然已经"连续 N 轮没出现"，那**本轮正文里也不会有他**。

模型看到的是空手材料，只能回"正文没提到他"：既找不到"真走了"的证据，也找不到"还在"的证据。

### 3. 后果：这个人会永远卡在「在场」

提示词那一句是**条件句**：

> 「疑似离场」里的人：正文明确写了告别、离开、死亡 → 离场

条件不满足 → 什么都不做 → 这个人永远留在「在场」组。而**在场人物不召回**（[ADR 0024](0024-建档提前.md)），于是他的档案**永远召不回来**——正好把插件存在的意义抹掉。

而且这不是谁"决定"出来的规则，是提示词没写全的副作用：文档从来没写过"没提到怎么办"。

## 决定

### 1. 术语统一成两个词

| 旧 | 新 | 含义 |
|---|---|---|
| 强信号 | **离场** | 正文明确写了告别／离开／死亡／退场，当轮就判 |
| 弱信号 | **模糊离场** | 连续 N 轮没出现，程序数轮次判 |
| 疑似离场 | **废除** | 这个名字不再出现 |

设置项「**模糊离场判定轮数**」保持不变（默认 3，范围 1～5），现在和正文用词一致了。

### 2. 谁判分清楚

| 判什么 | 谁判 | 为什么 |
|---|---|---|
| **离场**（明确） | 模型 | 要读懂正文语义，程序读不懂 |
| **回场** | 模型 | 同上（正文写了他出现，程序只能靠名字匹配，容易漏） |
| **模糊离场** | **程序** | 纯数轮次；正文里没他，问了也是空手 |

**数够就判，不问模型。**

### 3. 提示词跟着改（详见 [系统提示词.md](../DESIGN.md)）

- 删掉「任务里列出的疑似离场被正文确认」这一条，改成**正向指令**：「正文明确写了告别、离开、死亡、退场（当场就能确认，不用等名单）」；
- 加一句边界：「模糊离场（连续 N 轮没出现）由程序数轮次判定，不归你管，也不会给你名单」；
- 每轮 followup 的【判定】素材里**不再带模糊离场名单**。

### 4. 提示词正文抽成独立文件

原来提示词全文写死在设计稿 §7.6.1 里，改一个字要动设计稿，还容易和代码常量对不上。

现在：**`docs/系统提示词.md` 是唯一真相源**，设计稿 §7.6.1 只说约束、不复制全文。

## 后果

- **收益**：模糊离场不会再"永远判不出来"；提示词少一段、少一个变量；改变判据只改一处。
- **代价**：模糊离场会误判——玩家其实还带着某人、只是这几轮正文没写他，也会被判离场。靠「已离场的人本轮明确在场 → 在场」**自愈**：下一轮他一露面就回来，离场记录清掉，档案内容一点没丢。
- **边界**：模糊离场判出的 `gt` 是**判定当轮**的游戏内时间，比真实离场晚 0～N 轮（[ADR 0005](0005-时间只记录不解析.md) 已接受这个偏移，正文本来也没写他什么时候走的）。
- **边界**：没有 MVU 现场名单的卡上，条件①「现场名单里没有他」不可用，只看「连续 N 轮没出现」。
- **回退**：回退到离场之前，离场记录要清掉（已写在 §3.6 回退表）。

## 被否决的方案

- **保留模型确认（现状）**：信息空转，还留一个"永远不判"的死角。
- **加第三状态「存疑」**：最准，但状态机多一档，设置项、回退表、召回池筛选都要跟着改，第一版不值。
- **继续用三个名字**：每次写代码都要翻译，迟早写错。
- **把模糊离场也算进「离场」，不再区分**：召回时要显示「离场于 X」，而模糊离场的时间精度本来就差，两者混一起会让人以为时间是准的。

## 待定

- 被误判离场的人如果被召回注入，玩家会看到「离场于 X」，但他其实在队里。目前靠手动改状态兜底，**要不要在被召回时加一句提示**（例如"状态可能有误，点这里改回在场"）——留到面板交互设计时再定。
