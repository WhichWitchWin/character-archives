# 0122 玩家称呼不再按卡存（收窄 ADR 0054）

- **状态**：有效
- **日期**：2026-11-22
- **supersedes**：无（**收窄** [ADR 0054](0054-身份设置按卡分区.md) 的适用范围）

## 背景

ADR 0054 让「身份设置」按卡 id 分区存在插件数据里：`identity["cards/改写权.json"] = { playerName, person }`。
里面其实是**两件不同性质的东西**：

| 字段 | 性质 | 按卡存对不对 |
|---|---|---|
| `person`（第几人称） | **这张卡的属性**：同一张卡无论开几局都是第二人称 | ✅ 对 |
| `playerName`（玩家称呼） | **这一局的属性**：同一张卡这局叫「小s」、下局可能叫别的 | ❌ 错 |

而酒馆本来就有权威接口 `ctx.tavern.getPlayerName({ gameId })`，我们自己的注释也写着「**酒馆是唯一真相源**」。
按卡存的那份于是变成一份**永远不会自动更新**的影子数据：

2026-11-22 实测：某张卡在插件里存着很久以前测试时的「测试人」，酒馆里早就是「小s」了。
开局头两轮酒馆还没初始化称呼 → `resolvePlayerName` 回落到那份旧值 → 主角先叫「测试人」，第三轮又变「小s」。
玩家看到的是「主角名字一直在变」，而三个名字（主角／测试人／小s）分别来自：兜底值、影子数据、真名。

## 决定

### 1. 新宿主：称呼只认酒馆，完全不碰 `identity`

```
有 getPlayerName 接口  → 只用它的返回值；读不到就返回**空串**（调用方保留原值，别覆盖）
没有该接口（旧宿主）   → 才读 identity.playerName 兜底
```

「读不到返回空」这一条是关键：空 ≠ 用旧值。`ensurePlayer` 已经配合改成
「已有主角时只有明确拿到称呼才改名」。

### 2. `person` 继续按卡存

它是卡的属性，这一点没错。`identity` 这个结构保留，只是**不再往里写 `playerName`**。

### 3. 面板「来源」下拉改用编号当 value

顺手修的相邻问题：来源下拉原来拿**名字**当 `<option value>`。名字会变（主角尤其），
改过称呼之后旧选项就对不上，选下去后端按名字找不到人 → 界面卡住。
改成编号 `p0`：`claim-picker` 的 `people` 带上 `id`，后端 `resolvePersonByName` 本来就认编号。

## 后果

- **收益**：称呼只有一个来源，不会再出现「档案里叫测试人、酒馆里叫小s」的双份数据。
- **收益**：酒馆第一轮还没初始化称呼时，主角保留原名而不是被写成兜底值／旧值。
- **代价**：`identity` 里那条历史 `playerName` 变成**死字段**（新宿主不读不写）。留着无害，不做迁移清理——
  删字段要动玩家数据，收益只是"看着干净"。
- **边界**：旧宿主（没有 `getPlayerName`）仍然依赖这份存档；那类宿主已经很少。
- **边界**：面板「本局设置」改称呼时仍会调 `ctx.tavern.setPlayerName` 写回酒馆——那是对的方向。

## 被否决的方案

- **把 `playerName` 改成按局存**：又多一份影子数据，还要跟酒馆同步；酒馆本来就有接口，没必要。
- **一次性清掉 `identity` 里的 `playerName`**：动玩家数据、收益只是整洁，风险不对等。
- **`ensurePlayer` 继续用兜底值覆盖**：那正是"名字横跳"的直接原因（上一轮已修）。
