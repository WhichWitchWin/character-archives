# 0009 条目定义加 fromTurn，回退确认后清理并回收码

- **状态**：已采纳
- **日期**：2026-10-31
- **supersedes**：ADR 0008 中「回退后条目变空而不是消失」这个降级的接受

## 背景

ADR 0008 把该局的条目定义放进整局数据，代价是：**回退到「那时还没有这个条目」的轮次时，会看到一个空条目**（有定义、没值），偏离设计稿 §3.6「从当前人物册删掉该条目」。

要修这个问题，需要知道「什么时候删除是安全的」。用户确认了平台行为：

> **回退之后如果又运行了一轮，就不能再撤销回退了。**

有了这条，删除的时机就明确了。

## 决定

### 1. 条目定义加 `fromTurn`

```js
entries: {
  xa: { name: '口头禅', prompt: '…', unique: false, mode: 'value', fromTurn: 10 },
}
```

- **显示与匹配时按轮次判断**：当前轮 `< fromTurn` → 视为不存在；
- 撤销回退回到后面的轮次 → 又出现（定义还在）。

### 2. 回退时不动定义

`onTimelineChanged` 收到 `kind: 'rollback'` → 只记一个标记 `rollbackAt = 回退到的轮次`。此刻还能撤销回退，**绝不删**。

### 3. 撤销回退时清标记

`kind: 'undo-rollback'` → 清掉标记，什么都不做。

### 4. 回退后第一次 `onTurnSettled` → 清理并回收码

这时未来已经被新内容覆盖、撤销不回来了，于是：

- 删掉所有 `fromTurn > rollbackAt` 的条目定义；
- 删掉的那几个码**回到空闲池**，可以分给新条目；
- 清掉标记。

### 5. 为什么这时回收码是安全的

当前时间线上还活着的快照，最晚只到 `rollbackAt`。而要被删的条目 `fromTurn > rollbackAt` ——

> **第 `rollbackAt` 轮及以前的快照，不可能引用这些码。**

引用它们的那些快照（`rollbackAt` 之后、被回退丢掉的）已经不在时间线上了。所以码空出来给新条目，不会让任何历史快照解错。

## 后果

- **收益**：空条目问题消失；被丢弃未来的条目不会永久占着码；完全符合 §3.6 的语义。
- **代价**：依赖两条平台行为 ——
  1. `onTimelineChanged` 能可靠收到 `rollback` / `undo-rollback`（文档已确认，见 `plugin-api-game.md:166`）；
  2. 「回退后运行一轮即不可撤销」—— 这条由用户实际操作确认，**本机未做自动化验证**。
- **边界**：如果玩家回退后**没有再运行**就关掉游戏，标记会留在整局数据里；下次进入后第一轮结算时照常清理，行为一致。
- **被否决的方案**：
  - *回退时立即删除*：会毁掉撤销回退。
  - *永不删除，只靠 `fromTurn` 隐藏*（ADR 0008 的降级）：码永久被占，长期玩会耗尽 26 个自建槽。
