# 0118 手动改过的认知豁免一次冷却

- **状态**：有效
- **日期**：2026-11-22
- **supersedes**：无（补充 ADR 0086 的冷却规则）

## 背景

召回冷却的规则是「刚变过的东西歇 N 轮」（ADR 0086，默认 10 轮）。它对模型自己写的东西是对的，
但**对手动编辑正好反过来**：玩家刚在面板上改了一条，往往就是想让它下一轮被念到——
结果冷却把它压住了，表现成「我改了，模型还是不记得」。

受影响的五个入口：

| 入口 | 为什么会被冷却压住 |
|---|---|
| 加一条命题 | 新建指针天生带着「最后变动轮＝本轮」 |
| 补一条认知（新建指针） | 同上 |
| 改命题内容 | 内容变了，但指针的最后变动轮没变——看着不该压，实际是否被压取决于这条本来凉没凉 |
| 改索引词 | 同上 |
| 改态度／来源 | `update-pointer` 会把指针第 4 格推成本轮 → 必然冷却 |

## 决定

### 1. 标记存在 `flags.manualFree`，键与冷却表同格式

`manualFree = { "pt:p1:9": true }`，键就是 `pointerKey(personId, claimId)`。

放 `flags` 而不是快照：它是「等下一次召回」的临时状态，不该跟快照一起回退。
（也因为键与冷却表同格式，两边的清理代码长得一样，不容易写歪。）

### 2. 五个入口都打标记；「改成一样的不算」

`add-claim`／`add-cognition`／`update-claim`／`update-claim-words`／`update-pointer`，
在**真的改了**之后才打。三个 update 入口原本没有「改没改」的判断（只有面板拦了一层），
现在宿主侧补上：改成一样直接返回 `{ ok: true, unchanged: true }`，不打标记也不写盘。

### 3. 粒度：改命题影响所有指向它的指针，改指针只影响那一条

- 改**命题内容／索引词** → 所有指着它的指针都打（念出来的字变了，谁都该能念新的）
- 改**态度／来源** → 只打那一条（只动了这一条认知）
- **新建**命题／认知 → 只打新建的那一条

### 4. 判定时两道闸一起跳过

冷却其实有两道闸：冷却表的 `until`，以及指针第 4 格「最后变动轮」。`cooldownGate` 在
标记存在且确实处于冷却中时，两道闸都放行。

**为什么不直接把 `pointer[3]` 往前拨**：那一格还兼着两个职责——召回同分排序（越新越靠前，
`recallEngine`）与面板人物排序（`panelView`）。往前拨会让它反而排到后面，和「想让它快点被念」
正好相反。

### 5. 标记的三种死法

| 情形 | 处理 |
|---|---|
| **真被念进了提示词** | 删（`manualFreeUsed`） |
| **冷却自然到期了**（本来就能念） | 删（`manualFreeStale`）——标记没用了，留着只是垃圾 |
| **指针／命题／人被删** | 删（`dropPointerManualFree`／`dropClaimManualFree`／`dropPersonManualFree`） |

**「念进提示词」的判定要严**：被预算砍掉的块不算（`buildRecallSection` 先记候选、
最后按真正进了文本的指针过滤一遍）。删早了等于白改。

### 6. 别的原因没念，标记保留

人不在场、栏目没勾、眼睛闭着、预算不够——这些都不让标记失效，因为**冷却还在**，
标记还等着起作用（等他回来再用）。所以这些原因下既不报 `used` 也不报 `stale`。

### 7. 只有真注入的两条路消费标记

- 自动召回（`buildRecallSection`）✓
- 面板「召回」按钮（`buildPendingRecallText` → `queryPerson`）✓
- 面板「查认知」（`queryPerson` 不传 `manualFree`）✗——它只是给人看一眼，什么都没进正文，
  不该把玩家的豁免额度用掉

## 后果

- **收益**：手动加／改的东西下一轮就能被念到，符合直觉。
- **收益**：标记会自己消失（念过／没用／被删），不会无限堆积。
- **代价**：手动编辑可能多一次 `saveGameState`（改命题内容时本来只写快照）。
- **代价**：多一张需要跟删除对齐的旁挂表——所以五处删除点都补了清理与守卫。
- **边界**：豁免只管冷却。在场、栏目勾选、眼睛、预算照旧管得住（ADR 0114 那三层眼不变）。

## 评审修正（同一天，2026-11-22）

只读评审抓出五处，已修：

1. **批量删认知的清标记是空转**（最严重）：`dropCognitions` 返回的是**数字数组**，原代码按
   `item.claimId` 取 → 键变成 `pt:p1:undefined`，一个真标记都删不掉；而且「长度没变化」连盘都不写。
   新增 `dropPointersManualFree(bucket, personId, claimIds)` 直接吃数组，单条路径也用它。
2. **标记带轮次**：值从 `true` 改成「打标记时的轮次」。`pruneFutureFlags` 据此清掉「未来」的标记——
   回退之后命题号会被复用，残留标记会让一条本该冷却的新认知被误豁免。老数据的布尔值认不出来就留着。
3. **导入要清**：`pendingImport` 落地时是**整份换档案**，命题号全变了，`cooldowns` 与 `manualFree` 一起清。
4. **写标记前重新读一次整局数据**：原来把入口开头 load 的 state 整份写回，写回任务
   （`onTurnSettled`）期间玩家的改动会被它盖掉——那正好是这条功能要治的病。改成 `loadGameState` 后再改标记。
5. **撤回时也清那条指针的标记**：原来只在「整条命题被删」时清，别人还知道这条命题时会残留。

顺手修掉两处相邻的老问题：删人没清 `state.cooldowns`（命题号复用会无故冷却新命题）、
`update-claim-words` 的「改成一样」按整个对象比（面板重建的词类别是 `null`，会把「词没变」
误判成变了，还顺手抹掉原类别——改成只比词）。

**已知边界（有意不修）**：

- 主角（`p0`）的标记在自动召回里不会被消费——主角走「回场全量」那条路，本来就不看冷却，
  标记要等面板召回或删命题才消失（有界泄漏，无害）。
- 召回模板被玩家改成不含 `{{BLOCKS}}` 时，「没进文本」会被算成用掉（模板改坏才会发生）。
- 正文模型的 `archive_query` 工具是第三条会进上下文的路径，但它**不消费**标记——见"待定"。

## 待定

`archive_query`（正文模型自己查档案）的返回也会进模型上下文，并且会给查到的指针盖冷却章。
它要不要消费豁免标记？消费 = 手动改的东西被模型查一次就回到正常冷却；不消费 = 模型查过之后
玩家改的那条仍然能插一次队。**未定，等玩家拍板。**

## 被否决的方案

- **手动编辑时把 `pointer[3]` 拨到 `turn - turns`**：省掉标记，但破坏排序语义（见决定 4）。
- **手动编辑时直接删冷却表记录**：只关掉一道闸，`pointer[3]` 那道还挡着；而且冷却表
  `pruneExpired` 只认 `until`，塞特殊记录会被当过期清掉。
- **标记打在命题上**：`update-pointer` 只动了一条指针，打在命题上会让**别人**记得的同一条
  也跟着插队（例：改了张三对「职业」的态度，李四的也提前被念）。
- **「改成一样」也算改过**：玩家手滑点一下就把一条冷却中的认知提前放出来，行为不可预期。
