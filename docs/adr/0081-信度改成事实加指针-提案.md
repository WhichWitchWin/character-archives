# 0081 信度改成「命题 + 指针」两层（提案，未定稿）

- **状态**：提案（**未定稿，别当结论用**）
- **日期**：2026-11-03
- **相关**：[ADR 0019](0019-信度拆成两维.md)、[ADR 0020](0020-写入判断带上视角说明.md)、[ADR 0023](0023-值级动作集与输出格式.md)、[ADR 0044](0044-姓名升到人物级别.md)、[ADR 0082](0082-召回改成在场人物认知指针-提案.md)
- **起因**：第三人称全知视角下，现有信度体系失效

## 修订记录

| 日期 | 改了什么 | 为什么 |
|---|---|---|
| 2026-11-03 | 第一层「事实」改名「**命题**」 | 值可以是「某人以为的」，不一定真发生过。A 骗 C 说「B 在旧港」，这条值得存在，但它不是事实。叫「事实」会让人以为这一层只存真相 |
| 2026-11-03 | 边界加第 7 条：**不记「谁知道谁知道」** | 认知链会爆炸。公共知识被推翻时（「世界有神」→「没有神」），每个人都要对每个人各有一条指针，N² 起步。二阶认知只在正文明确写出来时，作为一条普通命题记 |

## 背景：现在的信度是「主角视角」

现有信度 = 来源（用户／自述／他述）× 真值（真／未定／假）：

- 「用户」= **主角**亲眼见到／亲耳听到
- 真值 = **主角**信不信

**崩的地方**：第三人称切到主角不在场的场景（反派密谋、支线），主角既没看见也不知道，但正文写得很清楚。这时真值只能标「未定」，模型读到的却是"这件事不确定"——**「未定」被两个意思共用了**：真的不确定 / 主角不知道。

## 方案演变（三个版本，前两个被推翻）

| 版本 | 想法 | 为什么不行 |
|---|---|---|
| ① 每条值 = 该角色的认知 | 删掉「主角视角」，每条值都是"这个角色以为的" | 「主角认为张三叫什么」无处安放；人物名字若主观化，系统认不出人 |
| ② 加世界事件表 | 建独立事件节点，各人认知指向它 | **变成完整记忆馆**；而且「该不该记」没有可操作的判断标准 |
| ③ **命题 + 指针**（当前） | 命题层存一份，指针层各人一份 | ← 就是下面这套 |

## 最终模型：三层

### ① 命题层（全局一份）

| 字段 | 说明 |
|---|---|
| **ID** | 给指针指路（不能靠文字匹配：「老陈在医馆」和「老陈待在医馆」得是同一件事） |
| **内容** | 一条**命题**：有人提过、有人信过的一句话。**不保证为真** |
| **有效期** | 从第几轮到第几轮。**命题会过期，旧的不能删**——它历史上成立过 |

### ② 指针层（每个角色一份）

| 字段 | 说明 |
|---|---|
| **指向** | 哪条命题（命题 ID） |
| **状态** | **真 / 假 / 未知** |
| **来源** | **自己**（该角色本人的认知，不限于亲眼所见）／**某人**（标名，那人告知他形成的认知）／**未知**（路人、信、书、传闻，或任何不在写入素材里的人） |

### ③ 人物标签（客观）

姓名、别名、在场状态——系统靠它认人，**永远是客观的**（[ADR 0044](0044-姓名升到人物级别.md)）。

## 存储结构（2026-11-03 定）

命题表和指针表**扁平存放**，不嵌套在人物档案里；程序加载时建三个内存索引，查询走索引，**持久化仍是 JSON**（能直接看、能导出、回退机制不动）。

```js
// 命题表：一条命题一行
snapshot.claims = [
  [id, 所属人物, 栏目码, 内容, 起始轮, 索引词],
]

// 指针表：一条认知一行
snapshot.pointers = [
  [人物id, 命题id, 状态, 来源],
]
// 状态：0 真 / 1 假 / 2 未知
// 来源：'' 自己 / 'p7' 某人 / '?' 未知来源
```

内存索引（加载时建，不落盘）：

| 索引 | 用途 |
|---|---|
| 人物 → 指针列表 | 召回：这个人知道什么 |
| 命题 → 指针列表 | 反查：谁相信这件事 |
| 人物＋命题 → 指针 | 写入：去重与覆盖判断 |

**为什么不用 SQLite**：迁移成本（回退要重做、导出要重写、不能直接看）大于收益。当前快照 0.4 KB，真实规模约 200 KB 级，每轮写入约 1 ms——瓶颈不在存储引擎。

## 三态的实际含义

| 情况 | 怎么记 |
|---|---|
| **根本不知道这件事** | **没有指针** |
| 听说了，但拿不准 | 指针·**未知** |
| 他信了 | 指针·**真** |
| 他认为是假的 | 指针·**假** |

**「没指针」和「未知」是两回事**——这就是三态必须保留的原因（用户 2026-11-03 明确要求）。

## 关键：撒谎 vs 疯了，自动分开

| | 他的指针 | 他说出口的话 |
|---|---|---|
| **撒谎** | 假（他知道真相） | 说成真的 |
| **疯了／记错** | 真（他信错了） | 说成真的 |

同样是"说了假话"，**指针状态不同就能分辨**。用户举的例子：

> 张三疯了，以为自己在酒店，实际在山洞。
> - 命题层：`张三在山洞`
> - 张三的指针 →「我在酒店」：**真**（他信）
> - 李四的指针 →「张三在酒店」：**未知**，来源＝张三
> - 李四去酒店扑空 → 李四的指针变 **假**
> - 李四找到山洞 → 李四的指针 →「张三在山洞」：**真**，来源＝自己
> - **张三没有指向山洞的指针**（他不知道自己在哪）
> → 李四一对照张三疯了的状态：张三不是骗我，是真疯了

## 另一个例子：老陈从医馆到仓库

| 时刻 | 命题层 | 指针层 |
|---|---|---|
| T1 | F1：老陈在**医馆**（有效 T1~T3） | 老陈 → F1：真 |
| T2 昏迷 | F1 仍成立 | 老陈 → F1：**未知**（不知道自己在哪了） |
| T3 被搬到仓库 | **F2：老陈在仓库**（有效 T3~） | 王五 → F2：真 |
| T4 王五骗主角 | F1、F2 都在 | 主角 → **F1**：真，来源＝王五 |
| T5 主角扑空 | | 主角 → **F1**：**假** |
| T6 老陈醒来 | | 老陈 → F1：**假**；老陈 → **F2：真**（新得到） |

注意 T6：老陈醒来会**新得一条**「我在仓库」的指针——旧的那条变成"假"。

## 已确认的边界

1. **姓名、别名、在场状态保持客观**——系统靠名字认人
2. **不单独建「世界事件表」**——世界事件就是命题层，不需要第二套结构
3. **不单独存「主角对别人的看法」**——它本来就是指针，不需要额外栏目
4. **一/二人称、第三人称下主角都可以建档**，主角就是普通人物
5. **同栏目多值不能砍**——一件事很多人有不同说法
6. **在场由模型从正文判断**——写入只给"可能在场的人"，模型自己看正文
7. **不记「谁知道谁知道」**——只记「某人知道某条命题」，不记二阶及以上的认知链。**理由：公共知识会爆炸**——一件大家默认都知道的事（「世界有神」）被推翻时，每个人都要对每个人各有一条指针，规模 N² 起步。二阶认知只在**正文明确写出来**时，作为一条普通命题记下（「A 说：C 也知道」）
8. **命题一律写成正向陈述**——「B 没死」不是一条新命题，而是命题「B 死亡」＋ 某个人的状态「假」。这样不用做自然语言反义判断（2026-11-03 用户定）

## 写入规则（2026-11-03 定）

| # | 规则 | 决定 |
|---|---|---|
| ① | 「知道」的门槛 | **模型判断**——正文写了他听到／看到才算，不自动给全场人加指针 |
| ② | 状态默认值 | **未知**——都是听说的，模型没写"他信了"就落未知 |
| ③ | 说话人自己的指针 | **不建**——说话人已经出现在听者的「来源」字段里，再给他一条指针是重复表达 |
| ④ | 值什么时候过期 | 待聊（清理话题） |
| ⑤ | 孤儿值留不留 | 待聊（清理话题） |
| ⑥ | 「公开」标记 | **不设**——公开的范围无法界定（广场上的人该知道、深山老林的人不该知道），而且本插件只记非龙套人物 |
| ⑦ | 指针怎么产生 | **传播即建**：一个人告诉另一个人，听者才建指针（来源＝说者，状态＝未知）。没人告诉 → 没有指针 → 不知道 |
| ⑧ | 重复告知 | **同一人对同一条命题只有一条指针**，重复告知不新建 |
| ⑨ | 覆盖规则 | **自己确认过的不能被别人的说法覆盖**——来源＝自己 ＋ 状态＝真 的指针，别人再怎么说都不改 |
| ⑩ | 「自己」的范围 | **该角色本人的认知**，不限于亲眼所见／亲耳听到——他自己的判断、记忆、推理都算 |
| ⑪ | 认知提供人 | **不单独建指针**——他提供的认知已经出现在接受者的「来源」里；除非他自己也有对这条命题的认知，那就按他自己的流程走 |

## 未定项

1. **来源用词**：`自己／某人／未知来源`（已定），但「某人」是否只限建档人物？
2. **同栏目多值上限**：现在详细档最多 2 条，三个人的说法装不下
3. **值的粒度**：「老陈在医馆」这种状态算一条命题，还是只记"事件"（被搬到仓库）？
4. **旧数据迁移**：现有 9 个信度码怎么映射到「命题 + 指针」
5. **值的过期与孤儿值**——留到「清理」话题

## 待验证

- 数据量：命题 M 条 + 指针（只存"知道的"，不是 N×M）
- 检索：仍按人物扫，指针不增加主路径成本
- 模型每轮写两层的准确率（这是最大风险）
