# 0113 条目锁与值锁：三层继承，不许子比父宽

- **状态**：有效
- **日期**：2026-11-14
- **supersedes**：无（补 [ADR 0037](0037-锁与眼睛解耦.md) 留下的「条目/值锁的继承与冲突」待定项）

## 背景

[ADR 0037](0037-锁与眼睛解耦.md) 把 🔒 锁定成「只管写入、不影响召回」，但当时只有**人物级**锁：
要保护单条内容，只能把整个人锁上，代价是他的其他条目也不再更新。条目层与值层的锁延后到
[ROADMAP](../ROADMAP.md) M5-6，并留下一条待定：**「人物锁上、条目解锁」这种子比父宽要不要允许**。

[ADR 0038](0038-锁的写入边界.md) 又留了同类问题：条目/值锁要不要「不进写入素材」。

## 决定

### 1. 三层锁，粒度分别是人物 / 条目 / 值

| 层 | 键 | 锁住的范围 |
|---|---|---|
| 人物 | `p7` | 他整本档案 |
| 条目 | `p7:a`（人物 × 栏目码） | 这个人在这一栏下的所有值 |
| 值 | `12`（**命题 id**） | 这一条命题 |

存储都在整局数据：`flags.lock`（已有）、`flags.lockEntries`、`flags.lockClaims`。
**不写快照**——回退时锁保持原样，跟人物锁同一套（ADR 0037）。

### 2. 不允许「子比父宽」

人物锁上时，他下面的条目与值**一律算锁住**，不管它们自己有没有单独上锁。

**为什么**：允许子比父宽，面板就会出现「人物锁着、但某个条目显示未锁」。玩家会以为
那一条能改，写完才发现被丢弃——这比"少一个自由度"更糟。想单独解锁某条，先解人物锁。
界面上把这种情况做成**禁用**而不是"点了没反应"。

### 3. 值锁锁的是**命题**，不是「某人 × 命题」

命题在结构上是**全局扁平一份**（[ADR 0081](0081-信度改成事实加指针-提案.md)），改它就是
改所有人看到的内容。所以「值锁」保护的是那条命题本身，不按"谁记得它"分开锁。

**推论**：别人想给一条被锁的命题**加认知**（指针），动作里的 `关于` 也得写命题的主人，
所以同样会被条目锁/值锁挡住——这与「锁住的内容不进写入素材」是一致的。

### 4. 锁只挡模型，不挡玩家

- **写入**：命中锁的动作整条丢弃，并写进 `bad`（带原因「…锁着，不写」），调试日志单独报
  「因锁丢弃 N 条」；
- **召回**：照常注入（ADR 0037 不变）；
- **面板手动编辑**：照常可以改（玩家改自己写的东西不该被拦，同 [ADR 0098](0098-认知模型四个旋钮.md) 的口径）；
- **改状态**：不受影响（人物锁那套规则直接沿用，ADR 0038）。

### 5. 锁住的内容不进【写入】素材

锁住的条目/值不列进写入素材。**并且**锁住的栏目**不算「这些栏目还空着」**——不这么做，
模型会以为那栏是空的、拼命往里写，而每一条都会被丢弃，纯烧 token、日志还吵（ADR 0038 同一理由）。

## 后果

- **收益**：能精确保护某一条手写内容，不必冻住整个人。
- **收益**：锁住的内容在素材里消失，锁得越多省得越多。
- **代价**：三层锁的语义要玩家理解一次（面板用 tooltip 说明「随人物锁」「随栏目锁」）。
- **边界**：值锁按命题 id，不是「某人记得的这条」——同一条命题被锁，所有人都写不进它。

## 被否决的方案

- **允许子比父宽**：面板语义会骗人（显示未锁、实际写不进），见决定 2。
- **值锁锁「人物 × 命题」**：同一条命题会同时存在两种锁状态（这个人锁了、那个人没锁），
  而内容只有一份——状态互相矛盾，无法解释"谁能改"。
- **锁住的内容也不给召回**：那是眼睛（👁）的职责，与锁职责不同（ADR 0037 已把两者解耦）。
- **锁住就完全不给模型看（连判定素材也不给）**：判离场/回场还需要看他（ADR 0038 已定）。
