# 0079 删掉「容量」设置组

- **状态**：有效
- **日期**：2026-11-03
- **相关**：[ADR 0057](0057-自持文件存储.md)、[ADR 0058](0058-数据放插件数据区.md)

## 背景

设置页「容量」组有两项：

| 项 | 默认 | 原意 |
|---|---|---|
| `capacity.hintPercent` | 60 | 档案用到酒馆容量的百分之多少时提醒玩家 |
| `capacity.keepTurnsOnCompact` | 10 | 酒馆压缩历史时，最近几轮快照留着不用重算 |

两件事凑一起，它们就没意义了：

1. **它们从来没被读过。** 全项目搜 `hintPercent` / `keepTurnsOnCompact`，只出现在「默认值定义」和「界面元数据」两处——业务代码一次都没引用。**玩家改了，什么都不会发生。**
2. **容量约束本身没了。** 快照和整局数据都写自持区文件（ADR 0057、0058），酒馆里只剩几十字节的 `{f,h}` 指针。没有"快满了"，也没有"酒馆压缩我们的历史"这回事——快照窗口由 `DEFAULT_KEEP_TURNS = 200` 自己管。

## 决定

整组删掉：

- `settings.js`：`DEFAULT_SETTINGS.capacity` 与 `SCOPE.capacity`
- `settingsView.js`：`SETTING_SCHEMA` 里的「容量」组与 `GROUP_SCOPE.capacity`
- `DESIGN.md` §8.6 设置表里对应的两行

旧存档里残留的 `capacity` 字段**不迁移、不清洗**：`resolveSettings` 只按已知键合并，多出来的字段被忽略，不会报错也不会显示。

## 后果

- **收益**：设置页少两个"改了没用"的旋钮。死设置比缺设置更伤人——玩家会以为自己调了参数。
- **收益**：少一处文档与代码对不上的地方。
- **代价**：无。删的都是没人读的东西。

## 一并清理

`plugin/lib/capacity.js` 与 `tests/capacity.test.mjs` 是同一批退役逻辑的残骸——整套"酒馆容量水位"（单条 64 KB、每局 8 MB、整局数据 256 KB、快照 2000 条、以及各档提示/清理阈值）。**没有任何地方 import 它**，已连同测试一起移入回收站（不硬删）。

## 待定

- `DESIGN.md` §3.2／§3.5／§3.6 讲的是酒馆容量上限与"容量事件"。其中 `savePluginData` 的 256 KB、`handle` 参数 256 KB 仍然有效，但"整局 8 MB / 单份快照 64 KB"已经被自持存储绕开——那几节要不要按现状重写，单独再定。
