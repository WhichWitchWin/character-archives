# 0035 「候选」改名「模糊建档」

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：无（术语变更，不动任何旧结论）

## 背景

「候选」这个词在项目里被**两套完全不同的东西共用**：

| 用法 | 含义 | 例 |
|---|---|---|
| **候选（人物）** | 还没够格建档、但已经露过脸的人，先记在一张轻名单上 | `{ "动作":"候选", "姓名":"卖炭翁" }` |
| **候选（值／条目）** | 同一个条目的多个备选值；MVU 映射里的备选条目名 | `candidates`、「同一条目码可重复出现，表示有多个候选值」 |
| **候选（召回消歧）** | 同名人物分不清时列出让玩家选 | 「分不清则列候选或不召回」 |

写提示词、读设计稿、看代码时，同一个词指三件事，很容易说岔。

而「候选」这个说法本身也没说清它是什么——听起来像是在"等投票"，实际是**"还不够格建档，但先记着"**。

## 决定

### 1. 人物那一套改叫「模糊建档」

- 动作名：`候选` → **`模糊建档`**
- JSON：`{ "动作":"模糊建档", "姓名":"…" }`
- 素材段：`【候选人物】` → **`【模糊建档】`**
- 判据③里的「候选表」→「模糊建档表」

「模糊」对应"还不确定要不要建"，和已有的「模糊离场」是一套语感：**拿不准的，先模糊处理。**

### 2. 另外两个「候选」不动

- 值／条目的多个备选值 → 仍叫「候选值」（这是通行叫法）
- 召回消歧时列的名单 → 仍叫「候选」

它们跟"人物观察名单"没关系，改名反而更乱。

### 3. 旧 ADR 不动

[ADR 0033](0033-判定素材删除已建档名单.md) 里写的「【候选人物】」保留原文（G3④ 只增不改）。**新名字以本 ADR 和设计稿为准。**

## 后果

- **收益**：人物那套有了专属名字，不再和"候选值"「召回候选」撞车；「模糊建档」比「候选」更能说明它是什么。
- **代价**：多一个需要记的词；代码里将来解析动作时要认 `模糊建档` 这三个字。
- **边界**：**只改名字，行为一点没变**——什么条件下报、报了之后怎么办、存哪、怎么清，全都还是原来的样子（其中"存哪、怎么清"本来就没定，见下方待定）。

## 被否决的方案

- **全篇把「候选」都换成「模糊建档」**：会误伤候选值、MVU 候选条目、召回候选名单，反而更糊涂。
- **改叫「临时档」**：容易被理解成"已经在档案里了"，但模糊建档的人**还没进档案**。
- **改叫「观察名单」**：意思对，但和其他术语（离场／模糊离场／索引词／沉降）不成体系。

## 待定

模糊建档**自己的规格仍然是空的**（这次只改名，没补规格）：

1. 存在哪、什么格式？（早先记的 TODO：整局数据 `{姓名, 首次出现轮, 次数}`）
2. 谁更新「已出现轮数」？现在的时序只写了"程序扫已建档人物"，没写扫模糊建档的名字。
3. 怎么清理？没有任何过期机制——已建档人物有沉降（20 轮沉底），模糊建档反而没有，会无限攒。
