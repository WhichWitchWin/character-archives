# 0056 玩家称呼改为以酒馆为准（issue #464 接口）

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0055](0055-身份设置按卡存.md) 的「平台限制：抓不到玩家称呼」一段

## 背景

ADR 0055 当时查遍四个接口（`getTurnState` / `getRequestContext` / `getCardContext` / `getCard`）都拿不到玩家称呼，真值在 `chat.macroState.userName`，没暴露给插件。于是做成了"留空 + 手填 + 按卡记住"。

随后提了 [dsh-tavern#464](https://github.com/flizzywine/dsh-tavern/issues/464)，作者当天补了接口（commit `2747b48`、`3937b1b`）：

| 接口 | 作用 |
|---|---|
| `getDefaultPlayerName()` | 全局「默认玩家称呼」 |
| `getPlayerName({ gameId })` | **本局**当前称呼（`{{user}}` 的值）——作者建议用这个 |
| `setDefaultPlayerName({ playerName })` | 改全局默认（只影响**新游戏**） |
| `setPlayerName({ gameId, playerName })` | 改本局称呼 |

要点（原话摘录）：

- 每次调用都读最新值；**未设置时返回 `"你"`**；
- 返回的是**称呼本身**，不是别名列表——正文里的第二人称「你」仍需插件结合语境排除；
- `playerName` ≤80 字，去首尾空白，空串恢复为「你」；
- 本局修改在**正文生成或后台结算期间**会报 `TAVERN_PLUGIN_BUSY`；
- 卡内插件**不能**改全局默认值。

## 决定

### 1. 读：酒馆是唯一真相源

三级兜底：

```
1. ctx.tavern.getPlayerName({ gameId })   ← 有就用（玩家可能改过，优先本局值）
2. 我们自己的按卡记录（插件数据）          ← 旧宿主没有接口时
3. 空串                                    ← 都没有就不参与「拒建同名」，免得误伤
```

**用 `getPlayerName` 而不是 `getDefaultPlayerName`**：作者明确建议——玩家可能在开局或本局设置里改过称呼，全局默认值未必是这一局用的。

### 2. 写：面板改称呼 = 改酒馆的本局称呼

玩家在档案界面顶部改「你是」时，同时调用 `setPlayerName({ gameId, playerName })`，**两边共用一个值**。

不这么做会分裂成两个名字：档案里认「林澈」，正文里叫「你」。

- 遇到 `TAVERN_PLUGIN_BUSY` → 面板提示「正文生成或结算中，等这一轮结束再改称呼」，不静默失败；
- 旧宿主没有 `setPlayerName` → 只存我们自己的按卡记录（面板上会说明"这里是手填的备用值"）。

### 3. 人称仍然是我们自己的（按卡存）

酒馆没有人称概念，`person`（第一/二/三人称）继续存在插件数据里，按卡分区。

## 后果

- **收益**：新卡不用手填称呼了，开局就能用酒馆里的值。
- **收益**：档案和正文用同一个称呼，不会再出现"档案里叫林澈、正文里叫‘你’"。
- **代价**：面板上改这个值会**顺带改掉本局玩家称呼**——界面上必须写明。这条已写进提示。
- **边界**：仍拿不到"别名列表"，正文里的「你」还是靠语境判断，插件不做代词消解。

## 待定

- 酒馆更新后，`getPlayerName` 返回「你」时要不要当成"未设置"（现在直接用，因为「你」不会撞任何真人名）。
