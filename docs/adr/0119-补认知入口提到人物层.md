# 0119 补认知的入口提到人物层

- **状态**：有效
- **日期**：2026-11-22
- **supersedes**：[ADR 0116](0116-手动补认知.md) 的决定 1（「认知视图**每栏**加 ＋」）

## 背景

ADR 0116 把「补一条认知」的入口放在**每一栏**的标题行上。它有个前提没被满足：

- `panelView` 的 `cognitionColumns` **只列有内容的栏目**（认知视角不补空）；
- `client` 又拿 `row.cognitionColumns?.length` 当整块的渲染条件。

两者一叠：**一个人只要还没有任何认知，整个「他的认知」块就不渲染**，于是每栏那个 `＋` 也一个都不存在——
新建档的人永远补不了第一条认知，只能等模型写。

## 决定

### 1. 「他的认知」整块无条件渲染

去掉 `&& row.cognitionColumns?.length` 这个短路。只要在看某个人，这块就画（标题行永远在）。
一条认知都没有时，展开后给一句「还没有任何认知，点上面的 ＋ 补一条」——别让玩家以为面板坏了。

### 2. 补认知入口放在**人物层**：标题行右侧一个 `＋`

`FoldHeader` 加 `extra` 插槽（右侧附加内容），把 `＋` 挂进去。点开在标题行下面出下拉
（全体已建档人物的全体命题，`人物 · 栏目：内容`），选中即给**当前这个人**加一条指针。

### 3. 每栏的 `＋` 撤掉，栏目行只留眼睛

- **锁与眼**留在栏目的理由是它们**按栏目生效**（「这一栏不念」「这一栏不许改」）；
- **补认知**不按栏目生效——加的是「这个人知道某条命题」，归哪一栏由**那条命题自己的栏目**决定。

所以入口提到人物层之后，"按栏目加"这件事本来就不成立。

### 4. 下拉的 `pickFor` 用 `'*'` 表示人物层

`''` 没在挑、`'*'` 人物层。原来的栏目码分支一并删掉（不再有按栏目挑的入口）。

## 后果

- **收益**：任何人（哪怕刚建档、零认知）都能补第一条；入口唯一，不用先想"这算哪一栏"。
- **收益**：认知块空着也能看见，玩家知道"这块是空的"，而不是"这块没了"。
- **代价**：选命题时看不到"它会被归到哪一栏"——但那条命题的栏目是既定的，玩家本来也不用决定。
- **边界**：空提示只在**展开**时显示（收起时只留标题行）。
- **边界**：`＋` 在没有可选项（档案里一条命题都没有）时禁用，`title` 提示先去「他是什么样」加一条。

## 被否决的方案

- **保留每栏的 ＋，另外在标题行加一个兜底**：两个入口做同一件事，空人物时只有兜底那个能用，
  反而更迷惑；"按栏目加"本身也不成立（见决定 3）。
- **让玩家先选栏目、再选命题**：多一步，而且栏目由命题决定，选了也白选。
- **只在"零认知"时才在标题行显示 ＋**：入口时有时无，玩家记不住；一直都在更简单。
