# 0061 内部码永不进入模型可见的文本

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0048](0048-模型只报人名.md) 里「重名时素材带 `老陈(p7)`」那条（同名已砍，这条尾巴没必要了）

## 背景

一次真实故障：模型报了 5 条完全正确的值动作，**全被拒**。

```json
{"动作":"新增","人物":"张","栏目":"身份/职业","值":"这家便利店的值班店长","来源":"他述"}
```

原因在校验端：

```js
const code = action?.栏目              // "身份/职业"（模型看到的是名字）
const definition = definitions?.[code] // definitions 的键是 'a'、'b'（内部码）
if (!definition) reject('栏目不存在')  // → 5 条全拒
```

**模型只知道栏目名，快照里存的是条目码。** 这个错不是"少写了个映射"，而是越过了本该存在的一道墙：

> 条目码、人物码、字典码、信度码，都是**我们程序的内部实现**。模型在任何阶段都不该看到它们。

## 决定

### 1. 一条硬规矩

| 方向 | 规矩 |
|---|---|
| **出站**（我们 → 模型） | 只写**人话**：人物写姓名/别名、栏目写栏目名、值先说解码、信度写成「来源·真值·时间」 |
| **入站**（模型 → 我们） | 只收**人话**：人物用名字（程序翻成编号）、栏目用名字（程序翻成条目码） |
| **兜底** | 拿不到人话时写占位（如「（未命名栏目）」），**绝不回落到码** |

内部码只在程序内部流转：快照、缓存、面板接口参数。

### 2. 清掉三处泄漏

| 位置 | 之前 | 现在 |
|---|---|---|
| `followup.js` 写入素材 | `definitions[code]?.name ?? code` —— 没名字就印条目码 | 印「（未命名栏目）」 |
| `followup.js` 人物标题 | 重名时印 `老陈(p7)` | **只印名字**（同名已砍，重名不可能出现） |
| `render.js` 栏目名默认值 | `nameOf = (code) => code` | 默认「（未命名栏目）」 |

### 3. 入站解码放在校验之前

`validateValueActions` 先做「栏目名 → 条目码」翻译：

```js
if (definitions?.[text]) return text        // 已经是码（面板传来的）
return codeByName.get(text) ?? null         // 或者是栏目名（模型传来的）
```

两种写法都认——**模型那条走名字，面板那条走码**，互不影响。

## 后果

- **收益**：模型永远不需要知道我们的编码方案，提示词也不必解释"a/b/c 是什么"。
- **收益**：换编码方案（比如条目超过 52 个要换双字母）不会影响模型侧。
- **代价**：每个进出边界都要有一次翻译；翻译漏了会表现为"栏目不存在"这类静默拒绝（这次的坑）。
- **边界**：字典码仍在快照里存着，但**读出来必须过 `decodeValue`**；信度位同样只在内部流转。

## 守卫

加了三类测试：

1. 人物素材里**不出现 `p7` 这类编号**；
2. 栏目没名字时印**占位名**，不印条目码；
3. 校验层**既能认栏目名、也能认条目码**（前者给模型，后者给面板）。

## 待定

- 值里的**序号**（`1.`、`2.`）算不算内部码？目前算"位置"不算"码"，允许出现在素材里——它是模型定位的手段，且不泄露实现。
