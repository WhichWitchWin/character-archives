# 0082 召回改成「在场人物的认知指针」（提案，未定稿）

- **状态**：提案（**未定稿，别当结论用**）
- **日期**：2026-11-03
- **supersedes**：[ADR 0024](0024-建档提前.md) §2「在场人物照旧**不召回**」、[ADR 0046](0046-召回接线.md) §3 筛选顺序第一条「状态必须是「离场」」
- **相关**：[ADR 0081](0081-信度改成事实加指针-提案.md)、[ADR 0042](0042-一致性四档与召回命中缓存.md)、[ADR 0043](0043-身份层豁免冷却与空值兜底.md)
- **起因**：信度改成「命题 + 指针」后，旧召回的两条前提同时失效

## 背景：旧召回为什么不再成立

旧召回给的是「**他是什么人**」——身份、干了什么、去了哪。这些正文刚写过，所以「在场人物不召回」成立（ADR 0024 §2 原文：「在场的人正文模型自己看得见，不需要我们塞」）。

新召回给的是「**他知道什么**」——他信什么、从谁那儿听来的、他以为自己在哪。这些**正文一个字都没写**，模型只能靠猜。

> 正文：「老陈一拍桌子，说这笔账拖了三年。」
> 档案里：老陈 →「主角欠他钱」：**真**

「老陈拍桌子」正文写了；**「他为什么拍桌子」只有档案能告诉模型**。不给，下一轮就可能写出一个忘了讨债的老陈。

## 决定

### 1. 取消「存在池」，只召回在场人物的认知指针

离场人物之所以需要被想起来，是因为**在场的人脑子里有他**——那本来就是一条指针（`主角 →「老陈欠我一笔钱」：真`）。召回在场人物的认知时，老陈自然被带出来。

不单独给他一个池子。现行「只召回离场人物」整条规则退役。

### 2. 冷却降到指针级

冷却单位从「人物」改成「**这一条指针**」，默认轮数不变。

- 第 1 轮给了「他怕张三」→ 这条指针冷却；
- 第 3 轮新增「他发现张三骗他」→ **新指针**没冷却过，照给；
- 第 5 轮「他怕张三」仍在冷却，不给。

「在场连续五轮」的重复问题自动消失，给出去的是**变了的部分**——正是模型缺的。

### 3. 优先级从「时间」换成「场景」

| 档 | 给什么 |
|---|---|
| ① | 这个人**关于在场其他人物**的指针 |
| ② | 这个人**关于所处地点**的指针 |
| ③ | 其他（**未定**，见下） |

理由：模型写对话时最需要知道「他怎么看眼前这个人」，其次「他觉得这地方怎么样」。

### 4. 旧召回实现标记退役

`plugin/lib/recallPipeline.js`、`recall.js`、`compose.js`、`render.js` 里的召回相关实现，在新结构落地前**保持现状、不再扩展**；写入侧定稿后一并重写。

**2026-11-04 更新：已实际退役**——五个文件（含 `brief.js`）连同它们的 5 个测试文件一并移入回收站；`index.mjs` 的 `turnSection` 只剩占位（返回空字符串），新引擎待实现。

## 未定项

1. **主角算不算「在场人物」**——算，整个召回就是「主角眼里的世界」；不算，只有 NPC 的认知。
2. **第三档给什么**——「未了事项」「计划」这类只跟他自己有关的指针给不给。
3. **预算怎么分**——5 人 × 10 条 = 50 条，3000 字装不下，需要分配规则。
4. **冷却存什么**——「给过哪些指针 ID」；指针状态变了要不要重给（倾向按「指针最后变动轮次 > 上次给的轮次」重给）。
5. **依赖 0081 定稿**——事实/指针的存储结构没定，本节无法落代码。

## 被否决的方案

- **保留两个池（存在池 + 认知池）**：离场人物的「存在」本来就是在场人物的一条指针，两个池重复表达同一件事。
- **在场人物每轮给全部认知**：五轮都在场就五轮给同一份，纯烧预算。
- **在场人物给一次然后人物级冷却**：他第 3 轮可能刚改主意，冷却期间模型就不知道了。
