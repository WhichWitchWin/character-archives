# 0053 快照带「剧情地点」；MVU 值要勾选才收

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：无（给 §4.1 快照结构加字段；把 §8.8 的「自动建条目」从隐含默认改成显式勾选）

## 背景

接 MVU 时发现两件事：

### 1. 快照只有时间，没有地点

§4.1 快照头是 `{ v, t, p, gt }`——只有**时间**，没有**地点**。

但很多状态机卡里就有地点值（实测那张卡是 `地点: { 城市, 区域, 场所 }`）。只记时间不记地点，同一时刻在不同地方发生的事就分不开：

> 「永安三年·冬」在旧港码头发生的事，和同一天在临安城里发生的事，档案里分不出来。

### 2. MVU 字段是全收还是玩家挑？

原设计（§8.8）写的是「**对不上的 MVU 字段自动建同名条目**」——等于**全收**。

问题是真卡里字段很杂：`冷却: {关系, 好感, 怀疑}`、`神: {暴露度}`、`疑点`、`依据`……全变成栏目，档案立刻变成垃圾场。

## 决定

### 1. 快照头加 `loc`（剧情发生地点）

```json
{ "v": 1, "t": 40, "p": [...], "gt": "永安三年·冬", "loc": "临安·旧港·码头" }
```

- 跟 `gt` 一样的规矩：**原文照抄，不解析**（ADR 0005）；
- 拿不到就是**空串**，脏数据也当空串（不让整份快照作废）；
- **第一版就要上**——不能等，因为地点是很多卡的常备字段。

### 2. MVU 值**要勾选才收**

| 规则 | 行为 |
|---|---|
| 玩家在映射表里**勾选**某个 MVU 字段 | 才把它抄成条目（信度位 `"9"`） |
| 某个字段**从来没被勾选** | 不建条目、不抄值 |
| 玩家**取消勾选** | **删掉那条已建的条目**，并且**本局不再捕获**这个字段 |
| 玩家**删掉一条已映射的条目** | 视为取消勾选，之后不再映射 |

也就是说：**勾选表就是"这张卡要收哪些 MVU 字段"的唯一开关**，而 `autoMap`（默认开）只负责**把能自动对上的字段先勾上**，让玩家少点几下。

### 3. `autoMap` 默认开，但只是"预勾选"

- 开：把能按名字对上的字段（`身份` → `身份/职业`、`关系` → `关系`）**预先勾好**，玩家可以再取消；
- 关：一个都不预勾，全由玩家手动挑。

## 后果

- **收益**：档案只收玩家要的字段，不会被 `冷却`「暴露度」这类引擎状态塞满。
- **收益**：地点进了快照，同一个时间点在不同地方的事分得开，「最后去向」也有依据。
- **代价**：玩家每换一张卡要过一遍勾选（`autoMap` 能省掉大部分）。
- **边界**：取消勾选会**删掉已有条目**——这是破坏性操作，界面上要二次确认。

## 被否决的方案

- **MVU 字段全收（原设计）**：真卡字段太杂，档案会被垃圾字段淹没。
- **地点不进快照、只进条目**：那它就成了"某个人在哪"，而不是"这段剧情发生在哪"——语义不同。
- **地点也解析成结构化字段**：违反 ADR 0005「只记录不解析」，且各卡格式差太远。
- **取消勾选只停捕获、不删条目**：留下一条永远不会更新的死值，比没有更糟。

## 待定

- 勾选表存在**整局数据**还是**按卡**（换局要不要重配）——用户提到「本局」和「这张卡」两种口径，需定一个。
- 取消勾选删条目时，要不要连**值**一起删（现在倾向是）。
- 映射表的面板界面（勾选区、忽略按钮、二次确认文案）。
