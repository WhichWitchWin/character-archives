# 0062 回头测试前置成一道独立动作（提案）

- **状态**：**有效**（2026-11-03 落码；实现与本文略有出入，以「最终实现」一节为准）
- **日期**：2026-11-02
- **supersedes**：（待确认后）[ADR 0059](0059-别名查撞与单字名.md) 里「单字姓名必须配 ≥2 字别名」这条提示词文案；[ADR 0031](0031-回头测试与沉降.md) 的回头测试**位置**（从"建档规则里的一条"提到"独立动作"）

> ⚠️ 本文只是方案，**代码与提示词都还没改**。确认后再落。

## 背景：一次真实的误收录

第 6 轮，模型建了一个人叫「张」：

```json
{ "动作":"建档", "姓名":"张", "别名":"值班店长张", "称呼":"店长", "状态":"离场" }
```

但从正文看，**这个人从头到尾没有出场**，唯一的来源是一张贴在收银台上的塑封小牌：

> 抬手把一张贴在台板上的**塑封小牌**翻过来，上面印着「**值班店长 张**」和一个手机号

正文里关于他的全部信息都是转述：

> 「店长今晚不值班。」「他一般十点接晚上的账。」
> 「关机。他有小孩，晚上基本不开。」

按回头测试，喊一声「张」半条街回头 —— **这条根本不该建**。

## 为什么没挡住

### 1. 模型把「文具上印的字」当成了「怎么叫他」

提示词只写了「称呼必须来自正文里怎么叫他」。塑封牌上的字**确实在正文里**，于是被照收。

### 2. 「张」不在反例里

现有反例全是**职业／身份词**：小贩、路过的、侍卫、黑衣人、外卖小哥。
**单字姓氏**不在其中，而中文里"值班店长 张"读起来确实像在指一个人。

### 3. 提示词与代码不一致（我们的锅）

提示词里还留着 ADR 0059 那条：

> 姓名只有一个字时，必须配一个两字以上的别名

而代码里这条**已被 ADR 0060 删除**。模型看到「张」带了别名「值班店长张」，很可能认为"符合规矩"。

### 根因

**回头测试全靠模型自觉，程序不校验。** 而"单字姓氏算不算能喊出来的名字"恰恰是**程序能判、模型常判错**的事。

## 方案 B：同一次调用里，把回头测试变成一道**必须先给结论**的动作

不增加模型调用（现在每轮已经是判定＋写入两次），改为**在同一轮判定里先要结论、再要动作**。

### 1. 新增一种人物级动作：`回头测试`

每次【判人】的**第一条动作**必须是它：

```json
[
  { "动作":"回头测试",
    "通过":["林小鱼","值班店长张"],
    "不通过":[{"称呼":"张","原因":"单字姓氏，只出现在塑封牌上"}] },

  { "动作":"建档", "姓名":"值班店长张", "别名":"张姐", "状态":"离场" }
]
```

### 2. 程序校验

| 检查 | 处理 |
|---|---|
| 本轮**没有**「回头测试」动作 | **所有**「建档」「模糊建档」全部拒绝，并记提示 |
| 建档/模糊建档的姓名**不在**「通过」里 | **这一条**拒绝，其余动作照常 |
| 「通过」里有人但本轮没建 | 不管（只是结论，不是承诺） |
| 「不通过」里有、动作里也没建 | 正常 |

> 原则：**宁可漏，不要错**。漏了下一轮还能补，错了要玩家手动收拾。

### 3. 系统提示词改动（**完整文案，供审**）

**改前**（`docs/系统提示词.md` 一、建档）：

```text
每个称呼先过回头测试：**站在街上喊这个称呼，会只有他一个人回头吗？**
  ✅「老陈」「独眼陈」「刀疤刘」
  ✗「小贩」「路过的」「侍卫」「黑衣人」——喊一声一堆人回头
  ✗「骑电瓶车的外卖小哥」——电瓶车是外卖小哥的标配，十个回头
原则：**同行的标配不算标识，反常才算**（外卖小哥的标配：电瓶车、头盔、保温箱；鱼贩的标配：鱼摊、围裙、秤）。

称呼必须来自正文里怎么叫他，**不许自己起名**。
**过不了回头测试的人不建档**——这不是判他重不重要，只是判他有没有一个能找回来的名字。
· 过了测试，再满足任一条：
    ① 与主角有实质互动：对话涉及信息、交易、冲突、承诺
    ② 持有重要物品或线索
    ③ 出现 ≥2 轮（模糊建档表里出现过、本轮又出现，就算 2 轮）
    ④ 被别人提起，**且提的是他的具体事**（只出现一个名字不算）
· 姓名不可留空，如无明确姓名就用别名或称呼顶替。
· **别名不能和已有任何人重名**（别人的姓名也算）；程序会拒掉整条建档。
· **姓名只有一个字时，必须配一个两字以上的别名**（"周"→"周老板"）：喊一声"周"一堆人回头。
```

**改后**：

```text
每个称呼先过回头测试：**站在街上喊这个称呼，会只有他一个人回头吗？**

过不了的不建，也不进模糊建档：
  ✗「小贩」「路过的」「侍卫」「黑衣人」——职业／身份，喊一声一堆人回头
  ✗「骑电瓶车的外卖小哥」——同行的标配，十个回头
  ✗ **单字姓氏**（张、王、周）——喊一声半条街回头
  ✗ **名片／招牌／名册上印的字**——那是"写着的"，不是"有人这么叫他"

原则：**同行的标配不算标识，反常才算**（外卖小哥的标配：电瓶车、头盔、保温箱；鱼贩的标配：鱼摊、围裙、秤）。
称呼必须来自正文里真的有人这么叫他，**不许自己起名，也不许从文具上抄**。

✅ 过得了的：老陈、独眼陈、刀疤刘、瞎眼的鱼贩、值班店长张

**先判，再动手**：每次【判人】的第一条动作必须是回头测试的结论，格式见动作示例；
之后才允许「建档」「模糊建档」，**名单里没有的人不许建**。

· 过了测试，再满足任一条：
    ① 与主角有实质互动：对话涉及信息、交易、冲突、承诺
    ② 持有重要物品或线索
    ③ 出现 ≥2 轮（模糊建档表里出现过、本轮又出现，就算 2 轮）
    ④ 被别人提起，**且提的是他的具体事**（只出现一个名字不算）
· 姓名不可留空，如无明确姓名就用别名或称呼顶替。
· **别名不能和已有任何人重名**（别人的姓名也算）；程序会拒掉整条建档。
```

**删掉**最后那条「姓名只有一个字时，必须配一个两字以上的别名」——单字的问题交给回头测试管。

### 4. 写入提示词：**不改**

写入阶段是"给已建档的人写值"，不涉及建档，一个字都不动。

### 5. 判定素材：**不改**

判据放系统提示词就够；素材里不需要额外加段落（素材越短，模型越专注正文）。

## 后果

- **收益**：模型必须先**显式表态**，不能只在动作里悄悄带上一个不该建的人。
- **收益**：程序有据可查——建档名字不在「通过」里就拒，不再纯靠自觉。
- **收益**：调试窗口能看到它判了什么、为什么，出问题好定位。
- **收益**：**建档与模糊建档共用同一道关**，两个入口不会各自跑偏。
- **代价**：动作结构多一层；模型可能漏写某个人 → 那人建不了（可接受，符合"宁可漏"）。
- **代价**：每轮多一条动作，素材与输出都长一点点（可忽略）。

## 被否决的方案

- **A｜真·两阶段**（先单独问一遍回头测试）：要多一次模型调用。现在每轮已经是「判定＋写入」两次，再加一次不划算。
- **C｜只改提示词**（加反例、不说结构性要求）：全靠自觉，这次的「张」就是自觉失败的例子。
- **程序硬拦单字姓名**：能挡住「张」，但挡不住「值班店长」这种两字身份词；而且回到 ADR 0060 刚放开的地方，反复折腾。

## 待确认

1. 文案措辞是否合适（尤其"不许从文具上抄"这种说法）。
2. 「通过」名单要不要**允许为空**（本轮没人过关）——提案是允许。
3. 漏写「回头测试」动作时，是**全拒建档**（提案如此）还是**只警告不拒**。

## 最终实现（2026-11-03 落码，与上文提案的出入）

落码时按用户的要求做了调整，**以本节为准**：

### 1. 动作名与形状

判定阶段的 payload 多了一个**顶层块**（不是动作数组里的一项）：

```json
{
  "回头测试": {
    "通过":   [ "值班店长张", "沈清禾" ],
    "不通过": [ { "称呼":"老头", "原因":"蓝色夹克是拎板凳老人的标配，不是反常" } ]
  },
  "建档": [ { "姓名":"值班店长张", … } ],
  "改状态": [ … ],
  "模糊建档": [ … ]
}
```

- 「不通过」也接受纯字符串（`"老头"`），程序会补成 `{称呼, 原因}`。
- 顶层写法 `{通过, 不通过}`（不带「回头测试」键）也认。

### 2. 程序校验三条（判定阶段强制）

| 检查 | 不满足时 |
|---|---|
| **本轮必须有「回头测试」动作** | 本轮所有建档**全拒**（模型没表态就不许建） |
| **建档的姓名/别名必须在「通过」名单里** | 那条建档被拒（**别名命中也算通过**） |
| **「通过」名单里的称呼必须在正文里原样出现** | 那个称呼**从通过名单里剔掉**（等于没通过） |

第三条是用户明确加的要求：**模型给的通过回头测试的人的称呼，必须是正文里的称呼**。

### 3. 与层 1（ADR 0067）的关系

两条是**串联**的：
- ADR 0067：建档的姓名/别名要在正文里原样出现（防造名字）
- ADR 0062：建档的人要在「通过」名单里（防泛称），且名单本身要在正文里（防名单造假）

### 4. 为什么「没表态就全拒」而不是「放行」

宁可漏，不要错：模型没给结论时，默认它**没通过**。代价是模型偶尔漏给结论 → 那一轮不建档 → 下一轮它会重给（拒绝原因里带「通过名单」，方便它自己改）。

### 5. 提示词同步

`docs/系统提示词.md` 的建档章节改成「**先过回头测试，并把结论写进 `回头测试` 块**」，输出段的【判人】示例也加上了这个块。`plugin/prompt.js` 已重新生成。

### 6. 面板手动建档不受影响

`requireLook` 默认 false —— 只有**判定阶段**（模型来的动作）强制回头测试；面板上手动新建人物是玩家自己的决定，不查。

## 待定（仍然）

- 模糊建档要不要也走回头测试？（现在只查层 1，不查回头测试）
- 「不通过」名单里的人，程序要不要**主动拦下建档**（现在拦了：模型自己把它放进「不通过」就不能建）——已实现，但**模型可以既不放进「不通过」也不放进「通过」**，那种情况会被第三条拦掉。
