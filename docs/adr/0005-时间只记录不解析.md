# 0005 时间处理：只记录与标注，不解析格式

- **状态**：已采纳
- **日期**：2026-10-31
- **supersedes**：设计稿 §7.9 中「有游戏时间（MVU 含日期字段）→ 程序判定到期」一支、§8.8「时间源字段」的职责说明

## 背景

设计稿 §7.9 原本分两支：有游戏时间就走程序精确判定，没有就走「存文字 + 每 N 轮让模型复查」。

但各张卡的时间写法完全不统一：有的只算天数（数字），有的年月日、月日年、日月年，有的只记年，还有干支纪年、自定义纪元。要程序判定就得做一整套解析器 + 格式歧义确认 + 精度降级 + 时间倒退处理 —— 而且**猜错是静默的**（把 `05/12` 认成 12 月 5 日，「三个月后」的提醒就全错，玩家还发现不了）。

另一个硬事实：**MVU 只有"当前"变量值，历史轮次的时间拿不回来**。想在离场归档时追溯"他最后一次出现是几号"，只能自己提前记。

## 决定

### 一、不解析时间格式

时间一律当**文字**处理：记录原文、原样标注给模型，程序**不比较大小**、不换算天数、不判断到期。

到期判断交给模型 —— 它擅长语义（"三个月后"过没过），不擅长的是精确解析；而我们砍掉的正是后者。

### 二、gt 的落点与优先级

| 落点 | 内容 | 何时有 |
|---|---|---|
| **快照头** | 本轮游戏时间原文 | 每次写快照时 |
| **值（可选第 5 元素）** | 该值捕获时的游戏时间原文 | 只有"不是当轮写入"的值才有 |

优先级：**值自带 gt > 快照头 gt > 都没有**（都没有就退化成模型从正文猜）。

第 5 元素**默认省略**，不用空串占位 —— 否则 60 个值 × 2000 份快照会白扔约 360 KB。

### 三、在场名单（整局数据，临时结构）

每轮把正文里出现的人物记一条：

```
anchors: { p7: { turn: 20, gt: "三年五月十二日" }, … }
```

- 每人一条，约 30 字节，10 个在场人物约 300 字节；
- 每轮覆盖为他最后一次出现的轮次与当时的 gt；
- 之所以要**每轮都记**：「最后一次出现是哪一轮」只有事后才知道，不能等到判定时再记。

### 四、离场归档：锚定最后在场轮，内容回读

- 明确离场（强信号）：当轮捕获、当轮写入，gt 就是当轮的；
- 模糊离场（现场名单里没有 + 连续 N 轮未出现）：判定后在场上名单里取 `{turn: 20, gt}`，**回读第 20 轮正文**提取内容（设计稿本来就是「回看最后一次确认他在场的那一轮取资料」），写入的值挂 turn 20 + 那轮的 gt；
- 因此**等待期（待确认 3 轮、手动提名最长 10 轮）不产生时间漂移**；
- 残余偏移只剩"模糊离场本身的 3～5 轮观察期"，而它在语义上本来就模糊（正文没写他什么时候走的），接受。

### 五、MVU 容灾的暂存（整局数据）

资料源正在消失、又必须立刻保住时（MVU 容灾），内容不能等回读，必须在那一轮**连值带 gt 一起**存进整局数据：

```
pending: [ { turn: 20, gt: "三年五月十二日", 原因: "mvu-rescue", 值: [ … ] }, … ]
```

- **同一轮的所有值共享一条 gt**（一轮 100 个值也只占一份）；
- gt 在**捕获那一刻锁定**，之后等多久都不变；
- 写入成功 → 清除该条；作废（人物回场 / 超时）→ 清除该条；
- 写入一直失败 → **最多保留 7 轮**，超过则丢弃这批并在提示板记一条（防止整局数据被撑爆）。

### 六、覆盖与手动编辑

- 覆盖一条值 = **整条替换**，gt **不继承**：新值没带 gt，旧 gt 一起清掉；
- 玩家可以在面板上手动编辑任意值的 gt，默认留空 = 不指定。

### 七、删快照不留时间

快照被删（§3.4 自动删、§3.7 压缩）时，**不把 gt 转存到整局数据** —— 连当轮的正确快照都没有了，留个孤立时间没有意义。

### 八、时间源怎么来

| 情况 | 行为 |
|---|---|
| 能自动认出 | 直接抓，不打扰玩家 |
| 抓不到 | 插件面板里**常驻一条通知**，提醒玩家匹配时间源 |
| 玩家手动指定过 / 明确跳过 | **该会话不再提示** |
| 没有 MVU 或读不到时间 | 不提示，直接走模型判断（§7.9 无时间那条路） |

### 九、发给模型时怎么标注

程序只做标注，不做判断：

- 值自带 gt → 告诉模型「这条按它自己的时间算」；
- 没有 → 用快照头 gt；
- 两者都没有 → 不提时间，交给模型从正文猜。

## 后果

- **收益**：砍掉整套解析器/格式确认/精度降级（约 200 行 + 40 条测试）；不存在"格式认错导致时间全错"的静默失效；等待期不漂移；整局数据的固定开销只有在场名单（约 300 字节）。
- **代价**：到期判断依赖模型，可能不准、可能漂移；每张卡的时间精度取决于玩家有没有配时间源；**残余偏移**为模糊离场的 3～5 轮观察期。
- **被否决的方案**：
  - **程序解析时间格式**：格式无穷、猜错静默，收益只落在一条软提示上。
  - **每份快照都记完整时间线**：分钟级卡每轮都变，2000 轮约 60 KB，占整局数据 23%。
  - **每条值都挂 gt**：比"按轮共享"贵约 30 倍。
  - **插件自建数据文件 + 监听 `onTimelineChanged` 手工同步**：官方 `plugin-design.md` §4 明确「数据绑定正文版本，由 Tavern 自动处理，不做快照，也不靠通知同步」；手工同步会漏掉插件未运行期间的变更，且"后覆盖"会毁掉撤销回退。
