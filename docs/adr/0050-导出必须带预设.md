# 0050 导出：档案必须带预设和字典一起走

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：无（落地 [ROADMAP](../ROADMAP.md) M4-7 的导出一半，导入仍未做）

## 背景

要做导出。格式定 JSON（用户明确要求），并且**和条目预设合并**——可以单独导预设，但**不能单独导人物档案**。

原因很硬：人物册里的值是按**单字母条目码**存的。

```json
["a", "账房", "4", 10]
```

没有条目定义，这个 `"a"` 谁也解释不了——它到底是「身份职业」还是「未了事项」？**导出去就是一串乱码**。

同理还有**字典**：值的原文可能是字典下标（数字），没有 `dict` 同样解不出来。

## 决定

### 1. 两种包，同一个格式

| kind | 内容 | 能否单独导 |
|---|---|---|
| `preset` | 条目定义 ＋ 顺序 | ✅ 可以 |
| `archive` | **预设** ＋ 人物册 ＋ 字典 ＋ 轮次 ＋ 时间 | ❌ **必须自带预设** |

包的外壳：

```json
{
  "format": "dsh-tavern-character-archives",
  "version": 1,
  "kind": "archive",
  "exportedAt": "2026-11-02T…",
  "preset": { "name": "…", "entries": { "a": {...} }, "order": ["a"] },
  "archive": { "turn": 40, "gt": "…", "persons": [...], "dict": {...}, "note": "" }
}
```

### 2. 没有条目定义就直接报错

`buildArchiveExport()` 在 `definitions` 为空时**抛错**，不产出"解释不了"的包。宁可导不出来，也不给一份看不懂的文件。

### 3. 校验在导入侧先做

`validateBundle()` 检查：格式标识、版本号（太新就拒）、kind、**档案包必须有预设**、档案包必须有字典。

## 后果

- **收益**：导出的档案永远是自解释的——拿着这份 JSON 就能完整还原每个人物。
- **收益**：预设可以单独分享（"我这套栏目挺好用，给你"）。
- **代价**：档案包会重复携带条目定义（每份几十条，几 KB）。这点冗余换来"永不乱码"，值。
- **边界**：**导入还没做**（M4-7 的另一半），所以现在只能导出、不能导回来。

## 被否决的方案

- **档案单独导**：值里的条目码没有定义就是乱码（本 ADR 的核心反例）。
- **只导档案、预设另外存**：两个文件容易走散，用户只发一个就废了。
- **导出成 Markdown**：好看但导不回来，且同样是"码无法解释"的问题。
- **依赖酒馆自带的整局导出**：那导的是整个存档，不是一份能单独看／搬给别人的人物档案。

## 待定

- **导入**：版本校验、冲突提示（同名/同码不同定义）怎么做，等做导入时定。
- 导出要不要带**候选表、冷却、离场记录**等运行时状态——目前只带人物册本身（那些是"这一局的运行时"，换局没意义）。
