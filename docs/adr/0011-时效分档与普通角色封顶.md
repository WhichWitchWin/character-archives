# 0011 时效改为分角色衰减，普通角色总分封顶

- **状态**：已采纳（两个数值待定，见文末）
- **日期**：2026-11-01
- **supersedes**：无。本 ADR 记录对设计稿 §7.10「时效项」的**偏离**。

## 背景

设计稿 §7.10 的时效是 `exp(-0.01 × 距上次更新的轮数)`，与匹配、一致性、先验**等权平均**。落地时发现三个问题：

### 1. 与功能定位相悖

这个插件的存在意义是**替已经离场的人物保管记忆**。离场越久，「距上次更新」越大 → 时效分越低 → **越该被想起的人越被压**。方向反了。

### 2. 正反馈回路（马太效应）

```
召回 → 档案被更新 → 距上次更新变小 → 时效升高 → 更容易再被召回 → …
```

冷却（默认 10 轮）只削一刀，**不消除**。结果热度永远集中在少数人身上。

### 3. "等权"不等于"影响小"

分母是 4，看着温和，实际够跨档：

| 距上次更新 | 时效分 | 折进总分 |
|---|---|---|
| 0 轮 | 1.00 | 0.25 |
| 20 轮 | 0.82 | 0.20 |
| 100 轮 | 0.37 | 0.09 |

0.11 的总分差足以跨过 0.50 那条档位线。

> 附：**在场人物不参与召回**（召回只针对离场角色），所以"刚召回的人"不会因为时效高而反复出现——但冷却到期后仍会。

## 决定

### 1. ★重要人物不受时效惩罚

玩家标记为重要的角色，时效**恒为 1.0**，离场 500 轮也一样。

### 2. 普通角色：带上限与下限的衰减

```
时效 = 0.9 × (下限 + (1 − 下限) × exp(−0.01 × 离场轮数))
```

- **上限 0.9**：普通角色永远拿不到 1；
- **下限**由「剧情节奏」档位决定。

### 3. 剧情节奏三档 → 掉分下限

| 档位 | 下限 | 离场 20 轮 | 离场 200 轮 |
|---|---|---|---|
| 慢（日常/慢热，默认关闭项之一） | 0.7 | 0.85 | 0.67 |
| 中（默认） | 0.5 | 0.82 | 0.51 |
| 快（战斗/悬疑/大跨度） | 0.2 | 0.77 | 0.28 |

**方向已定：剧情越快，普通角色淡出越快**（功能角色该被遗忘），剧情越慢掉落越缓。

### 4. 普通角色总分封顶

普通角色的**总分**封顶，进不了「全量」档（建议封 0.79，刚好卡在 0.80 下面）；**本轮对上 ≥2 条关联线索时破格**，允许进全量——防止"剧情里突然成了主角、但没被标星"的角色信息不足。

### 5. 自动清理第一版不做

长期离场 + 分数垫底的普通角色，**第一版不自动清理**。留作后续版本（见[ROADMAP](../ROADMAP.md) P6）。

## 后果

- **收益**：冷角色不再被系统性地饿死；重要人物永远可靠；普通角色不会吃掉全量预算；正反馈回路被上限 + 下限夹住。
- **代价**：偏离设计稿 §7.10 的等权四项；需要新增两个设置项（剧情节奏、★重要标记）；★ 标记要存进整局数据（建议 `flags.star`）。
- **边界**：轮数是「游戏外」计数，遇到闪回／时间跳跃会失真。因此**故事内的陈旧交给 `gt` 标注去告诉模型**（ADR 0005「时间只记录不解析」），而不是继续用分数惩罚。
- **被否决的方案**：
  - *反向时效（离场越久分越高）*：会系统性偏爱"早没戏的人"，而"刚离场、最可能被提起"的反而垫底；
  - *直接删掉时效项*：丢掉了"同分时优先新的"这层微弱排序信息；
  - *全局单一下限（不分角色）*：重要人物和功能角色被一视同仁，等于没解决。
