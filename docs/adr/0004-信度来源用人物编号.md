# 0004 信度来源用人物编号，名字从快照取

- **状态**：已采纳
- **日期**：2026-10-31
- **supersedes**：设计稿 §5.1 中 `"r42"` 的形式（原写「来源＝字典第 42 号」）

## 背景

设计稿 §5.1 用 `"r42"` 表示「他述，来源是字典第 42 号」。但 §4.3 明确**字典不收人名**，于是这个码永远指不到人 —— §5.2 那个「他述来源：可选档案中已有的人物」在数据层没有落点。

三条路都试过：

| 方案 | 问题 |
|---|---|
| A. 人名进字典，继续用 `r42` | 两个人同名会落到**同一个**下标，玩家看不出引用的是谁（用户明确否决）；滚动回收还可能把仍在用的下标换成别的词 |
| B. 用人物编号 `rp7`，但按**当前**人物册解析名字 | 角色改名后，回退到旧轮次会看到**新名字** —— 剧透 |
| C. **人物编号 `rp7` + 名字从该份快照取** | ✅ 采纳 |

## 决定

1. **信度位的来源引用改用人物编号**：`rp7` / `rp7+` / `rp7-`（`p7` 是人物编号，格式 `p` + 十进制数字）。
2. **废弃 `"r42"` 写法**，不保留兼容 —— 当时还没有任何落盘数据，v1 一次定死。
3. **姓名按原文存进快照、不进字典**（沿用 §4.1 原规定）。显示「他述来源」时，**以正在查看的那份快照为界**取姓名：
   - 显示第 20 轮的快照 → 拿第 20 轮里 p7 的姓名 → 当时那个旧名字；
   - 显示当前快照 → 拿现在的姓名 → 新名字；
   - 因此回退**不会剧透**后来的改名，也不需要改写任何历史快照。
4. **人物编号永不复用**：整局数据维护一个只增不减的计数器，删掉 p7 之后下一个人物是 p8。
5. 名字的边界情况（不额外建表）：

| 情况 | 显示 |
|---|---|
| 该份快照里还没有这个人 | 未知来源（p7） |
| 该份快照里这个人已被删除 | 已删除的人物 |
| 已合并的副人物 | 老陈 → 陈老板（沿用 §二「已并入 X」的重定向） |

## 后果

- **优点**：同名不同人分得清；回退不剧透；不改写历史快照；不加名册、不加墓碑表；人名依旧不占字典槽位。
- **代价**：
  - 信度位从 `r42`（3 字节）变成 `rp7`（3 字节），编号到三位数时 `rp123` 会多 1 字节；
  - 显示来源名字时**必须带上下文**（哪一份快照），不能再写成「传一个编号就返回名字」的无状态函数；
  - 实现上需要 `findPerson(snapshot, id)` 这类按快照查找的入口（已在 `plugin/lib/snapshot.js`）。
- **需要用户同步的设计稿位置**：§5.1 信度码表里 `"r42"` 三行、§5.4 回退组合表中与来源相关的描述、§5.2 界面里「来源」下拉的行为说明（选人物 → 存编号）。
