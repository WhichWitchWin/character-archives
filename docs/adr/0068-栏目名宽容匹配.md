# 0068 栏目名宽容匹配：格式差异不该全拒

- **状态**：有效
- **日期**：2026-11-03
- **相关**：[ADR 0067](0067-名字必须来自正文.md)（层 1：名字必须来自正文）、[ADR 0061](0061-内部码不进模型.md)

## 背景：一次实测被拒

模型报的值动作：

```json
{ "动作":"新增", "人物":"老陈", "栏目":"身份职业", "值":"替周也备车备早饭的随从", "来源":"用户" }
```

程序拒了：

```
值动作被拒 1 条
原因：栏目不存在：(空)
可用的栏目：["身份/职业","性格","能力资源","当前处境","最后已知去向","后续计划","未了事项","关系"]
```

**差别只有一个斜杠**：模型写「身份职业」，系统叫「身份/职业」。

## 为什么模型会写错

- 素材里给模型看的是**栏目名**（ADR 0061：内部码不给模型看），模型照抄时可能顺手省掉斜杠；
- 「身份职业」在中文里本来就是更自然的写法；
- 值的其它 4 条都写对了（性格、能力资源、当前处境、未了事项），只有这一条带斜杠。

## 决定：栏目名做**宽松匹配**

除了原样匹配，再加一条**归一化匹配**：去掉所有分隔符（斜杠、空格、顿号、连字符、括号等）后再比。

| 系统叫 | 模型写 | 结果 |
|---|---|---|
| 身份/职业 | 身份职业 | ✅ 认 |
| 身份/职业 | 身份 / 职业 | ✅ 认 |
| 最后已知去向 | 最后-已知-去向 | ✅ 认 |
| 身份/职业 | 长相 | ❌ 拒（真不存在） |

**优先级**：条目码 → 栏目名原样 → 归一化后。两条栏目名归一化后相同（`身份/职业` 和 `身份职业` 同时存在）时，**原样匹配优先**。

## 后果

- **收益**：这类"抄漏了一个符号"的损失全部消失——它本来是**模型的笔误**，不是模型的判断错误，拒掉只是让档案少一条值。
- **代价**：极小。归一化后撞名的可能（如上表最后一种）用"原样优先"兜住。
- **边界**：**只放宽栏目名**。人物姓名、别名、回头测试名单**仍然是原样匹配**——那些是"这个称呼正文里到底有没有"的判断，不该放宽（ADR 0067）。

## 与 ADR 0067 的区别

| | ADR 0067（层 1） | 本 ADR |
|---|---|---|
| 管什么 | 人物**姓名/别名**、回头测试**称呼** | 栏目的**名字** |
| 规则 | **必须原样出现在正文里** | 原样或归一化后相同即可 |
| 为什么 | 判断"这人正文里到底叫什么" | 判断"这栏是哪一栏"——只是符号差异 |

一个字之差：一个管**是不是他**，一个管**是哪一栏**。
