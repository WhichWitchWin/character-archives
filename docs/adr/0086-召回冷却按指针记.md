# ADR 0086 · 召回冷却按「指针」记

- **日期**：2026-11-04
- **状态**：已定；指针结构（来源带时间／最后变动轮）与指针级冷却函数已实现，召回引擎尚未接线
- **相关**：[ADR 0082](0082-召回改成在场人物认知指针-提案.md)、[ADR 0085](0085-主角入档与召回规则.md)、[ADR 0040](0040-离场缓冲改名.md)

## 背景

召回要改成「在场人物的认知指针」之后（ADR 0082），冷却还停在「人物级」：整人冷却 10 轮。这有两个毛病——他连着五轮在场，五轮给同一份「他怕张三」纯烧预算；反过来，这 10 轮里他**任何新认知**也不给，模型会写出「他忘了刚知道的事」。

## 决定

1. **冷却单位 ＝ 一条指针**（人物 id + 命题 id）。人物级冷却退役。
2. **两个盖章时机**：
   - **指针建立或修改时**：指针是**模型刚写进去的**，它本来就知道这件事——马上又塞回给它纯属浪费，还可能让正文重复。**修改也按新建算**：一个人的认知会变，说明他当时在场、就是模型刚写的那段；所以指针内容一变就等于**新指针**，冷却从**修改轮**重新开始。
   - **指针被召回时**：给过就摁住 N 轮，别每轮重复。
3. **判定**：`当前轮 − 最后变动轮 < N` **或** `当前轮 < 召回冷却.until` → 这一条不给。
4. **第 4 格改成「最后变动轮」**：指针结构 `[人物id, 命题id, [[态度,来源],…], 最后变动轮]`。建立时写、每次写入内容（态度或来源组变了）时更新；召回轮记在冷却表里，键 `pt:人物id:命题id`。语义从"建立轮"改成"最后变动轮"——**没有消费者用得上建立轮**，为它多存一格不值。
5. **离场/在场不另设特殊冷却**：
   - NPC 离场 / 回场：召回**落后一轮**——写入阶段先处理离场回场，玩家输入时才召回，此时回场的人已经是「在场」，走普通召回即可。
   - 主角「离场 → 在场」那一次**全量指针注入**是**一次性**的（ADR 0085），**注入时不看冷却**；但**注入完这批指针照样全部盖章**（`until = 当前轮 + N`），下一轮常规召回不会重复给。注入完主角在场就不再当召回源。
6. **轮数**沿用现有设置：默认 10 轮、范围 0～20、0 ＝ 关闭冷却。

## 为什么

- **按指针**：给出去的是「**变了的部分**」，正好是模型缺的信息。
- **建立也盖章**：这条最容易漏——新建的指针模型刚写完，立刻召回等于把刚发生的事再讲一遍。
- **不搞人物级双键**：两种键混用会让"为什么这轮没给"变得无法解释。

## 补充决定：来源组带游戏时间（同日）

**问题**：只记轮次，模型不知道"他什么时候知道的"——"这笔账拖了三年"还是"你昨天才说漏嘴的"，只能瞎猜，猜错就前后矛盾。而轮次对模型毫无意义（它不知道第 12 轮是游戏里哪一天）。

**时间不加在指针上，加在「来源组」上**——时间属于「某一次听闻」，一个人可能三年前听张三说过、昨天又听李四说了，两条来源的时间本来就不该混成一个。

### 结构

```
指针 = [人物id, 命题id, [ [态度, 来源, 游戏时间?], … ], 最后变动轮, 约定状态?]
                            ↑ 内层从 2 格变 3 格，时间可省略        ↑ 只有约定类命题才有（ADR 0087）
```

- **来源＝自己**：每次自我认知更新，时间**刷新**（"我现在这么认为"）。
- **来源＝别人 / 未知**：各带各的时间；最多 3 组，超了**按加入顺序删最早那组**（"这件事他忘了是谁最早说的"）。
- **旧数据 / 非 MVU 卡**：没有 gt 就是 2 格，行为与现在一致（非 MVU 卡本来就没有游戏内时间，见 ROADMAP P11）。
- **指针第 4 格保留「最后变动轮」**：冷却要算**轮次差**（`当前轮 − 最后变动轮 < N`），gt 是**原文**、按 ADR 0005 只记录不解析，不能参与计算。时间归来源、轮次归指针，各管各的。

### 为什么"最旧"按顺序而不是按时间

`gt` 是原文（"三年五月十二日"），程序**不解析**它，自然也比不出大小。所以"删最旧"＝删数组里排第一的那组（加入最早）。要精确比较就只能再加轮次，不值这个复杂度。

### 收益

召回时能直接告诉模型：

> 「老陈 → 主角欠他钱：真（三年五月十二日，他自己确认过）」
> 「老陈 → 主角欠他钱：假（今天，听李四说的）」

他信哪一版、什么时候变的，一眼就清楚。

## 一条总原则

**场上刚发生过的事，一律不直接给。** 模型刚写完那一段，它就知道；新建、修改、召回，三种都盖章。只有"变了的部分"在冷却结束后才值得再给——而那正好是模型缺的。

## 待定

- 值（条目）层要不要也压召回：本条只覆盖指针层，值层沿用原有条目级冷却。
