# 0044 姓名升到人物级别；召回的两个前提

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0043](0043-身份层豁免冷却与空值兜底.md) 里把「身份层唯一值条目」当姓名载体的部分；以及设计稿 §2「姓名栏可以留空」
- **关闭**：Q16（姓名的双重身份）

## 背景

### 1. 姓名存了两份（Q16）

| 存在哪 | 用途 |
|---|---|
| **人物记录**（`p` 数组第 3 位） | 抬头显示、召回匹配（配合召回词串） |
| 条目列表里的「姓名」条目 | 身份层 ① 那一行 |

两处**可能对不上**：改名要同步两处，漏一处就穿帮。这个问题从 ADR 索引里挂了很久（Q16）。

### 2. 召回和写入的门槛本来就不同

| | 靠什么 | 需要名字吗 |
|---|---|---|
| **召回** | 姓名／别名匹配 ＋ 抬头显示 | ✅ **必须有**——没名字匹配不上，抬头也写不出来 |
| **写入** | **人物码 `p7`**（建档时就分配好） | ❌ 不需要 |

把姓名抬到人物级别，正好让这两个门槛各归各位。

## 决定

### 1. 姓名只存人物记录，不再有「姓名」条目

人物记录里的姓名字段是**人物识别字段**，不再对应任何条目。

### 2. 姓名位**必须非空**，但可以是称呼

不要求真名。「瞎眼的鱼贩」「无名船工・第12轮」都可以当姓名用。

### 3. 召回的两个前提

一个人要被召回，必须同时满足：

1. **姓名位非空**；
2. **至少有一个条目有值**。

任一条不满足 → **不参与召回**，但**照常参与写入**（写入靠人物码）。

第 2 条的理由：档案全空的人召回来只有一行名字，纯占预算。

### 4. 唯一值条目机制保留，但默认一个都不开

- 默认预设库里**所有条目的「唯一值」都是否**；
- 玩家想给某个条目加唯一值，自己点（比如「当前所在地」只允许一个值）。

### 5. 导入预设：必须有唯一值，第一个抬升为人物识别

| 情况 | 处理 |
|---|---|
| **0 个唯一值** | **拒绝导入**，提示「这份预设里没有唯一值条目，无法确定用什么当人物识别」 |
| **1 个** | 把它**抬升**到人物行：它的值进人物记录的姓名字段，**它本身不再是条目** |
| **多个** | 取**预设表里第一个**唯一值条目抬升，其余照常保留为条目 |

抬升是**导入那一刻**决定的；之后想换识别字段，按「人物改名」处理（旧名进别名，§2）。

### 6. 面板显示

没名字的人显示为 `p7（未命名）` 并带提示标记，点进去能补。

## 后果

- **收益**：**Q16 关闭**——姓名只有一个来源，改名只改一处。
- **收益**：召回门槛清楚了（名字 ＋ 至少一条内容），空档案不再占预算。
- **收益**：写入不受名字影响，没名字的人照样能被维护。
- **代价**：没名字的人**永远召不回来**。这是事实而非缺陷（抬头写不出、匹配也匹配不上），但面板必须提示，否则玩家会觉得"这人的档案怎么从来不出现"。
- **代价**：导入预设多一道校验；预设作者必须标至少一个唯一值。

## 被否决的方案

- **保留姓名双存（现状）**：改名要同步两处，漏一处就穿帮，Q16 会一直挂着。
- **没名字也召回**：匹配不上、抬头空，模型拿到一段资料却不知道写的是谁。
- **空档案也召回**：一行名字纯占预算。
- **强制建档必填真名**：不现实，无名人物本来就存在；用称呼顶替就够。
- **取消唯一值条目机制**：玩家仍有用它的场景（"当前所在地"只能一个值）。

## 待定

- **Q17 别名双存**：别名同样是两份（人物记录的召回词串 ＋「别名」条目）。本次先不聊。
- **抬升后想换识别字段**的交互细节（改哪个、旧值怎么处理）。
- 导入预设时"第一个唯一值"按什么顺序算（预设表里的排列顺序，还是另有优先级）。
