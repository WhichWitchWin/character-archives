# 0045 砍掉 MVU 容灾

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0005](0005-时间只记录不解析.md) 第五节的「MVU 容灾暂存 `pending`」；以及设计稿 §2 里「MVU 容灾的出口」整套（状态 `2`／`3`、容灾组、容灾开关）

## 背景

「MVU 容灾」原本由四块组成：

| 组成 | 当初解决什么 |
|---|---|
| 状态 `2`（离场·资料容灾）／`3`（在场·资料容灾） | 记住"容灾之前他是在场还是离场"，数据恢复后好归位 |
| 面板第三个分组「MVU容灾组」 | 把这批人单独放一起 |
| `pending` 暂存批 | 资料源要消失时**连值带 gt 抢存**，等以后回读历史正文补内容 |
| 设置项「MVU容灾」开关 | 控制开不开 |

它服务的是这条链路：

```
MVU 里的人物要被清掉 → 抢先把值存下来 → 以后回读历史正文补细节 → 归位到离场/在场
```

## 这条链路已经不存在了

| 原来依赖什么 | 现在 |
|---|---|
| **回读历史正文**补内容 | [ADR 0024](0024-建档提前.md) 把建档提前到第一次出现，**根本不需要回读**——`pending` 的用途整个消失 |
| **用 MVU 的现场名单**判在场 | [ADR 0025](0025-离场记录取代在场名单.md) 去掉了 `anchors`，状态由正文 ＋ 程序数轮次决定，**不需要记住"容灾前是几"** |
| 怕来不及抄 | 每轮 `onTurnSettled` 都按映射表把 MVU 值抄进档案（信度位 `"9"`）——**读到就存下了**，没有窗口 |
| 怕资料随 MVU 消失 | 我们自己有档案，正文抽出来的值都在 |

一句话：**MVU 只作数据源，不作状态源。**

## 决定

四块全砍，只保留一件事：

> **MVU 值按映射表抄入档案**（信度位 `"9"`，不经过模型）。

## 后果

- **收益**：状态字段从 4 个值减到 2 个（`0` 离场／`1` 在场），判断逻辑、面板、回退表都跟着变简单。
- **收益**：少一张滚动表（`pending`）、少一个设置项、少一个面板分组。
- **代价**：快照里状态字段的值域从 `0～3` 缩到 `0～1`，**老数据里的 `2`／`3` 要迁移成 `0`／`1`**（当前还没真实数据，迁移成本为零）。
- **边界**：**只在 MVU 里、正文从没出现过的人不会建档**——那正是"没戏的背景板"（[ADR 0024](0024-建档提前.md) 的非龙套判定要求正文依据）。
- **补口**：如果玩家确实想把卡作者写好的那批人收进来，走 [ROADMAP](../ROADMAP.md) **M5-7「从 MVU 导入人物」**——**手动勾选**，不自动建。

## 被否决的方案

- **保留容灾**：四块现在全是空转，留着只会让实现和文档都背着不存在的场景。
- **自动从 MVU 建档**：MVU 里躺着几十上百个数据条目（路人甲的好感度、店主 A 的库存），自动建会把档案撑爆，也架空"非龙套"边界。
- **保留状态 `2`／`3` 但不做容灾**：没有容灾就没有"容灾前状态"要记，两个值纯粹是死值。

## 待定
