# 0032 判定素材带「本轮提到的人」与状态

- **状态**：有效
- **日期**：2026-11-02
- **supersedes**：[ADR 0030](0030-术语统一与模糊离场归程序.md) 中「判定素材不再带任何离场名单」的连带结果（0030 删名单的方向对，但漏了「回场」需要状态）

## 背景

[ADR 0030](0030-术语统一与模糊离场归程序.md) 把「疑似离场名单」从判定素材里删掉了——因为模糊离场归程序数轮次，模型不需要那份名单。

**但那张名单同时是模型唯一的「谁在离场」的信息源。**

删完之后，判定素材长这样：

```text
【已建档人物】老陈、周、林昭     ← 只有名字，没有状态
```

而提示词给的指令是：

> 改状态 …… · 已**离场**的人本轮明确在场 → "在场"

**模型无从执行**：它不知道谁是已离场的。所以「改状态」只剩「正文写了告别 → 离场」能用，「回场」这条是空的。

这不是提示词写得不清楚，是**素材缺了模型判不了的那一项**。

## 决定

### 1. 程序先扫一遍正文

`onTurnSettled` 里，用现成的 `match.js`（姓名／别名／单字规则，召回也用同一套）扫本轮正文，得出**命中了哪些已建档人物**。

### 2. 判定素材新增一段

```text
【本轮提到的人】
· 老陈 p7 —— 离场
· 林昭 p12 —— 在场
```

只列**本轮碰到的**人，不列全档 —— 素材长度跟着本轮正文走，不跟档案规模走。

### 3. 【已建档】压成一行

```text
【已建档】老陈、周、林昭、独眼陈……（共 47 人）
```

它现在只剩一个用途：**防止模型把老人当新人重复建档**（"陈账房"就是老陈）。状态信息全部移到上一段，不重复。

### 4. 提示词补一条硬约束

> **名字出现 ≠ 他在场**：回忆、传闻、假设、"要是他在就好了"——都不算。只有正文写他实际在这个场景里、能对话能动手，才算「在场」。

所以素材段的标题是「本轮**提到**的人」，不是「本轮**在场**的人」。**素材给事实，规则给判法**，两边都要有。

### 5. 素材模板也抽成独立文件

`docs/每轮发什么.md` 成为 followup 素材的唯一真相源；设计稿 §7.6.2 只留约束与要点。

## 后果

- **收益**：「回场」这条指令终于有依据；「明确离场」也不再需要模型自己猜谁在场——两个方向都能判。
- **收益**：素材长度可控（只列命中的人），比"全档带状态"省得多。
- **代价**：多一步程序扫描。但 `match.js` 本来就要为召回跑，复用它，成本很低。
- **依赖**：命中率取决于**别名收录是否全**。别名没收录 → 漏命中 → 漏判回场。兜底：模型若在正文里看到与【已建档】列表重名或近名的称呼，仍可报「改状态」，由程序校验。
- **边界**：「提到 ≠ 在场」仍是**模型判断题**，会有误差。误判成在场的后果是"人不在场却被召回维护"，不致命；误判成离场的后果更轻（下一轮出现就自愈）。
- **注意**：单字名的命中按 [ADR 0010](0010-单字命中细则.md) 走（统一 0.6，永不置 name/alias），这里的扫描必须与召回用**同一套规则**，否则两处判断会打架。

## 被否决的方案

- **给全部已建档人物带状态**：档案上百人时素材爆掉，而其中 90% 跟本轮无关。
- **只给离场人物名单（不带在场的人）**：模型看到"林昭告辞走了"，林昭不在名单里，会以为不用处理 → **漏判明确离场**。
- **让程序直接判回场**：程序分不清"老陈推门进来"和"主角想起老陈"，这正是模型该干的活。
- **把状态并进【已建档】每一行**：全档逐条带状态，token 翻几倍，收益只有本轮相关的少数几个。

## 待定

- 【已建档】那一行几百人时要不要截断、截断后怎么防重复建档。
- 命中门槛：单字名、常见词（"周"也是姓）会不会把无关正文判成"提到"——沿用召回的阈值，还是判定这里更严，待定。
