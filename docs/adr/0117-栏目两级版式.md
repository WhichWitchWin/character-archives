# 0117 栏目两级版式：栏目名一行、值缩进、双色交替、默认收起

- **状态**：有效（决定 1 里「认知侧栏目行是眼睛＋＋」已由 [ADR 0119](0119-补认知入口提到人物层.md) 改为「只有眼睛，＋ 提到人物层标题行」）
- **日期**：2026-11-22
- **supersedes**：无

## 背景

「他是什么样」的每一栏是**左右排**的：左边一个 `flex: '0 0 68px'` 的标签格，值在右边同一行。
这个格子里还塞了「＋」和锁按钮（锁是 2026-11-14 加进去的），名字因此变成可收缩项——
中文的 `min-content` 就是**一个字**，字号一大就被压成逐字竖排（用户截图：职业／性格／
能力资源…每个字占一行）。另一次改动把按钮移出格子治好了竖排，但左右排本身还在：
栏目和值看起来是"一行一栏"，层次分不清。

同时「他的认知」是另一套版式（栏目名一行、值在下面），两块长得不一样。

## 决定

### 1. 两块统一成两级：栏目名独占一行，值缩进一级

栏目名那一行放：▸/▾ 箭头、名字（`whiteSpace: 'nowrap'`，不许逐字折行）、条数或「（空）」，
右边靠 `marginLeft: 'auto'` 放该侧的按钮（命题侧是「＋」＋锁，认知侧是眼睛＋「＋」）。
值排在下面，`paddingLeft: '1.8em'`（跟字号走，不写死像素）。

### 2. 每栏可单独折叠，**打开一个人时默认全收起**

折叠状态记的是「**展开**的栏目码集合」，初始空集＝全收。

**为什么记"展开"而不是"收起"**：栏目是跟着人物动态变的（不同人的栏目集合可能不同），
记"收起"就得预填满所有码，新出现的栏目永远进不来；记"展开"则新栏目自动落在"收起"一侧。

### 3. 栏目之间双色交替

按栏目在列表里的序号，`index % 2 === 0 ? ui.soft : 'transparent'`。
**走主题的半透明色**（`--SmartThemeBlurTintColor`），不写死颜色——深色主题下写死浅色会糊。

### 4. 空栏目照样列出来，标题行直接写「（空）」

「他是什么样」的既有意图是"空栏目也列，玩家才知道该补哪一栏"。默认收起之后，
如果空栏目和满栏目长得一样，这个意图就失效了——所以**收起状态也要看得出这栏是空的**，
条数位置直接显示「（空）」。展开后值区同样画一个「（空）」。

### 5. 栏目名行整行可点折叠，行内按钮各挡一下冒泡

按钮沿用 `stopPropagation`：否则点「＋」会顺手把这一栏收起来。

### 6. 「整栏折叠」与「一栏太长只露前 6 条」是两套，都保留

前者管"要不要看这一栏"，后者管"这一栏太长"（`COLUMN_LIMIT = 6` ＋「还有 N 条（点开）」）。
两者的状态分别存在 `openCols` 与 `openColumns`，互不影响。

### 7. 批量选择的「看得见的行」要排除收起的栏目

ADR 0112 的口径是"宁可少选，不猜区间"。栏目收起后里面的行不在屏幕上，
`visibleClaimIds` / `visibleCogIds` 必须先按 `openCols` 过滤掉收起的栏目。
（这条容易漏：漏了以后 Shift 连选会选中玩家根本看不见的东西。）

## 后果

- **收益**：两块版式一致；栏目和值的层次一眼分得清；默认收起让"打开一个人"短很多。
- **收益**：名字不再可能被挤成竖排（`nowrap` ＋ 按钮已经不占名字的宽度）。
- **代价**：想看内容得多点一下（默认收起换来的）。
- **代价**：每栏至少占一行（空栏目也是），栏目多的人会比"展开状态"更矮、但比原来的左右排更高。
- **边界**：折叠状态**不写盘**，切走再回来恢复默认收起——跟「还有 N 条」一样是"看一眼"的临时状态。
- **边界**：认知视图的「补一条认知」下拉**不受栏目收起影响**（它属于"加东西"不是"看东西"），
  收起状态下点「＋」照样出下拉。

## 被否决的方案

- **默认展开**：栏目多的人（8 栏）一打开就是一屏半，玩家每次都得往下翻；收起更省。
- **把折叠状态写进整局数据**：多一份要跟快照/回退对齐的状态，而它只是"看一眼"的偏好；
  真要记住，应该是"默认展开的栏目"这种全局偏好，属于另一个话题。
- **三种以上底色**：双色交替已经够分区，颜色多了在主题色下容易糊成一片。
- **只改「他是什么样」，认知那块保持原样**：两块版式不一样本身就是这次的由头之一。
